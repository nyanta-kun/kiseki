## 1. 毎回効く原理（ここを外すと必ず遠回りする）

### 1.1 大きい払戻は「帯」ではなく「点数」で作る

予算が1レース1万円で固定なら

```
払戻 = 的中した点のオッズ × (10,000 ÷ 点数)
```

**点数を半分にすれば払戻は倍**。オッズ帯を上げるのは同じことを的中率を落として
やる遠回りで、両者は交換可能。競合の高額的中30件を分解しても同じ結論になる
（96万円＝5,000円×192倍の**2点買い**／39万円＝10,000円×39倍の**1点買い**。
`docs/rival_hot_highpay_2026_08_27.md`）。

### 1.2 「払戻 T 以上が出る頻度」は券種・点数・配分に依存しない

```
P(払戻 >= T) = 帯ROI × 予算 ÷ T
```

相手を広げれば1点の払戻は下がるが的中率が上がって相殺する。
**大きい払戻の発生頻度は買い方では動かない**（memory `keirin_highpay_payout_ceiling_2026_08_06`）。
動かせるのは **的中率 ⇄ 一撃力 ⇄ 件数** の三角形の中の位置だけ。

### 1.3 目標払戻 T と件数 N は対で決まる

1レース1万円・1日 N 件なら、**1件の的中で日次回収率100%を超える条件は「払戻 >= N万円」**。
片方だけ動かすと「当たっても日次がプラスにならない」か「当たる回数が足りない」。
`T = N × 10,000` で自己整合させること（memory `keirin_tf_core_redesign_2026_08_22`）。

### 1.4 ROI は控除率の壁（74.85%）に張り付く。採否を ROI で決めない

三連単でこれまでに測った全構成の ROI は概ね **65〜85%** に収まり、構成間の差は
ほぼ常に CI が重なる。**「回収率が上がる」と説明してはいけない。**
月次で見るのは **件数・的中率・払戻中央・10万+の本数** の4つ。

外部でも同じ。netkeiba 好調予想家10人の8月15,194商品の合計 ROI は **72.4%**（壁の下）。
「高額的中」は収支の証拠ではなく分散の作り方の証拠でしかない。

## 2. 買い目の作り方

### 2.1 確率 — 位置別合成 Plackett-Luce（**1着率だけで組まない**）

```
a = normalize(pw)              # 勝率
b = normalize(p3)              # 3着内率
s_i = normalize(a**w_i · b**(1-w_i))      w = (1.0, 0.5, 0.0)
P(x,y,z) = s0[x] · s1[y]/(1-s1[x]) · s2[z]/(1-s2[x]-s2[y])
```

正本 `strategy_wt.rank_7t3_blend_probs`。1着は勝率、3着は3着内率、2着は相乗平均。
**pw 単独の PL（`odds_prediction_tf.pl_ordered`）とは別物**で、確認窓の top1 的中は
**5.99% → 10.07%**。三連単の買い目確率を1着率だけで作るのが元の穴だった。

### 2.2 同ライン隣接ボーナス λ / μ（**周辺確率の積はライン依存を表現できない**）

```
score(x,y,z) = P_PL(x,y,z) × λ^[y が x の直後(同ライン line_pos+1)] × μ^[z が y の直後]
λ = 2.0, μ = 1.5     （λ 2.0〜2.5 × μ 1.2〜2.0 は広いプラトー）
```

`RANK_7T3_LINE_ADJ_W`。top1 の1点に1万円で **的中 +0.96pt / +1.01pt（両窓有意）・
ROI +6.9pt / +13.7pt・9/9四半期で符号プラス**。

- 機序: PL が最強ライン先頭→番手と食い違うのは 68.9%、うち **29.8% は2着に別ラインの車**を
  置いている（二軸そろい 22.31% ↔ 11.65%）。逆に 20.0% は PL が正しいので
  **ハード規則にせず重みにする**（λ=∞ は λ=2.5 に負ける）
- 🔴 **7T1 には効かない**。母集団が「上位2車が別ライン」＝隣接ペアを定義上除いている
- 同型の知見が9車の軸選定にもある（[[nine_car_axis_redesign]]）

### 2.3 並べ替え — 帯で最適が変わる

| 帯 | 並べ替え | 根拠 |
|---|---|---|
| 30〜50倍 | **確率順** | EV順は的中1.69%まで落ちる（`honmei_trifecta_50x` §3） |
| 100〜300倍 | **EV順（確率 × 予測オッズ）** | 母集団・点数を揃えた直接対決で +4.1pt・壁超え 6/7窓 ↔ 2/7窓 |

🔴 **どちらか一方を全帯へ持ち込まないこと。** 帯をまたぐと逆転する。

### 2.4 配分 — 三連単は均等でよい

三連複の `tilt_stakes`（ダッチング）とは違い、**三連単ではダッチングは同等〜わずかに劣る**。
例外は 7T1 で、そこでは配分ではなく**点数**を目的から導いている（次項）。

### 2.5 点数 — 目的（目標払戻 T）から自己整合で導く。固定の足切り倍率を置かない

```
払戻 >= T  ⟺  当たった点のオッズ >= T ÷ (1点あたりの賭け金)
```

その値に届かない点は**目的に一切寄与せず賭け金を薄めるだけ**なので落とす。
点数 N と足切り `T×N/BUDGET` を自己整合させ、条件を満たす点を Σ確率 最大で N 点選ぶ
ときの目的値が最大になる N を採る（`rank_7t1_select`）。

- ⚠️ 1点あたりの賭け金は `BUDGET/N` ではなく **`rank_7t1_min_stake(N)`**（単位丸め後の最小額）。
  10,000円を3点なら 3,333 ではなく **3,300円**。`T×N/BUDGET` で切ると最小の点だけ届かない
- 🔴 **固定の足切り倍率（例: 50倍）を置くと、軸が強いレースだけが壁を課されて
  成績が落ちて見える**。前身 7H3 の見かけの効果はこれだった
- 目標額 T が決めるのは**何点に割るか**だけ。**買うか買わないかは決めていない**
  （k=1 まで下げれば必ず1点通るので、10万〜30万のどれでも買えないレースは0件）

7T1 の掃引（honest walk-forward・決勝系×別ライン・13.4本/日）:

| T | 平均点数 | 的中 | 20万超 |
|---|---|---|---|
| 10万 | 2.82 | 5.35% | 0.93%（8.0日に1回） |
| **15万（採用）** | **2.31** | **4.49%** | **2.10%（3.5日に1回）** |
| 20万 | 1.98 | 3.14% | 2.07% |
| 30万 | 1.64 | 2.76% | 2.28% |

15万は20万に届く頻度を落とさずに的中頻度だけ上げる**優越関係**（閾値スイープの勝ちではない）。

## 3. レースの選び方

### 3.1 🟢 効くのは種別だけ

探索↔確認の順位相関が 的中 +0.395 / ROI +0.408。上位は決勝・準決勝・チャレンジ決勝、
下位は選抜・一般。

🔴 **ただし帯をまたぐと順位が変わる。** 50倍帯で両窓とも壁超えは 予選81.6 / 特一般80.7 /
準決勝80.6% だが、チャレンジ決勝は 30倍96.5% ↔ 50倍59.4%。
**両帯で一貫して通るのは予選・準決勝の2つだけ。**

7車の種別Tier（三連複での測定だが母集団の質としては共通・memory `keirin_9car_and_type_scan_2026_08_24`）:
勝ち上がり戦（決勝・準決勝・予選）が良く、**番組編成レース（特選・選抜・一般）が悪い**。
「決勝系＝節目のレース」という読み方は誤り。

### 3.2 🔴 効かないと測って否定したもの（再提案しない）

| 案 | 結果 |
|---|---|
| 混戦度（1着率エントロピー）でレース選別 | 点推定は上がるが **7窓中4窓しか上回らず**窓レンジ 64〜107 で発散。件数が1/3になって測れなくなっただけ |
| Σp（モデル自身の的中確率）で選別 | 確認窓 **AUC 0.5172**・較正も崩壊 |
| 高配当レース分類器（72特徴 LGBM） | 三連単≥1万 AUC 0.641 / **≥3万 0.569 は単一特徴 p1_ent 0.579 に負ける**。買いに変換すると最良 ROI 67.2% |
| 場（venue） | 探索↔確認の順位相関 −0.065＝ノイズ。LGBM の gain 21.5% は過学習 |
| 開催日目 | 両窓で順位が反転・CI 全重なり |
| 荒れ指標（軸積・top3合計・エントロピー） | 全滅 |
| 日次上位N件へ絞る（ev降順） | **件数を1/3にしても ROI は 81.8% で同じ**＝ev 選別は無価値 |
| 日次選別の順序 | **無作為が ev 降順とほぼ同じ**。確率順・予測オッズ順は無作為より悪い。**選別器を作らないこと** |
| 「軸が揃わない日は買わない」 | 二軸そろい率の日次ムラの**約9割が二項ゆらぎ**。朝の指標は5分位で7ptしか分離せず運用不能 |
| 「20レースに絞る」 | 100%超の日は N をどう動かしても 25〜33% で平ら。**動くのは0円の日だけ**（73.6%→12.0%） |

## 4. 🔴🔴 記述的傾向を買い目の制約に変換すると必ず負ける

確定払戻から見れば **100倍以上の決着の50.8% は「指数1位＋別ライン2車」**で、
指数1位のライン3車で決まると 100倍+ はわずか 4.4% ——という強い傾向は実在する。
**それでも制約にすると全帯・両窓で悪化する。**

| 制約にした案 | 結果 |
|---|---|
| 「指数1位＋別ライン2車」限定 | 50倍+10点 73.1→69.9% / 30倍+10点 74.6→68.7%・**1/9窓しか壁超えしない**（制限なしは5/9） |
| 「本命が3着以内」を明示制約（◎+3車ボックス） | 68.4% ↔ 制約なし 73.8% |
| 位置固定フォーメーション | 全滅 |

理由は共通で、**位置別合成 PL の確率上位が既に織り込んでいる**（50倍+5点の内訳は
同ライン3車 0.8% / 別ライン2車 35.2%＝実際の決着よりさらに絞れている）。
人間が読める規則へ落とすと確率順から外れた目を買わされる。

🟢 唯一の使い道は **オッズ帯フィルタの代替**（別ライン2車限定なら10万+が 0.39→1.12件/日・
ROI 76.1→72.5%）。予測オッズを使わずに配当を狙う経路として等価。

同じ理由で **「本命を3着以内に入れる」制約も不要**。制約なしでも 50倍+5点のうち
平均4.78点が本命絡み・5点とも本命入りが85.3%。的中の律速は本命ではなく**残り2車**
（本命の3着内率79.3%に対し、本命が3着内だったレースでも的中は10〜13%）。

### 入稿ゲート — 🔴 **三連単には1つも掛かっていない**

`netkeirin_submit_wt.py` のランクループにある3ゲートは、すべて `if not use_trifecta:`
の内側にある。三連単経路（`formation_bet_7t1` / `formation_bet` / `multi_bet_7h2`）は
**素通り**する。

| ゲート | 内容 | 三連複 | 三連単 | 看板穴埋め |
|---|---|---|---|---|
| `MIN_POINT_ODDS` | 1点でも生オッズ 2.0倍未満があれば出さない | ✅ | ❌ | ❌ |
| `MIN_EXPECTED_PAYOUT_BY_RANK` | 買った目の**最低**払戻倍率の下限 | ✅ | ❌ | ❌ |
| `MIN_MEAN_PAYOUT`（平均払戻2万円） | 想定平均払戻が2万円以下なら出さない | ✅ | ❌ | ✅ |

ダッチングでは **平均想定払戻 = 予算 ÷ Σ(1/予測オッズ)** なので、
`MIN_MEAN_PAYOUT = 20,000` は実質 **`Σ(1/予測オッズ) < 0.5`＝買い目の市場シェア 37.5% 未満**
という制約と同じ（`docs/type_lab/SUMMARY.md` §2.1）。三連単に同等のものを掛けるなら
`Σ(1/予測オッズ) <= 0.6` 等を**明示的に足す必要がある**（型ラボの残論点）。

⚠️ `stake_allocation.py` の「三連単経路は対象外。**予測オッズは三連複しか作れず**」という
注記は**古い**。三連単の予測オッズ（`odds_tf_n7`）は 2026-08-12 からあり、
2026-08-26（PR#316）以降は入稿の配分にも使っている。ゲートを掛けられない理由は
もう存在しない。

## 6. 実装上の落とし穴

1. 🔴 **1着1車固定のフォーメーションでは表現できない。** 確率上位5点の1着が1車に揃うのは
   **7.0%** しかない。**1点=1行**で送る `formation_bet_7t1` 経路を使うこと
2. 🔴 **三連単は板を見ない均等配分なので `equal_stake_trifecta` で前倒しを許可する。**
   許可しないと 7T1 が朝に前倒しを見送り `deferred_races` に入り、**下位の 7S/7B/7C まで
   朝に取れなくなる**（実際に起きた・PR#319 で `_can_pull_forward` の `if not partners` が
   常に真だったことも判明）
3. 🔴 **`RANKS_BOUGHT_ON_SUBMIT` に足し忘れると、売っているのに Web の投資・回収
   サマリーから消える**（7T1 で 2026-08-15 に発生）
4. **`_normalize_7t1_candidate` は `axis1`/`axis2` 必須**。7T3 は軸が無いので
   `rank_7t3_axes` で導かないと全レースが「候補情報不正」で無言スキップ
5. **`_is_enabled()` は fail-open**（`netkeirin_settings` に行が無いと常時ON）。
   新ランクは `enabled=false` の行を明示投入してからデプロイ
6. **`rank_7t1_is_target_race_type` に `marquee.MARQUEE_KEYWORDS` を束縛しない。**
   正本を共有していた頃は「7T1 を絞る」と看板判定まで動いた
7. **母集団を変えたら過去分の再構築が要る**（`rebuild_7t1_walkforward_pg.py` /
   `rebuild_7t3_walkforward_pg.py`）。件数が変われば別商品で、実績が接続しない
8. **文面と実装を食い違わせない。** 7T3 は5点すべてに共通する車が1車のレースが50.5%＝
   **半数に「二軸」は存在しない**ので `_body_no_axis()` で【二軸】節を落としている

## 7. 検証の作法（三連単で特に踏みやすいもの）

- 🔴 **予測オッズ `odds_tf_n7.txt` は train_end 2025-12-31。オッズを使う数字は
  2026 窓だけが honest。** 探索窓の ROI は in-sample で必ず良く出る
- 🔴 **KPI と同じ定義で比べる。** netkeirin の表示的中は**ガミ除き**。生の的中率で比べると
  差が3倍に見える（7S の決勝除外を「44.5%→5〜10%」と誤報告した実例。正しくは −0.22pt）
- 🔴 **簡易実装で A/B しない。** 軸を固定して測ると、本番 `rank_7t1_select` が
  42順序対の総当たりで既に拾っている能力を「欠けている」と誤認する。
  出荷実装（`exp_tf_shape_prod.py`）で測り直すまで採用しない
- 🔴 **ベースラインは本番コードから作る。** 定数の存在は使われている証拠にならない
  （ルート CLAUDE.md「検証の作法」）
- 探索 2024-07〜2025-12 / 確認 2026-01〜。**四半期9窓の合議**で見る。月で判断しない
  （7T3 は 2026-03 だけ ROI 37.4%）
- 掃引で選んだセルの ROI を「妙味」と読まない。上限つき構成は H1/H2 で 80↔117 と振れる

## 8. いま開いている論点

- **三連単枠の件数を 6.3件/日 から増やすか。** 10万+率は競合と同オーダーで、
  差は件数だけ。台は `予選/準決勝/特一般 × 50倍+ × 10点`（9/9窓で壁超え・17.3件/日）だが、
  この母集団は 7S/7C/7B と丸ごと重なるので**優先順位と投資総額の設計が要る**
  （案Cは投資 17.3万円/日で現行全体 29.7万円/日 を6割増やす）
- **10万+が2日に1回出ると店頭の「直近の的中」枠を占有する**（当たるたび上書き）。
  ベース商品の小的中との並走設計が要る（`docs/sales_kpi.md`）
- **型ラボ**が三連単の明示ゲート `Σ(1/予測オッズ) ≤ 0.6` と12点の入稿経路を持ち込む予定
  （`docs/type_lab/SUMMARY.md` §6）。既存枠との統合はそこで決める
