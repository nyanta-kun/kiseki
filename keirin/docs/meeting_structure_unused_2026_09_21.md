## 4. 🟢🟢 `n_entries`（出走車数）— モデルは車数を知らない

### 4.1 残差は車数で単調

| 車数 | n(探索/確認) | 残差 探索 | 残差 確認 | SE |
|---|---|--:|--:|--:|
| 5車 | 1,365 / 870 | **+4.32** | **+3.64** | 1.33 / 1.66 |
| 6車 | 7,690 / 4,987 | +1.20 | +0.39 | 0.57 / 0.71 |
| 7車 | 163,631 / 109,992 | −0.42 | −0.61 | 0.12 / 0.15 |
| 8車 | 1,190 / 728 | −1.17 | −1.12 | 1.40 / 1.80 |
| 9車 | 19,727 / 13,886 | **−1.64** | **−1.97** | 0.34 / 0.40 |

**両窓で完全に単調**。同一グレード内（GIII の 8車 −1.1/−1.2 ↔ 9車 −1.5/−1.8）でも
分かれるので、グレードとの交絡ではない。

### 4.2 正体は「Σp3 = 3 の制約が入っていない」こと

3着内率は定義上 **1レースの合計が必ず 3.0**。実測の合計:

🔴 **下表は 2026-09-21 夕に測り直した値**（初版は尺度の取り違えで誤っていた・§10.8）。
左＝探索2025 / 右＝確認2026。

| 車数 | R（探索/確認） | Σp3 | 理想比 | Σpw | 理想比 |
|---|--:|--:|--:|--:|--:|
| 5車 | 302 / 193 | 2.770 / 2.811 | **−7.7 / −6.3%** | 0.919 / 0.955 | −8.1 / −4.5% |
| 6車 | 1,507 / 988 | 2.912 / 2.926 | −2.9 / −2.5% | 0.985 / 0.993 | −1.5 / −0.7% |
| 7車 | 23,164 / 15,564 | 3.021 / 3.028 | +0.7 / +0.9% | 1.016 / 1.011 | +1.6 / +1.1% |
| 8車 | 166 / 101 | 3.094 / 3.098 | +3.1 / +3.3% | 1.049 / 1.045 | +4.9 / +4.5% |
| 9車 | 2,175 / 1,534 | 3.149 / 3.180 | **+5.0 / +6.0%** | 1.074 / 1.080 | **+7.4 / +8.0%** |

🟢 **両窓で単調**。しかも §10.1 で**その場で学習し直したモデル**でも同じ形が出ている
（7車 3.014/3.019 ↔ 9車 3.181/3.207）ので、保存値の都合ではない。

§4.1 の残差は**この合計のずれとぴったり一致する**（9車: 予測 35.03 − 1.64 = 33.39 ≒ 3/9）。
つまり精度の問題ではなく、**車数という入力が無いので合計を合わせようがない**という構造。

🔴 これは JRA v28 で `place_slots` を `races.head_count` から作らず
**実際のフィールドの馬数**から作り、`normalize_place_to_slots` で Σ を枠数へ
揃えたのと**同じ型の欠落**（CLAUDE.md「🔴 `place_slots` は `races.head_count` から作らない」）。
中央にはある手当てが競輪に無い。

### 4.3 🔴 これは `axis_sum >= 1.44` の型判定を直撃する

`type_lab.AXIS_SUM_FIRM = 1.44` は**生の p3 の上位2車合計**を**絶対閾値**で切る
（車数を問わず同じ値・`src/type_lab.py:73`）。Σp3 が車数で 12pt も違うので、
同じ 1.44 でも**車数によって実質的な厳しさが違う**。

Σ=3.0 へ正規化して切り直した実測（2025-01〜2026-08・上位2車そろい率で評価）:

| 車数 | | 堅い判定 R数 | 堅い側 そろい率 | それ以外 そろい率 |
|---|---|--:|--:|--:|
| 7車 | 生 | 21,695 | 63.86% | 39.84% |
| 7車 | **正規化** | 20,162 | **65.88%** | 39.63% |
| 9車 | 生 | 1,065 | 61.69% | 34.64% |
| 9車 | **正規化** | **630** | **70.32%** | 36.70% |

🔴🔴 **この表の読み方は誤りだった（2026-09-21 夕に自己訂正・§10.2）。**
正規化は 9車の「堅い」判定を 1,065→630R と**4割減らす**ので、そろい率の上昇
（61.69→70.32%）の大半は**絞り効果**であって分離の改善ではない。
[[keirin_type_lab_race_filter_rejected_2026_08_27]] の
「件数を減らす検証には必ず無作為対照を置く」を自分で踏んだ。
**件数を揃えて測り直すと +1.6〜1.8pt**（7車 +1.2〜2.0pt）。効果は本物だが桁が違う。

⚠️ **既知の未修正事項と同根**。`strategy_wt.py` の `RANK_7S_AXIS_SUM_MAX` 付近に
「ゲートの正規化が不統一（2026-08-21 実測・未修正）」として、Σp3 が
±10% 揺れることと 7S の通過判定が 21.3% 入れ替わることが既に書かれている。
**本稿が足すのは「そのずれは無作為ではなく車数で系統的に並んでいる」という点**。

⚠️ 過去に測った「9車の境界を中央値 1.329 へ**下げる**」（[[keirin-type-lab-carcount-9car]]・
型Aのそろい 68.05→62.50% で否定）とは**向きが逆**。正規化は 9車を**厳しく**する。
否定済みの案とは別物なので、混同して「検証済み」としないこと。

### 4.4 打ち手は2つあり、別物

1. **`n_entries` を `FEATURE_COLS_WT` に足す** — モデル自身に合計を合わせさせる。
   ただし**レース内で全車同値**なので、`add_line_strength_features_wt` の docstring が
   非採用の理由に挙げた「レース内の順位付けに寄与しない」に当たる。
   効くのは**レース間の較正**（＝ axis_sum・予測オッズ・ダッチ・EV ゲート）で、
   軸選定の順位は動かない
2. **後段で Σp3 = 3 へ正規化する** — モデルを触らずに較正だけ直す。
   §4.3 はこちら。**閾値 1.44 は正規化していない値の上で決めた定数なので、
   正規化だけ入れると別のゲートになる。掃引をやり直すこと**

🔴 どちらも **p3 が変われば型判定・買い目・入稿ゲート・型ラボの台まで全部動く**。
商品KPI（表示的中・ROI・10万+）は必ず vintage で測り直すこと。

🟢 **B は両窓ともプラス**で、C との差は +5.25 / +2.95pt。

⚠️ B は `cup_mean_order_n`（節内の平均着順）に部分的に入っている。**純増分は未測**。

## 8. DB に無く、取得から要るもの

いずれも**番組編成の外から決まる情報**で、既存の否定腕（コメント・風・前日の決着傾向）とは
性質が違う。[[meeting_form_fillna_2026_09_21]] §4 で挙げたものと同じ。

- **勝ち上がりのボーダー**（今日の準決勝で「3着でも乗れるか」は競走得点で決まる）。
  §1 の実測どおり 3着の 33% しか乗れないので、**同じ3着でも得点上位かどうかで
  翌日の立場が変わる**。ただしこれは「翌日の番組」を決める量で、**今日のレースの
  走りに効くかは別**。候補としては §6 の裏返し
- **級班入替の境界**（期の後半・S級/A級の昇降級がかかる選手）。`period_norm` は
  何期生かであって、境界にいるかではない
- **賞金ランキング**（GP 出場ライン）。年末の GI で効く可能性

⚠️ いずれも実装コストが取得から発生する。**§4 の `n_entries` / Σp3 正規化は
既存データだけで済み、効果も一番はっきりしている**ので先に片付けること。

|---|--:|--:|
| Σpw（7車） | 1.947 | **1.016 / 1.011** |
| pw の LogLoss（全体・確認窓） | 1.689 | **0.311** |
| pw の Brier（全体・確認窓） | 0.225 | **0.095** |

一般則: **「値域から尺度を推測する変換」を書かない。** 列の定義（`_pct`）を見て
無条件に決め打つか、それが分からないなら先に `describe()` を出す。

## 10.9 正規化は「確率としての当てはまり」を良くする（小さいが一貫）

商品KPIは動かなくても、**確率として使う場面**では正しくなる。

| 対象 | 指標 | 探索2025 | 確認2026 |
|---|---|--:|--:|
| 3着内率 | ΔBrier | **−0.00077** | **−0.00068** |
| 3着内率 | ΔLogLoss | −0.00065 | +0.00007 |
| 1着率 | ΔBrier | **−0.00053** | **−0.00055** |
| 1着率 | ΔLogLoss | **−0.00194** | **−0.00185** |

- **Brier は 3着内率・1着率とも全セル・両窓で改善**
- **LogLoss は 1着率では全セル改善**だが、**3着内率は 5車・6車で悪化**（+0.002〜+0.020）
  ＝ 少数車は Σ を 3 へ引き上げる補正が効きすぎる。少数車で p3 の絶対値を使うときは注意
- 🔴 大きさは小さい。**「商品が良くなる」とは読まないこと**（§10.4 で否定済み）。
  価値は **今後の検証でレース間・車数間を比べられるようになること**に限る

## 10.10 確率の単調性は 0.25% で破れている

`pred_win_pct <= pred_top2_pct <= pred_top3_pct` は定義上必ず成り立つはずだが、
3つが**別々の二値モデル**なので保証がない。実測（0-100 スケールのまま比較）:

| 窓 | 破れ | 内訳 pw>p2 | p2>p3 |
|---|--:|--:|--:|
| 探索2025 | 0.28% | 0.08% | 0.20% |
| 確認2026 | 0.25% | 0.09% | 0.16% |

頻度は低い。下流で「P(2着) = p2 − pw」「P(3着) = p3 − p2」と**引き算して着順ごとの
確率を作る**箇所があれば、そこで負の確率が出る。使っている場所の棚卸しは別途。

# 14. 残作業の見積もり（2026-09-21・§12.2 を着手前に調べた）

## 14.1 台の系譜は4段・全部リポジトリ内にある（＝再構築できる）

## 14.2 🔴 だが台の p3/pw は **60特徴世代**（本番は70特徴）

```
wf_preds_2024-07-01_2024-09-30_f60_2022-12-01.pkl
…（9本すべて f60）
```

`f{N}` は `len(FEATURE_COLS_WT)`（`exp_*` 各スクリプトの命名）。
本番は **2026-08-19 に 66 → 2026-09-10 に 70** へ増えているので、
**型ラボの台は2世代前の指数の上に載っている**。

影響の性質を分けて考えること:

- 🟢 **同じ台の上で買い方どうしを比べる**のは成立する（腕の相対比較）
- 🔴 **絶対量は本番へ持ち込めない**。`AXIS_SUM_FIRM = 1.44` の通過率も、
  「型Aが何%」も、台の p3 分布に紐づく。`strategy_wt.py` に既にある
  「🔴 この数字は60特徴時代の指数」という注記と同じ問題が、
  **型ラボの台にもそのまま当てはまる**

→ **§12.2 は「バグ修正」ではなく「台の作り直し」**。同着だけ直して再構築しても
2世代前のままなので、やるなら `wf_preds` の再生成（walk-forward・2024-07〜2026-08）
からになり、規模が桁で違う。**単発の修正として着手しないこと。**
