## 13.1 同着の払戻（§12.1）

🔴 **採点の共通入口 `resolve_payout` の中で足した。** 呼び出し側
（`notify_results_wt.py` 12箇所・backfill 14本）は1つも変えていない。
同着でないレースでは追加分が必ず 0 になるのでテストで固定した。

実データで機序を確定させた（`20260822_31_03#9C`）:

    着順 1着=5 / 2着=3 / **3着=7 と 9 の同着**
    入稿 3=5=7 ¥5,400 ・ 3=5=9 ¥2,500
    確定 trio 3-5-7 = 2.3倍 / 3-5-9 = 5.2倍
    記録 ¥12,420（= 230 × 5,400 ÷ 100・片方だけ） → 正 **¥25,420**

🔴 途中で踏んだ罠2つ:

- `wt_odds.combination` は**三連複も `-` 区切り**。`=` 決め打ちだと1件も見つからないのに
  例外は出ず**静かに 0 円**になる。書式を仮定せずパースする形に直した
- `picks_history.rank` は `RANK_9C`・`netkeirin_submissions.rank_key` は `9C`。
  突き合わせを誤ると `submitted_stakes` が None を返し、**0件で正常終了して見える**
  （実際に一度「該当なし」と出た）

## 13.2 型の再現（§12.7）

切り分けると**主因は `behind` ではなく p3 の二重ソース**だった:

    axis_sum が焼き付けと違うレース  **1,870 / 1,872 = 99.89%**
    型ラベルが変わるレース            113 / 1,872 = 6.04%
      firm（axis_sum）だけ反転  73 (3.90%)   ← `pred_top3_pct` を vintage が上書き
      arare（behind）だけ変化   32 (1.71%)   ← 開催中に更新される列
      両方                       8 (0.43%)

🟢 型の再現に要る値（`axis_sum` / `arare` / `type_label`）は**全部焼き付いている**ので、
スキーマ変更は要らない。`type_lab.type_label_of(axis_sum, arare)` を正本として切り出し、
`race_shape` 本体もそれを通すようにした（テストで両者の一致を固定）。
