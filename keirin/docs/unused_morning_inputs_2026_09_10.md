# 朝の推奨時点で使える「未使用の入力」の棚卸しと価値検証（2026-09-10）

> 依頼: 未使用であり、**朝の推奨タイミング（7:15 バッチ）で利用できる**ものに価値があるか。
> オッズは朝時点の**予測オッズ**しか使えない。
>
> 再現: `scripts/exp_type_lab/comment_value.py` / `scripts/exp_meeting_form_ab.py`

現行モデルの入力は `src/preprocessing/feature_wt.py::FEATURE_COLS_WT`（**66特徴**）。
DB 側（`wt_entries` / `wt_races` / `wt_race_conditions` / `wt_weather` / `venue_info`）の
全列と突き合わせ、**朝に確定していて FEATURE_COLS_WT に無いもの**を洗い出した。

## 2. 選手コメントには増分がない

`wt_entries.comment` は 100% 充足で発走前に取れるが、**平均 4.8文字・中央 4文字・
ユニーク率 7.2%** の定型句だった（例:「自力」「番手」「４番手」「◯◯君の後ろ」）。

| | 探索 2024-07〜2025-12 | 確認 2026-01〜08 |
|---|--:|--:|
| ベースライン（`pred_top3_pct`＝月次vintageの honest OOS）AUC | 0.7873 | 0.7832 |
| コメント単体（char 2-3gram TF-IDF + ロジスティック）AUC | 0.6318 | **0.6123** |
| ベースライン + コメント AUC | — | 0.7831 |
| **ΔAUC** | — | **−0.0001  95%CI [−0.0003, +0.0001]** |

レース内1位に置いた選手の3着内率も 80.28% → 80.39%（+0.11pt）で動かない。

🟢 **機序がはっきりしている。** 係数の大きい n-gram は
マイナス側が「４番手(−1.80)」「番手(−0.90)」「流れに乗(−0.73)」、
プラス側が「自力(+0.76)」と**選手名（「岩井君」「中原君」＝誰の後ろに付くか）**。
＝ **コメントの中身はライン内の位置と並びの宣言**で、
すでに `line_pos` / `is_line_leader` / `line_size` / `line_group` としてモデルに入っている。
**言い換えを足しているだけ**なので増分がゼロなのは筋が通る。

⚠️ 自然言語としての情報（調子・仕上がりの機微）はほぼ無い。4文字ではそもそも書けない。

## 3. 実装済み・未配線の2群の A/B（`scripts/exp_meeting_form_ab.py`）

方法論は既存の特徴 A/B（`exp_basic_elements_ab.py` / `exp_racetype_field_ab.py`）と同一。
**2窓 × 5seed・deterministic**、train は 2024-04-01 から test 窓の直前まで。

| 腕 | 窓 | ΔAUC | Δ1位勝率 | Δ1位3着内 | Δ上位2車そろい |
|---|---|--:|--:|--:|--:|
| **+節内成績（4列）** | w1 2026-04-13〜07-15 | **+0.00058** | **+0.33pt** | **+0.29pt** | **+0.35pt** |
| **+節内成績（4列）** | w2 2026-01-01〜04-12 | **+0.00068** | **+0.14pt** | **+0.27pt** | **+0.09pt** |
| +走りの質（3列） | w1 | +0.00003 | +0.22pt | +0.15pt | +0.09pt |
| +走りの質（3列） | w2 | **−0.00011** | **−0.02pt** | +0.03pt | +0.02pt |
| +両方（7列） | w1 | +0.00068 | +0.53pt | +0.29pt | +0.13pt |
| +両方（7列） | w2 | +0.00061 | +0.02pt | +0.08pt | **−0.17pt** |

baseline の seed 標準偏差は AUC で 0.00013 / 0.00005。

### 🟢 `MEETING_FORM_COLS_WT`（節内成績）は採用候補

**両窓・全指標でプラス**。ΔAUC は seed のばらつきの 4〜13倍。
比較の物差しとして、直近で採用した `line_leader` 6列（2026-08-19）の実測は
**ΔAUC +0.00044 / +0.00072・Δ1位勝率 +0.24 / +0.25pt** で、
**今回の節内成績はそれと同等以上**（+0.00058 / +0.00068・+0.33 / +0.14pt）。

分割重要度は `cup_mean_order_n`（節内の平均着順を頭数で正規化）が **21〜22位 / 73**、
他の3列は 53〜62位。＝ **実質この1列が効いている**（率よりも「何着で走ってきたか」）。

### 🔴 `FORM_QUALITY_COLS_WT`（走りの質）は不採用

**窓で符号が割れる**（ΔAUC +0.00003 / −0.00011＝seed ノイズの中）。
docstring の残差（+0.88pt・4σ）は本物でも、**66特徴のモデルは既にそれを吸収している**。
`fh_lost_rate_90` は重要度 20〜26位とよく使われるのに成績が動かない＝
既存列（`fh_rel_90` / `fh_best_rate_90`）と情報が重なっている。

### ⚠️ 両方入れると薄まる

`+両方` は w2 の上位2車そろい率が **−0.17pt** と単独より悪い。**節内成績だけ入れること。**

## 4. 採用するとしたら

`FEATURE_COLS_WT` に4列（または `cup_mean_order_n` + `cup_n_so_far` の2列）を足すのは
**モデルの入力を変える＝ p3 / pw が変わる**ので、影響は型判定・買い目・入稿ゲート・
型ラボの台まで全部に及ぶ。手順は:

1. `FEATURE_COLS_WT` へ追加 + `build_features_wt` から `add_meeting_form_features_wt` を呼ぶ
   （**現在この関数はパイプラインから呼ばれていない**。`add_line_strength_features_wt` の隣）
2. 月次 vintage モデル群を再学習（`wt_vintage_config.monthly_windows()`）
3. `backfill_index_pct_wt.py` で `pred_*_pct` を貼り直す
4. 型ラボの台（`/tmp/honmei_attr.npz` → `race_type_board.npz`）を作り直して商品KPIを再測

🔴 **本稿は「モデルの精度」までしか測っていない。** 表示的中・ROI への効き方は
上の 2〜4 を通さないと分からない（`docs/type_lab/audit_2026_08_28.md` の
「モデルが賢くなるたびに過去分析がリークする」問題があるので、商品KPIは必ず vintage で測る）。

## 5. 限界

⚠️ w1 / w2 はともに 2026年で、型ラボの確認窓と重なる（この2窓は既に何度も使われている）。
   ただし `FEATURE_COLS_WT` の採否は過去も同じ2窓・同じ方法論で判断してきた。
⚠️ 節内成績には勝ち上がりの交絡がある（初日に勝てば準決勝へ進む）。`RACE_TYPE_COLS_WT` が
   既に入った上での残差なので完全な交絡ではないが、独立とも言い切れない。
⚠️ 9車・6車は測っていない（7車のみ）。
