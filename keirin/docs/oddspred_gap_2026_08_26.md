# 予測オッズと確定オッズの食い違い — 配分と足切りへの影響（2026-08-26）

**ユーザーの問い**: 「朝の入稿のため予測オッズモデルを作っているが、予測オッズでの
**金額配分**と**足切り**の結果が確定オッズと乖離がありそう。精度を上げる方法はないか」

結論を先に:

- 🟢 **乖離は実在する。しかも中身は2つに分かれ、片方は完全に系統的**（月次で安定）。
  - **平均払戻**: 確定 = 予測 × **1.10**（月次 1.086〜1.121・実入稿でも 1.102）
  - **最低払戻（下限）**: 確定 = 予測 × **0.78**（月次 0.766〜0.789）
  - 1点ごと: 確定/予測 中央 **1.07〜1.08**・**<0.8倍が 18〜24%**
- 🔴 **モデルの精度を上げる余地は、試した範囲では見つからなかった**（5案とも不採用・下記§5）。
  残差は締切間際の資金移動で、朝の構造情報では説明できない。
- 🔴 **本当の問題は「ゲートの閾値が、確定オッズで言うと別の数字を意味している」こと**。
  - `MIN_MEAN_PAYOUT = 20,000円` は実質 **約 22,000円**のゲート
  - `MIN_EXPECTED_PAYOUT = 1.5倍` は実質 **確定の下限 中央 1.17〜1.24倍**。
    通した商品のうち本当に 1.5倍以上あったのは **44.8%（実入稿では 57.7%）**
- 🔴 **定数較正は単調変換＝閾値の付け替えと同じ**なので「精度が上がる」話ではない。
  決めるべきは**操作点**（どれだけ通すか）で、それは §6 の表からユーザーが選ぶ。

## 2. 配分の食い違い

傾斜配分（`landing_weights`）は「全点の払戻をそろえる」ことを狙う。実測:

| | 計画（予測オッズ） | 確定 |
|---|---|---|
| 払戻の最大/最小 中央（実入稿） | 1.21 | **2.02** |
| 同（長い窓） | 1.12 | **2.11** |
| 重みの L1 誤差 中央 | — | 0.176（実入稿）/ 0.180（長い窓） |

脚別（1=最人気）に見ると **確定/予測は 1.057〜1.080 でほぼ平ら**＝
「人気側だけずれる」「裾だけずれる」といった**取り出せる傾きは無い**。
ばらつきは目ごとの独立な誤差で、レース内で相殺されない。

到達点（オラクル＝確定オッズを知っていた場合）:

| 配分 | ROI | 表示的中 | 2万円以上 | 実現下限 中央 |
|---|---|---|---|---|
| 現行（1/予測オッズ） | 78.5 / 78.0% | 39.20 / 40.34% | 8.69 / 8.38% | 1.06 / 1.05 |
| **オラクル** | 77.1 / 76.9% | **44.43 / 45.15%** | 6.63 / 6.52% | **1.45 / 1.41** |

**残っている取り分は表示的中で約 5pt**。ROI はむしろオラクルの方が低い
（配分は収支ではなく体験を作る道具）。

## 3. 足切りの食い違い

実入稿 705 商品（A）:

| ゲート | 予測で通す | 通した中で**実際に**基準を満たした | 切った中で実は満たしていた |
|---|---|---|---|
| 平均払戻 > 20,000円 | 320件 | **94.1%** | 21.8%（**84件**・約4件/日） |
| 最低払戻 >= 1.5倍（7C/7S・424件） | 215件 | **57.7%** | 9.1% |
| 1点 >= 2.0倍 | — | 予測で通したが確定では割れた 17件 | 予測で切ったが割れなかった 12件 |

長い窓（B・14,748R）では 1.5倍ゲートの達成率は **44.8%**（実入稿の方が高いのは、
入稿された商品が既に他のゲートで選ばれているため）。

**なぜ平均は過小で、最低は過大なのか**（向きが逆なのは偶然ではない）:

1. **水準**: 整合化（レース内で Σ(1/o) を 1.3453 へ再スケール）は**素の点予測を
   約8%下げる**。meta の記録でも 素 中央比 1.026 → 整合板 0.950（＝確定/予測 1.053）。
   これは下振れを減らすための**設計どおりの保守化**だが、**ゲートの閾値は
   その保守化を織り込まずに円・倍率で置かれている**。
2. **最小値であること**: 下限は5点の**最小**なので、目ごとの独立な誤差がある限り
   「予測の最小」より「確定の最小」は必ず小さく出る（順序統計量のバイアス）。
   配分がそろえるほど5点の払戻は接近し、最小はより深く食い込む。

食い違いの大きさ（B・14,748R）:

| 統計量 | 予測 vs 確定 Spearman | 残差 sd(log10) |
|---|---|---|
| 平均払戻 | 0.867 | 0.082（±21%） |
| 最低払戻 | 0.752 | 0.114（±30%） |

## 4. 何を測って何が分かったか（要点）

- 乖離の**系統成分は2つの定数で言い尽くせる**（×1.10 と ×0.78）。月次で安定。
- 残りは**目ごとの独立誤差**。朝の構造情報からは説明できない（§5）。

## 5. 精度を上げる案 — 5つとも不採用（すべて2026を前後半に割って両向きで確認）

| 案 | 結果 |
|---|---|
| **入稿時点の板を使う／混ぜる** | 板が5点そろうのは 朝波 52.8% / 昼波(h12) 38.9% / 夕波(h18) 47.9%。そろった上でも **配分L1 予測 0.183〜0.202 に対し板 0.270〜0.411**。板が勝つレースは 17〜31%。相乗平均も悪化。**予測オッズ単独（2026-08-21 の判断）が正しい**ことの再確認 |
| **開催メタ（種別・級・開催日目・場・バンク）＋地元フラグを特徴に足す** | logMAE 0.1363→0.1356・配分L1 0.1787→0.1785・偏りも不変（平均払戻比 1.108→1.107）。追加10特徴の gain 合計 1.4%。残差を種別別に見ると 0.999〜1.103 と構造があるが、**整合化がレース水準のずれを消すので取り出せない** |
| **再学習して新しくする** | 学習終端 2025-12-31 / 2026-04-30 / 2026-06-30 を同一窓で比較して logMAE 0.1400→0.1397・配分L1 0.1886→0.1881・偏り不変。**8か月古くても実害が測れない** |
| **配分の重みを脚ごとの下振れ分位で較正** | 表示的中 39.20→39.16%（25%点）/ 38.62%（10%点）。実現下限 1.06→1.08。**動かない**（脚別の比が平らなので当然） |
| **足切りを「実際にそうなるか」の分類器へ替える** | AUC 現行 0.874〜0.934 → モデル 0.868〜0.927 と**すべて悪化**。予測オッズから作った統計量そのものが最良の並べ替え |

🔴 **この検証で一度やらかした**: 分類器の特徴に `mof`（確定オッズの最小値）を
混ぜてしまい「AUC 0.874→0.929・適合率 +7pt」という**偽の改善**が出た。
特徴はホワイトリストで書くこと（`03_improvement_attempts.py` に assert を入れてある）。

## 6. 対応（2026-08-26 実装・ユーザー判断「対応して」）

定数較正は単調変換なので、**c を掛けることと閾値を動かすことは同じ**。
つまり「精度を上げる」話ではなく「**今の閾値が何を買っているかを知って選び直す**」話。

**最低払戻 1.5倍ゲート**（B・14,748R。判定値 = 予測の下限 × c）:

| c | 通す率 | 通した中で実際に1.5倍以上 | 切った中で実は1.5倍以上 |
|---|---|---|---|
| **1.00（現行）** | 39.4% | **44.8%** | 2.6% |
| 0.85（＝ `odds_low` の c(p25) 相当） | 24.7% | 58.3% | 6.4% |
| 0.78（＝ 確定の下限の中央を 1.5 にそろえる） | 18.6% | 65.3% | 8.7% |
| 0.70 | 12.3% | 74.6% | 11.4% |

※ 確定オッズで本当に下限 1.5倍以上あるレースは **19.2% しかない**。
現行は その2倍を通している。

**平均払戻 20,000円ゲート**:

| c | 通す率 | 通した中で実際に2万円超 | 切った中で実は2万円超 |
|---|---|---|---|
| **1.00（現行）** | 19.1% | **88.4%** | 15.9% |
| 1.10（＝ 中央を確定へそろえる） | 26.1% | 80.9% | 11.7% |

平均払戻ゲートは**現状すでに高精度**（通した中の 88〜94% が実際に2万円超）。
較正すると件数は増えるが「安い商品も通る」方向なので **触らない**。

### 実装したこと

**① 想定払戻(下限)の足切りを「下限包絡」で判定する**（閾値 1.5 は据え置き）

`netkeirin_submit_wt._expected_payout_floor_for` が予測オッズへ保守倍率
c(p25)（7車 0.843 / 9車 0.859）を掛けてから最小値を取る。実入稿 424件での効果:

| 判定に使う数字 | 通す件数 | 通した中で実際に1.5倍以上 | 切った中で実は1.5倍以上 |
|---|---|---|---|
| 素の予測オッズ（旧） | 215件（11.3/日） | **57.7%** | 9.1% |
| **c(p25)×予測（新）** | 136件（7.2/日） | **75.7%** | 13.9% |
| min(板, c×予測)＝表示用 `odds_low` | 97件（9.7/日） | 66.0% | 26.3% |

- **件数は 4.2件/日 減る。ROI は動かない。** 買うのは看板の確からしさ。
- 🔴 **表示用の `odds_low` で判定してはいけない**（上表の3行目＝両方悪い）。
  板は買う帯で系統的に低い（中央 確定/板 0.86）ため判定材料として濁る。
  **表示は min 側・判定は c×予測**と用途で数字を替える。
  レビュー画面の「下振れ」より本ゲートのほうが緩く出るのは**意図的**。
- 保守倍率が取れないときは **None＝足切りしない**（素の予測へ黙って戻さない）。
- 実オッズ板へ落ちたときは**倍率を掛けない**（板は既に c(p25) と同水準に低い）。
- 検査: `tests/test_expected_payout_gate.py`（保守倍率が外れると落ちる）

**② 予測オッズモデルの「存在」を監視する**

`check_model_freshness.py` に `odds_trio_n7.txt` / `n9.txt` / `odds_trio_meta.json`
の**存在チェック**を足した（`ODDS_MODEL_FILES`）。

- 🔴 **古さ（mtime）では見張らない**。再学習の自動化が無いので毎日鳴り続け、
  鳴りっぱなしの監視は無いのと同じになる。鮮度に精度上の価値が無いことは §5 で実測済み。
- 消えたときに困るのは配分が黙って朝の板／p3 単独へ落ちること（板の配分は明確に悪い）。
- 検査: `tests/test_model_freshness_odds.py`

### 見送ったこと

- **平均払戻ゲートの較正**（現状で高精度・較正は「安い商品を通す」方向）
- **再学習の自動化**（§5 のとおり鮮度に価値が無い。作ると保守対象だけ増える）

## 7. 運用上の穴（今回ついでに見つかったもの）

- 🔴 **予測オッズモデルには再学習の自動化も鮮度監視も無い**。
  `check_model_freshness.py` が見ているのは `lgbm_wt*.pkl` の4本だけで、
  `odds_trio_n7.txt` / `n9.txt` は対象外。最後の学習は 2026-08-20（学習終端 08-04）で手動。
  鮮度そのものに精度上の価値は無い（§5）が、**このモデルは配分・3つのゲート・表示を
  すべて決めている単一障害点**なので、壊れたときに黙って旧経路へ落ちるのは危うい。
- ⚠️ **9車は7車より明確に精度が低い**（meta の評価窓 logMAE 7車 0.1361 / **9車 0.1624**、
  ±2倍 92.0% / **85.6%**。学習レース数 60,169 / **5,696**）。
  実入稿でも 9C の配分L1 は 0.209 と最悪（7C 0.178・7S 0.165）。
