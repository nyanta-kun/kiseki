# 7H1「本命が勝ち切るレースは見送る」案 — 検証記録（2026-08-25・保留）

ユーザー方針: **7H1 で「本命が勝ち切る可能性あり」と判断したレースは推奨を見送り、
他の商品で拾う形**。2026-08-25 時点では**実装せず、記録を残して改めて検討する**。

きっかけ: 高知7R（`20260825_74_07`）。7H1 は本命ライン（車2・6）を全列から落として
`5-3-x / 5-7-x` の8点を買い、結果は **2-5-1** で外れ。同じレースで 7M1 が
`2=5-1,4,6,7` を記録し **67,000円** 的中していた。

## 2. 🟢 構造は提案どおり完全に排他

7H1 の買い目は本命を全列から外すので、**本命が3着以内に入った時点で的中は原理的に不可能**
（例外は3着同着のみ・実測2件）。同じレースを三連複二軸総流し5点で買うと真逆になる。

| 7H1 が選んだレース | 三連単F8点（現行） | 三連複 二軸総流し5点 |
|---|---|---|
| 本命バスト 27.3〜27.4% | 的中 17.2〜19.2% / **ROI 277〜317%** | **的中 0%** |
| 本命が2-3着 30.5〜33.1% | **的中 0%** | 的中 56.2〜57.5% / ROI 103〜107% |
| 本命が1着 39.6〜42.1% | **的中 0%** | 的中 48.6〜56.7% / ROI 89.8〜94.6% |

⚠️ 三連複側は 軸=本命 + 本命を除く3着内率トップ、相手=残り5車、**均等 2,000円**で計算。
本番の三連複ランクは `tilt_stakes`（予測オッズによるダッチング）なので実装時は数字が変わる。

高知7R もこの形なら取れる: `2=5-6,3,7,1,4` → 2-5-1 が 26.8倍 → 均等2,000円で **53,600円**。

## 3. 🔴 いま止まっている理由（この2つが解ければ実装できる）

### (a) 判定器の精度が足りない — **これが律速**

本番と同じ **67特徴**（`favbust_features`）を**月次walk-forward**で学習した結果:

**AUC 0.5533（探索）/ 0.5544（確認）＝ほぼコイン投げ。**

理由は明快で、**7H1 のゲートが既にバスト確率の上位10%で切っている**ため、
選ばれた帯に残る「本命が生きるか」の変動が予測できない。
7特徴の簡易モデルでも 0.539〜0.590、単一量の AUC は下表のとおり。

| 量 | 探索 | 確認 |
|---|--:|--:|
| `fav_ppw_norm`（表示1着率） | 0.5619 | 0.5798 |
| `gap12_norm`（抜け度） | 0.5545 | 0.5798 |
| `bust_prob`（現行ゲート） | 0.4845 | 0.4681 |

振り分けた合成成績（`route.py`）:

| | 探索 ROI | 確認 ROI |
|---|--:|--:|
| 常に三連単（現行） | 84.0% | 86.9% |
| 常に三連複 | 71.2% | 69.8% |
| 判定器で上位20〜70%を三連複へ | 67.4〜83.0% | 76.4〜89.3% |
| **【オラクル】実際の生死で振り分け** | **153.6%** | **154.6%** |

**どの振り分け割合も両端の間に収まり、両窓で「常に三連単」を超えるものは無い。**
オラクルは 表示的中 29.4/31.8%・ROI 153.6/154.6% と非常に大きいので、
**価値があるのは確かで、足りないのは判定精度だけ**。

### (b) 受け皿が薄い

7H1 が実際に入稿を取るのは選別の 76.5%（残りは上位ランクが先に取る）。
実効の優先順位（`enabled=false` を除く）は
`7T1 > 7T3 > 7S > 9C > 7B > 7C > 7H1 > 7M1` なので、**7H1 の下は 7M1 だけ**。

| 7H1 が取るレース（1,478件・2025-01以降） | 7M1 に候補がある割合 | その 7M1 の成績 |
|---|--:|---|
| 本命が1着 574件 | 26% | 的中 15.79% / ROI 87.0% |
| 本命が2-3着 462件 | 26% | 的中 18.64% / ROI 108.4% |
| 本命がバスト 442件 | 32% | 的中 0.70% / ROI 5.4% |

**見送っても 7割前後は無商品になる。** 7H1 は pt/R 1,011 で全ランク最高
（7M1 は 257）なので、件数減は売上へ直接効く（`docs/sales_kpi.md` §5.1）。

## 4. ❌ 単純な閾値では代用できない（測って否定済み）

「本命の1着率が一定以上／2番手との差が一定以上なら見送る」を掃引した結果、
**両窓とも「切った側」の方が的中率もROIも高い**＝提案と逆になる。

抜け度（表示）>= 0.30 で切る場合:

| | 残す群 的中/ROI | 見送る群 的中/ROI |
|---|---|---|
| 探索 | 4.40% / 59.9% | **5.54% / 120.7%** |
| 確認 | 5.30% / 75.8% | **5.74% / 148.2%** |

本命1着率で切る版・2条件の同時成立（9通り）も、両窓で一致するセルは無かった。

🔴 **高知7R は外れ値ではない。** 本命の表示1着率 43.6% は 2026年の 7H1 774件の
**中央値ちょうど**、抜け度 22.6pt は**下から38%点**。
**この1件を落とす閾値は商品の半分以上を落とす。**

## 6. 再検討するときに最初に見ること

1. **判定器の AUC が 0.65 を超えられるか。** 超えなければ振り分けは成立しない。
   いまの 0.55 は「ゲートで既に絞った帯の残差」なので、**別の情報源**
   （オッズ・直前情報・ライン変化など、現在の67特徴に無いもの）が要る
2. **受け皿を 7M1 以外に用意できるか。** いまのままでは見送りの7割が無商品
3. ⚠️ **vintage の pkl は同じ名前のまま再学習される**（`lgbm_wt_eval_m2607` の
   `trained_at` は 2026-08-20）。そのため本検証のキャッシュと picks_history は
   **件数はほぼ同じなのにレースの一致が 55.6%**。学習打ち切りは
   `race_date < test_from` なのでリークは無いが、**絶対水準を picks_history と
   比べてはいけない。窓内の Δ だけを読むこと**
