## 1. 本番の学習経路（先に読む）

`src/cli/main.py::train_wt` → `src/preprocessing/feature_wt.py` → `src/models/trainer.train_lgbm`。

| 項目 | 中身 |
|---|---|
| **行の単位** | **選手1人1行**（`wt_entries`）。レース内の関係は目的関数に入っていない |
| **母集団** | `finish_order.notna()`＝確定した全行。**DNS/DNF（`finish_order==0`）は負例として含む** |
| **目的関数** | `objective="binary"` / `metric="auc"` の**二値分類** |
| **ラベル** | `top3_flag`(配信 `lgbm_wt`・評価 `lgbm_wt_eval`) / `win_flag`(`lgbm_wt_win`) / `bad6_flag` / `top2_flag` を**別々のモデル**で |
| **特徴** | `FEATURE_COLS_WT` 70列・`prepare_X` が `reindex + fillna(0)` |
| **ハイパラ** | `n_estimators=500, learning_rate=0.05, num_leaves=31, min_child_samples=20, subsample=0.8, colsample_bytree=0.8, random_state=42` |
| 分割 | 日付ベース時系列CV 5fold（先頭60%バーンイン）で early stopping を見たあと、**全データで最終モデルを再学習** |
| 重み | `--dnf-weight`（既定 1.0＝無効）のみ |

🔴 **`subsample=0.8` は効いていない。** sklearn API は `subsample_freq=0` が既定で
LightGBM の bagging は無効。A/B で bagging を外しても条件は変わらない（本稿もそうした）。

## 2. 消費のされ方とのズレ

| 消費側 | 何を使うか |
|---|---|
| `type_lab.race_shape` | `order` = **p3 降順**（軸1・軸2）/ `axis_sum` = 上位2車の p3 の**和**（絶対閾値 1.44） |
| `strategy_wt.rank_7t3_blend_probs` | `a=norm(pw)`, `b=norm(p3)` から **位置別合成 Plackett-Luce** で三連単 210通りの同時確率 |
| `backend/.../keirin_type_lab_gate.AXIS_GATE_MIN` | プランごとの **axis_sum 絶対閾値**（1.246〜1.596） |

＝ **消費側は既に PL を仮定している**のに、その強度を
「独立に学習した2本の二値確率」で代用している。学習は「その1車が3着以内か」、
消費は「レース内の順序と同時確率」。

## 3. 候補と、1本に絞った理由

| 候補 | 消費との距離 | 判断 |
|---|---|---|
| **Plackett-Luce を直接最尤（ListMLE・上位K段）** | **最短**。消費側の PL そのものの強度を学習する。1本のモデルから pw（softmax）と p3（上位3入着確率）が**整合して**出る | 🟢 **採用** |
| レース内正規化着順の回帰（中央 v27 の `reg_rank` 型） | 順序は学ぶが**確率が出ない**。`axis_sum` も `rank_7t3_blend_probs` も作れず、別途較正が要る | 🟡 参考腕として同時に測る |
| LambdaRank（レース=group） | 出力がスケール自由なスコアで確率にならない。中央 v26→v27 は**これを捨てた**側 | 🔴 見送り |
| 着外率ヘッド（3着外を別ヘッドで合成） | **すでに本番にある**（`lgbm_wt_bad`・`rank_7s_select_axis` が z(p3)−0.5×z(大敗) で使用）。目的関数を変える話ではない | 🔴 見送り |
| ordinal（着順の順序回帰） | 二値を段階で積む形で、レース内の競合を表現しない。`reg_rank` の劣化版 | 🔴 見送り |

### 実装（`scripts/exp_objective_pl_ab.py::PLObjective`）

LightGBM の custom objective。レース r の上位K段の負対数尤度:

    L_r = Σ_{k=1..K} [ −s_{π(k)} + log Σ_{j∈R_k} exp(s_j) ]

`R_k` は k 段目の残存集合。**落車・失格・欠場は分母には残すが分子には現れない**
（「勝てたかもしれない相手」として正しく扱われる）。
勾配は各段の softmax − 指示関数、ヘシアンは p(1−p) の和。
1・2・3着が一意に決まらないレース（同着）は勾配 0 で学習から外す。

K=3（三連単そのもの）と K=6（下位の順序も使う）を測った。

### PL スコア → pw / p3

    s = softmax(score)  … レース内で和1
    pw_i = s_i
    p3_i = P(i ∈ 上位3) = s_i + Σ_{x≠i} s_x·s_i/(1−s_x)
                         + Σ_{x≠y≠i} s_x·(s_y/(1−s_x))·(s_i/(1−s_x−s_y))

**Σp3 はレースあたり厳密に 3.000 になる**（構成上）。現行 binary は 3.014。

|---|--:|--:|
| baseline（w1 / w2） | 1.4839 / 1.4766 | 56.99% / 56.08% |

モデルだけ差し替えると**堅い側（A/B/C）が 57% → 66% に膨らむ**。
「AUC が上がった」だけで商品が良くなるとは限らない、の典型。

🔴 **絶対閾値は腕ごとに引き直す。** そうしないと「較正が動いた」だけで

### 6.1 丸ごと差し替え（p3 も pw も PL）— 🔴 負ける

確認窓 2026-01-01〜08-04・10,404R / 216日・2seed:

| 腕 | 件/日 | 表示的中 | ROI | 払戻中央 | 10万+/日 |
|---|--:|--:|--:|--:|--:|
| 現行 binary（本番の絶対閾値のまま） | 32.33 | 25.80% | 81.5% | 23,070 | 0.229 |
| 現行 binary（軸ゲート引き直し） | 36.49 | 26.18% | 79.6% | 22,978 | 0.208 |
| 現行 binary（型境界も引き直し） | 36.49 | **26.10%** | 79.4% | 23,000 | 0.206 |
| PL-K3（本番の絶対閾値のまま） | 36.15 | 24.66% | 77.6% | 22,482 | 0.215 |
| PL-K3（軸ゲート引き直し） | 36.52 | 25.39% | 78.3% | 22,465 | 0.197 |
| **PL-K3（型境界も引き直し）** | 36.51 | **25.00%** | 77.5% | 22,725 | 0.185 |

🔴 **同じ在庫で 表示的中 −1.10pt・ROI −1.9pt。** モデル指標が上がったのに商品は悪化する。
（本番の絶対閾値のままだと堅い側が 52.7% → 64.1% に膨らみ、在庫が 32.3 → 36.2件/日 に増える。
**閾値を引き直さずにモデルだけ差し替えると、別の商品を売っていることになる。**）

### 6.2 原因の切り分け — 🟢 **効いているのは p3・壊しているのは pw**

同じ確認窓・型境界と軸ゲートは腕ごとに引き直し・2seed:

| 腕 | 件/日 | 表示的中 | ROI | 払戻中央 | 10万+/日 |
|---|--:|--:|--:|--:|--:|
| 現行 binary | 36.49 | 26.10% | 79.4% | 23,000 | 0.206 |
| PL-K3（p3・pw とも PL） | 36.51 | 25.00% | 77.5% | 22,725 | 0.185 |
| **PL の p3 × binary の pw** | 36.57 | **26.74%** | **80.6%** | 22,872 | 0.178 |
| PL-K3 温度 T=1.4（強度を寝かせる） | 37.37 | 22.85% | 73.8% | 22,620 | 0.213 |

🟢 **pw を現行の `lgbm_wt_win` に戻すと、丸ごと差し替えの −1.10pt が +0.64pt に反転する。**
`rank_7t3_blend_probs` は1着の強度に pw をそのまま使うので、
**AUC(1着) −0.005 の劣化がそのまま三連単の確率に乗っていた。**

🔴 **温度で寝かせるのは逆効果**（−3.25pt）。§5 の「PL は上に寄る」は
**較正の崩れではあっても、寝かせれば直るものではない**。
順位を保ったまま水準だけ動かすと、型の割り振りと買い目の並びが両方悪くなる。

## 7. 結論

| 問い | 答え |
|---|---|
| 目的関数を消費（PL）へ寄せる価値はあるか | 🟢 **モデル層では本物**。PL-K3 は ΔAUC(3着内) +0.0016/+0.0024・Δ1位勝率 +0.30/+0.54pt・Δ上位2車そろい +0.08/+0.38pt が**両窓プラス**で、採用実績のある節内成績の 2〜3倍 |
| そのまま差し替えてよいか | 🔴 **だめ**。pw まで PL にすると商品は 表示的中 −1.10pt。**pw は `lgbm_wt_win` のまま**にすること |
| p3 だけ差し替えれば商品は良くなるか | 🔴 **言い切れない**。Δ表示的中 +0.27 / +0.08pt・**4本とも CI が 0 を跨ぐ**・ROI は窓で符号反転・**10万+ は両窓で −14〜26%** |
| K を伸ばす / 回帰にする | 🔴 どちらも悪化（PL-K6 AUC −0.004〜−0.005 / reg_rank −0.006）。中央 v27 の `reg_rank` は競輪には移植できない |
| 温度で較正し直す | 🔴 −3.25pt で逆効果 |

**＝「目的関数を PL へ寄せると p3 は確かに良くなるが、その良さは商品KPI に届かない。」**
外れの3成分（軸崩壊・順序・相手）の天井検証と同じ結論の形になった——
**情報は増えているのに、買い方が変わらないので収支にも表示的中にも出ない。**

## 8. TEST をどう設計するか

`keirin_protocol.clean_test_start()` は **2026-07-16**（w1 の焼けが 07-15 まで伸びている）で、
四半期で揃えるなら最初の綺麗な窓は **2026Q4**。`MIN_TEST_WINDOWS = 4` なので
**2026Q4 / 2027Q1 / 2027Q2 / 2027Q3 の4窓＝判定できるのは 2027-10-01 以降**。
事前登録する内容は次の5つ:
(a) 腕は「**PL-K3 の p3 × 現行 `lgbm_wt_win` の pw**」1本（丸ごと差し替えと温度版は本稿で否定済み・再提案しない）、
(b) 主指標は **上位2車そろい率**、副指標に AUC(3着内)・1位勝率（プロトコルの実測 SD 0.15pt に対し4窓で SE 0.075pt＝観測した +0.08〜0.38pt を 1〜5σ で判定できる）、
(c) 商品KPI は **表示的中を主・10万+/日 を代償として併記**（4窓 ≒ 27,000R で対レース CI の幅が今の ±0.6pt から ±0.3pt 程度まで縮む）、
(d) 🔴 **較正の引き直しを腕の一部として登録する**——`AXIS_SUM_FIRM`(1.44) と
`AXIS_GATE_MIN`(8値) は**探索窓の分位点で引き直した値を凍結してから TEST に入る**
（本稿のように評価窓で引き直すと一度きり評価にならない）、
(e) 使ったら `record_test_usage()`。
なお **10万+ −14〜26% は両窓で一貫している＝測定ではなく店頭KPIの判断**なので、
「看板よりも表示的中を採る」と先に決められるなら、判定は (c) の CI が縮むのを待つだけでよい。
