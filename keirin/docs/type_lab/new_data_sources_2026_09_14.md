## 0. 結論（先に）

1. 🔴🔴 **「DB に無いデータ」の筆頭候補だった「2ソース目の予想印」は、期待値が
   構造的に小さい。** 1ソース目（winticket AI 印・gain 32.17%）を**丸ごと外しても**
   ΔAUC −0.0021 / −0.0026・**上位2車そろい −0.23 / −0.45pt** しか落ちない（§2 E1）。
   2本目が得られる上積みはこれ以下。
2. 🔴 **印は「自社が持っていない情報」ではない。** 69特徴（印を除いた現行特徴）から
   winticket の ◎ を **top1 82.80% / 81.99%** で復元できる（無作為 14.3%）（§3 E2）。
   同じ公開情報（競走得点・ライン・前検）から作られる2本目も同程度に冗長。
3. 🔴 **1本目の ◎ と自社モデル top1 は実質互換**。一致 89.7 / 90.3%、
   不一致レースでどちらが正しいかは**窓で符号が反転**（−2.59pt / +2.18pt・CI とも0跨ぎ）（§5 E4）。
4. 🟢 **外部サイトの実測（2026-09-14 朝）では、無料で朝に取れる印は実質2系統しかない。**
   netkeirin本紙 / チャリロト / Kドリームスは**同じ印（アオケイ系）**で、
   独立なのは **KEIRINスポニチ** だけ（§6）。※一致の確認は1レースのみ・要追試。
5. 🔴🔴 **決着をつける実験そのものが約1年かかる。** §5 の物差しで 1.5pt を分離するには
   不一致レースが約 7,000本要り、不一致率 10〜15% なら**全開催 5万レース＝1年強**。
   一方で得られる上限は **そろい率 +0.23〜0.45pt** ＝ `keirin_protocol` の実測 SD 0.15pt の
   1.5〜3倍でしかない。**投資対効果は成立しない。**
6. 🟢 **ただし「朝に1場1リクエスト」で貯め始めるコストはほぼゼロ**（チャリロト/Kドリームスは
   1場1日分が1ページ＝8〜16 req/日）。**採用ではなく「選択肢を作る」目的でのみ推奨**（§7）。

## 2. 🔴 「いま落としているのは外部サイトではなく、自分が落としている JSON」

winticket の racecard ページは**すでに毎日叩いている**が、`FETCH_KEIRIN_RACE` の
中身のうち保存しているのは一部だけ。実測（2026-09-14・8ページ）で未保存なのは:

| JSON のフィールド | 中身 | 判定 |
|---|---|---|
| `predictions[]` | 予想家の買い目 | 🔴 **中身は winticket 自身の AI 1本だけ**（`tipsterId="dsc-00"`・8ページすべて n=1）。買い目は**三連単24点＝P(4,3)・三連複4点＝C(4,3)**＝**◎○▲△の4車ボックス**で `prediction_mark` から完全に復元できる。**2ソース目にならない** |
| `records[].weather*` / `hourType*` / `trackDistance*` / `raceType*` / `linePosition*` | 条件別の着度数 | 🔴 **リーク**。同一開催 Day1↔Day3 の同一選手12人で `weatherCloudy` **12/12 変化**・`trackDistance400` 11/12・`raceTypeQualifyingRound` 7/12・`linePositionSecond` 6/12。既知の汚染列 `ex_spurt_pct` と同じ class（対照の `exSpurt` は 2/12）。**自社 DB から PIT で作り直すなら安全**＝データ源ではなく特徴設計の話 |
| `records[].first/second/third/others` | 着度数の**実数** | 🟡 Day1↔Day3 で **0/12 変化＝安全**。`first_rate` の分母（期内出走数）が新情報だが、rolling 系が同じ情報を持つ疑い。期待値は小 |
| `records[].hasModifiedGearRatio` / `modifiedGearRatio` | **ギヤ変更** | 🟡 安全（0/12 変化）だが**実測 0/42 車で発生なし**＝希少。単独では効かない |
| `records[].previousCupResults[].margin` | 着差 | 🟡 未保存。安全（0/12 変化）。`finalHalfRecord` は保存済み |
| `records[].*Succeeded` / `leftBehind` / `splitLine` | レース単位の戦法成否 | 🟡 これを貯めれば `ex_*` の **PIT 版**が作れる。ただし `ex_*` はリーク版でも **AUC 寄与ゼロ**と実測済み（2026-07-31）＝PIT 版も期待薄 |
| `players[].age` / `birthday` / `gender` | 年齢 | 🔴 `term`（期別）とほぼ同義 |
| `venues[].trackAngle*` / `trackStraightDistance` / `*Width` / `bankFeature` | バンク形状 | 🔴 **レース内で定数**（下記） |
| `race.lap` / `advancementConditionText` / `closeAt` | 周回・勝ち上がり条件 | 🔴 **レース内で定数** |
| `competitionRecords[]` | 頭対頭 | 🔴 `H2H_COLS_WT` で2度否定済み |

🔴🔴 **レース内で定数の量は、レース内の順位付けには原理的に効かない。**
実証: `bank_length_enc` / `is_indoor` / `grade_enc` はいずれも **gain 0.01% 以下・
`is_indoor` は split 0**（`model_headroom_2026_09_14` §2）。
→ 依頼にあった「バンク別傾向」「開催の格・賞金」「モチベーション代理変数」は
**すべてこの class**。交互作用として設計しない限り取っても効かない。

## 3. E1 — 1本目の印を**外した**ときの劣化（＝2本目の上限）

`exp_model_headroom_ab.py` と同じ 2窓 × 3seed・deterministic。
train 2024-04-01〜test 直前 / test w1 2026-04-13〜07-15・w2 2026-01-01〜04-12。

| 腕 | 窓 | AUC | 1位勝率 | 1位3着内 | 上位2車そろい |
|---|---|--:|--:|--:|--:|
| baseline(70) | w1 | 0.77869 ± 0.00007 | 45.93% | 79.52% | 53.59% |
| **−印(69)** | w1 | 0.77660 | 45.54% | 79.00% | 53.37% |
| baseline(70) | w2 | 0.78094 ± 0.00013 | 46.63% | 79.90% | 54.17% |
| **−印(69)** | w2 | 0.77829 | 46.29% | 79.54% | 53.72% |

**Δ（−印 − baseline）= ΔAUC −0.00208 / −0.00264・Δ1位勝率 −0.39 / −0.33pt・
Δ上位2車そろい −0.23 / −0.45pt**（n=6,065 / 6,427R）。

🔴 **gain 32.17% の特徴を丸ごと外して、そろい率は 0.23〜0.45pt しか落ちない。**
gain は「木がどれだけその列で分岐したか」であって**他の列で代替できない情報量ではない**。
2本目の印が得られる上積みは、1本目の限界寄与を超えない。

## 4. E2 — 印は自社の特徴から復元できる

印を除いた69特徴で「◎が付く車」を学習し、レース内 top1 で当てる:

| 窓 | ◎ top1 的中 | n | 無作為 |
|---|--:|--:|--:|
| w1 | **82.80%** | 7,121R | 14.26% |
| w2 | **81.99%** | 7,646R | 14.17% |

🟢 **印の 82% は自分の持ち物で再現できる。** 印が「他社の私的情報」ではなく
**同じ公開情報の要約**であることの直接証拠。同じ公開情報から作られる
2本目（新聞記者の印も競走得点・ライン・前検を見て打つ）も同程度に冗長と見るのが自然。

## 5. E3 — 「一致率 A の2本目」を合成して ΔAUC の較正曲線を作る

合成: `s2 = A·z(1本目の強さ) + (1−A)·z(私的信号)`、私的信号 = `γ·3着内フラグ + N(0,1)`
（γ は単独 AUC 0.74＝1本目と同等になるよう解析的に設定）。上位4車へ ◎○▲△ を付け直す。

| share | ◎一致率 | 印4車の重なり | 2本目の単独AUC | **ΔAUC** | **Δ上位2車そろい** |
|--:|--:|--:|--:|--:|--:|
| 1.0 | 100.0 / 100.0% | 4.00 / 3.99 | 0.7406 / 0.7448 | −0.00005 / −0.00015 | −0.01 / +0.00pt |
| 0.8 | 97.3 / 97.0% | 3.92 / 3.92 | 0.7493 / 0.7531 | +0.00975 / +0.00890 | +1.48 / +1.44pt |
| 0.6 | 71.8 / 71.8% | 3.46 / 3.45 | 0.7865 / 0.7899 | +0.04197 / +0.04095 | +7.45 / +7.64pt |
| 0.4 | 48.5 / 47.5% | 3.03 / 3.04 | 0.7921 / 0.7940 | +0.05500 / +0.05479 | +9.26 / +8.97pt |
| 0.0 | 21.8 / 21.2% | 2.49 / 2.49 | 0.7264 / 0.7260 | +0.05892 / +0.05765 | +8.99 / +8.84pt |

（w1 / w2。1本目の単独AUC は 0.7406 / 0.7448）

🟢 share=1.0 で ΔAUC ≒ 0 ＝**健全性チェックに通っている**（1本目のコピーは何も足さない）。

🔴🔴 **この表を「2本目を取れば +8pt」と読んではいけない。**
合成2本目の私的信号は**結果そのものから作った**ので、
「1本目と食い違うとき**必ず2本目が正しい**」という、現実の予想家には不可能な仮定が入っている。
E3 が測っているのは「**食い違いが正しいなら**どれだけ効くか」であって、
**食い違いが正しいかどうかは E3 では分からない**。そこを測るのが E4。

## 6. E4 — 食い違いは正しいか（1本目で実測）

台 `/tmp/race_type_board.npz`（7車・vintage walk-forward の p3）。
自社モデル top1（p3最大）と ◎ を突き合わせる。

| 窓 | n | 一致率 | 不一致 n | 不一致での3着内率 モデル ↔ ◎ | Δ（CI95） |
|---|--:|--:|--:|---|---|
| 探索 2024-07〜2025-12 | 25,833 | 89.7% | 2,664 | 67.64% ↔ **70.23%** | **−2.59pt [−5.22, +0.19]** |
| 確認 2026-01〜08 | 10,404 | 90.3% | 1,007 | **68.92%** ↔ 66.73% | **+2.18pt [−1.89, +6.16]** |

🔴 **符号が窓で反転し、両窓とも CI が0を跨ぐ。**
＝ **1本目の印の「食い違い」には情報が無い**（自社モデルと互換）。
これが E1 の小ささ（そろい −0.23/−0.45pt）と整合する。

## 8. 🔴 決着をつける実験のコスト見積り

2本目の印が効くとしたら経路は1つ:
**「1本目（と自社モデル）と食い違うレースで、2本目のほうが正しい」**。
これを測る物差しは §6 E4 とまったく同じ。必要なサンプル数は E4 から外挿できる:

- E4 の不一致 n=1,007 で 3着内率差の CI 半幅は **約4pt**。
- 意味のある差（そろい率 +0.3pt に相当する軸精度差 ≒ 1.5pt）を分離するには
  **不一致レースが約 1,007 × (4/1.5)² ≒ 7,150本**。
- 不一致率は 10〜15% 程度（1本目で 9.7〜10.3%）なので、**必要な総レース数は 5〜7万本**。
- 全開催は 1日 約100レース ＝ **1.5〜2年**。過去ページが取れるサイトなら短縮できるが、
  **朝の印を後から取れる保証はない**（更新で上書きされうる）。

一方 **勝ち取れる上限は §3 の −0.23 / −0.45pt（そろい率）**で、
`keirin_protocol` の窓間 SD は **0.15pt**。**測定コスト（1〜2年）と上限（SD の1.5〜3倍）が
釣り合わない。**

### それでも安く測れる第1段スクリーニング（3日・約300req）

本試験の前に、**300レース**（≒3日・チャリロト/Kドリームスなら **24〜48 req**、
スポニチなら約300 req）で次の2つを測れば、ほとんどの場合そこで終わる:

| 指標 | 落とす基準 | 根拠 |
|---|---|---|
| ① 自社69特徴からその印の ◎ を復元できる率 | **≥ 75% なら不採用** | winticket の印は 82.0〜82.8%（§4）。同水準なら同じ公開情報の要約＝冗長 |
| ② winticket ◎ との一致率 | **≥ 85% なら不採用** | §5 の曲線で 97% 一致だと そろい +1.4pt まで落ちる（しかもそれは「食い違いが常に正しい」仮定つき） |

n=300 なら①の SE は約 2.2pt・②の SE は約 2.1pt で、この閾値は十分に判別できる。
①②を通過した場合にのみ、§8 の本試験（1〜2年の前向き収集）を検討する価値がある。
