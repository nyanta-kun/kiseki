## 2. `A_ana` は設計と矛盾していた

`A_ana` は**軸1を買い目から完全に外して「軸1が飛ぶ側」に賭ける商品**。
そこへ軸信頼ゲート（軸が堅いレースを残す）を掛けるのは**狙いと正面から逆**で、
実測でも両窓で逆効果（−1.68 / −3.53pt）。掛けること自体が誤りだった。

なお `A_ana` の条件（`pw_ent` 上位10%）自体は妥当で、
**軸1が3着外だった割合を 8.1→21.3% / 9.7→23.3%（リフト 2.6/2.4倍）**に濃くできている。
軸1が実際に飛んだレースに限れば表示的中 25.00 / 20.24% と型A全体並み。

増える分だけを見ると 下位1/10 で 表示的中 25.04 / 23.66%、全部外すと 23.35 / 22.05%。
**本採用（効く4プランだけ残す）はこの中間**で、効いている分離を全部保ったまま件数を増やす。

🔴 **日次上限は件数のダイヤルではない。** 2026-09-02 の実測で朝に `daily_cap` で
落ちた11件のうち **8件は昼・夕の波で拾い直されている**（上限は「捨てる」のではなく
「遅らせる」）。上限を外しても日合計は 43 → 46件（+3件）にしかならない。
動くのは**朝の露出**だけなので、件数を増やす目的で触っても効果がない。

## 4. 実装

`AXIS_GATE_MIN` を4プランへ縮小し、**外したプランは `AXIS_GATE_EXEMPT_PLANS` に
理由つきで明示**する。

🔴 `passes_axis_gate` は**表に無い鍵を通す**ので、閾値の足し忘れは
エラーを出さずに素通りする（2026-08-31 に型A を3分割したとき実際に踏み、
型Aの入稿21件のうち10件がゲート未通過だった）。
そのため「掛けない」も明示が要る形にし、
`test_every_sellable_plan_has_an_axis_gate_threshold` が
**`AXIS_GATE_MIN` ∪ `AXIS_GATE_EXEMPT_PLANS` が売りうるプランを覆うこと**を要求する。
新しいプランはどちらかへ書くまでテストが落ちる。

## 5. 限界

⚠️ **符号反転は「効かないことの証明」ではない**（判定不能）。外したのは
「効く根拠が無いものに件数を払わない」という判断であって、害の証明ではない。
戻すときは 20seed の無作為対照を置いて測り直すこと。

⚠️ 本稿は**増える側の成績を直接出す**形で、無作為対照は置いていない。
増分の表示的中がベースとほぼ同じなので方向は堅いと見ているが、
`docs/RECOMMENDATION.md` §6 の作法どおりの対照ではない。
