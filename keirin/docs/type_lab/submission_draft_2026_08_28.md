# 型ラボの入稿データ（タイトル・メッセージ・印）の設計とサンプル（2026-08-28）

**問い**: 型ラボのプランを採用するとき、netkeirin へ入稿するための
**タイトル・メッセージ・印（◎○）を作れるか。**

**答え: 3つとも作れる。** 既存ランクと同じ経路・同じ部品でそのまま組める。
ただし**既存ランクの文面をそのまま流用してはいけない**（下記 §3）。

- 文面と印の正本: `keirin/src/type_lab_submission.py`（**標準ライブラリのみ**）
- 実データで組んで見る: `keirin/scripts/preview_type_lab_submission.py`
- 検査: `keirin/tests/test_type_lab_submission.py`

🔴 **まだ入稿していない。** `netkeirin_submit_wt.py` はこのモジュールを import して
いない。採否が決まってから `RANK_CONFIGS` 相当の結線を別途行う。

---

## 1. 既存ランクの入稿経路（何を再利用できるか）

netkeirin へ出す1商品は次の4つで構成される。型ラボでも部品はすべて同じ。

| 部品 | 既存ランクの出どころ | 型ラボで使えるか |
|---|---|---|
| タイトル | `netkeirin_settings.title_template`（DB・設定画面で編集可）＋ `src/race_shape.py::SHAPE_TITLES`（コード） | 🟢 同じ2ブロック構成。後半だけ差し替える |
| コメント | `RANK_CONFIGS[rank]["default_comment"]` ＋ `{shape_note}` などの差し込み | 🟢 同じ。文面はプラン別に持つ |
| 印 | `_normalize_*_candidate()` が返す `marks`（`{車番: "◎"/"○"/"▲"/"△"}`） | 🟢 `p3_order` と買い目から導ける |
| 出走表HTML | `netkeirin_submit_wt._build_entry_table(race_key, marks)` | 🟢 **そのまま呼べる**（写さない） |

差し込み変数は `_apply_template` の
`{venue}{race_no}{rank}{date}{axis1}{axis2}{shape}{shape_note}{stake_note}{race_type}{wide_note}`。
型ラボは `{shape}` / `{shape_note}` に相当するものを**型（A〜F）から**作る。

---

## 2. 🟢 型ラボは既存ランクより文面の根拠が強い

既存の `race_shape.classify_shape` は **表示専用ラベル**で、買い目の選定には
関与していない（docstring に「どのレースを買うかには一切影響しない」と明記）。

型ラボの型（A〜F）は逆で、**買い方を決めた根拠そのもの**。
したがって「タイトルに書いた見立て」と「実際に買うもの」が構造的にずれない。

    ① 軸の堅さ axis_sum → 堅い(A/B/C) / 混戦(D/E/F)
    ②〜⑥ 荒れ度 arare  → 各3分割
                        ↓
              型が PLANS を選ぶ = 買い目が決まる
                        ↓
              同じ型が TYPE_VIEWS / TYPE_NOTES を引く = 文面が決まる

## 3. 🔴 実データで見つかった制約（既存文面を流用できない理由）

### 3.1 「軸2車流し」と書けないプランがある

確率上位から積む `B_hit` / `C_hit` / `E_hit` は、**買い目の大半が
◎○を1・2着に並べていない**（`type_lab_picks` 2026-06〜08 実測・各400件）:

| プラン | 買い目に出る車数（平均） | 軸2車が1・2着**でない**目 |
|---|---|---|
| `A_hit` | 5.00 | 0.0% |
| `A_pay` | 6.00 | 50.0% |
| **`B_hit`** | 5.53 | **56.2%** |
| **`C_hit`** | 6.20 | **66.5%** |
| `D_hit` | 6.00 | 0.0%（三連複） |
| **`E_hit`** | 6.11 | **72.6%** |
| `F_hit` | 4.00 | 66.7% |
| `F_pay` | 5.00 | 50.0% |

既存の共通既定文「買い目は三連複・軸2車流しです」をそのまま使うと、
これらのプランでは**過半のレースで嘘になる**。
→ `PLAN_BODIES` をプランごとに持ち、B/C/E には
「◎○が2着・3着へ回る目も含みます」と明記する。
`tests/test_type_lab_submission.py` がこの3プランに「軸2車流し」と書けないことを固定している。

### 3.2 印は「買った車」にだけ付ける

`D_hit` は**相手のうち最も人気の1車をあえて外す**のが設計の核心。
その車に印を付けると「買っていない車を推している」ことになる。

実例（奈良3R 2026-08-26・指数順 `3-1-7-4-2-5-6`）:

    ◎3  ○1  ▲7  △2  △5  △6      4番は無印（外した相手）

⚠️ **4番の3着内率は 47.6%（全体3位）**。指数上位なのに無印という見え方になる。
これは商品の性格どおりだが、買い手には説明が要る（コメントで触れている）。

### 3.3 `E_hit` は全車に印が付くことがある

予測30倍以上の帯を14点で広く押さえる商品なので、買い目に出る車は平均 6.11／7車。
実例（玉野12R 初特選 2026-08-26）では ◎○▲△△△△ と**7車全部**に印が付いた。
上の §5.1 の例（青森1R）は5車で収まっており、**レースによって印の数が大きく振れる**。
印が絞り込みの信号にならないのは商品の性格そのものなので、
**見栄えのために印を間引かないこと**（間引くと買っていない目が出る）。

### 3.4 配分の説明は `legs` から導く

型ラボの配分はダッチ（∝1/予測オッズ）と信頼度傾斜の2種類だが、
**点数が少なければ結果的に均等に近くなる**。テンプレートに固定で
「オッズに応じて配分」と書くと均等のレースで嘘になる。
`alloc_note()` が実際の賭け金のばらつき（`> STAKE_UNIT`）で判定する
（`netkeirin_submit_wt._stake_note_for` と同じ考え方・同じ理由）。

### 3.5 Markdown は通らない

netkeirin のコメント欄は **HTML は通るが Markdown は解釈しない**
（`_build_entry_table` が `<table>` を直接埋めているのはそのため）。
`**強調**` はアスタリスクがそのまま商品説明に出る。テストで固定した。

## 4. 印の付け方（`marks_for`）

    ◎ = 軸1（＝ p3_order の1位）
    ○ = 軸2（＝ p3_order の2位）
    ▲ = 買い目に出てくる非軸車のうち、指数が最上位の1車
    △ = 買い目に出てくる残りの車
    無印 = 買っていない車

**`p3_order` の上位N車ではなく、実際の買い目から導く**のが要点（§3.2）。
既存ランクの `marks = {**{c: "△" for c in partners}, axis1: "◎", axis2: "○"}` も
同じく買い目由来なので、考え方は揃っている。

### 5.2 `A_hit`（型A・鉄板）— 松阪11R 準決勝 2026-08-26

```
■ タイトル
  本線の三連単｜二軸が堅い一戦

■ 印
  1◎  4○  5▲  6△  7△     （無印: 2, 3）

■ 買い目（3点）
     1-4-5   6,400円  予測  2.6倍  想定払戻 16,384円
     1-4-7   2,100円  予測  9.9倍  想定払戻 20,748円
     1-4-6   1,500円  予測 16.2倍  想定払戻 24,315円

■ コメント
  指数の上位2車がはっきり抜け、レースが荒れる要素も見当たらない一戦です。
  着順まで踏み込んで狙えると読みました。

  【二軸】
  本レースで照らし出した二軸は、◎1番・○4番です。

  【買い目】
  買い目は三連単。1着に◎、2着に○を固定し、3着だけを流しました。
  着順まで読み切れる形と判断したので、順番の入れ替えは買っていません。
  三連単 3点。金額は均等ではなく、当方が想定する発走時オッズに応じて配分しています。
  配当が低くなりやすい目に厚く、高くなりやすい目に薄く置き、
  どの目で決まっても払戻が投資を上回ることを狙う組み立てです。

  【ご購入にあたって】
  この配分は当方が想定する発走時オッズに基づくものです。
  レース直前の実際のオッズをご自身でご確認いただき、
  必要に応じて配分を調整いただくと精度が上がります。
```

```
  【二軸】

```

## 7. 🔴 採用前に決めること（このドキュメントでは決めていない）

1. **`_hit` と `_pay` のタイトルが型Aと型Fで同じ語になる**
   （`A_pay` も `F_pay` も「一撃の三連単」）。狙いは同じなので妥当だが、
   店頭で並んだときに区別が付かない。分けるなら語を決める必要がある
2. **`E_hit` の全車印**（§3.3）を商品として許容するか
3. **`D_hit` の無印が指数上位になる**（§3.2）ことへの説明を、
   コメント本文でもっと明示するか
4. **1レース1商品の制約**。型ラボのプランは型で排他だが、
   **既存ランクとは重なる**（型A 約46% / 型F 約47%）。
   入稿の優先順位に組み込む設計が別途要る
5. タイトル・コメントを `netkeirin_settings` の DB テンプレートで
   編集可能にするか（既存ランクは可能）。可能にすると
   「文面はコード側の正本」という原則と衝突する
