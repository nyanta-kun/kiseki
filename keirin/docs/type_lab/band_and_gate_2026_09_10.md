# 帯 `min_odds` と入稿ゲート `MIN_MEAN_PAYOUT` — 設計意図の切り分けと2次元掃引（2026-09-10）

> 依頼（当初）: 「印もあり、近い目を多数買っているのに的中目がないレースが多い」。
> `mark_order_2026_09_10.md` §3 が測ったのは「1点足す」だけなので、
> **帯とゲートの水準そのもの**を測り直す。
>
> 🔴 **依頼の再定義（同日・ユーザー指摘）**:
> 「本命線はレース出走選手の力関係を見た結果、固い場合は軸から点数を絞り、
> 波乱と見る場合は軸上位を場合によって外すなど、**レースの読みに合わせた提案をするのが
> 現在の予想ロジック**。この前提を蔑ろにして個別に変更を積み上げると全体としての設計が崩れる。
> 狙うべきレース選定・推奨方法を再定義し、そこに対して外れた場合に
> **どの観点で外れているかを正しく分析できる**ようにしてほしい」
>
> したがって本稿は**単独ノブの採否提案をしない**。書くのは次の2つだけ:
>   ① 帯は「読みを表現する道具」なのか「入稿ゲートを通すための辻褄合わせ」なのか
>   ② 外れを「読みの失敗」と「買い目の失敗」に分けて数える枠組みと、その実測
>
> 再現: `scripts/exp_type_lab/band_gate_build.py`（台）→ `band_gate.py`
> （`base` / `intent` / `miss` / `typing` / `band` / `gate` / `grid` / `d` / `retype` / `lineup`）

## 1. 🔴 先に本番コードと既存 doc を読んだ結果 — 帯は「読み」ではなく「価格」

### 1.1 設計者の言葉（`docs/type_lab/type_e.md`）

> 「30倍 × 14点 を採るのは、**①平均想定が 3.0〜5.0万帯の中央に来る ②ガミが 2% を切る
> ③下限 30倍が既に `RANK_7T3` で使われている定数**、の3点から。」
>
> 「平均想定払戻 47,100円 は `docs/sales_kpi.md` の **3.0〜5.0万帯（pt/R 309・最も売れる）**に入り…」
>
> 「🔴 **ただし「型E固有の買い方」ではない**。同じ腕を他の型に当てても表示的中 15.5〜18.6%・
> 払戻中央 31,570〜36,925円で**ほぼ同じ数字が出る**。**型Eを選ぶ根拠は成績ではなく**、
> 型Eが現行で薄いこと（無商品 43%）と型Eの三連複が売れない帯に落ちること」
>
> 「🔴 **一般則: 予測オッズ下限で払戻帯を揃えると、型が違っても表示的中はほぼ同じになる。
> 型が決めているのは「同じ買い方をしたときにどの帯へ落ちるか」だけで、
> 下限をダイヤルにすれば型に依らず任意の帯へ移せる。**」

**採否の3根拠に「型Eは荒れると読んだから」が1つも無い。** 帯30倍は
**netkeirin で最も売れる 3〜5万円帯へ商品を置く**ための価格設定である。
これは誤りではなく**店頭価格の設計**だが、**レースの読みの表現ではない**。

### 1.2 他のプランのコメントも同じ

| プラン | コードの言葉 | 何を表現しているか |
|---|---|---|
| `C_hit` 帯15 | 「型C 堅いが崩れ筋 — **帯を切って点数を増やす側**」／2026-09-01 の 20→15 は「**決着の目が20倍未満で帯が外していた**…**モデルではなく帯が主因**」／2026-09-08「🔴🔴 **帯そのものを下げてはいけない。**平均想定払戻2万の入稿ゲートに落ちて**在庫が消える**」 | **点数を確保するための下限**。下げられない理由は読みではなく**ゲート** |
| `E_hit` 帯30 | 上記 §1.1 | **価格帯（3〜5万）** |
| `F_hit` 帯5 | 「🔴 **これは帯ではない。**帯15倍への丸ごと置換は 2026-09-03 に測って不採用。**5倍は「大混戦なのに単勝並みに安い目」を落とすだけ**」 | 帯ではない（配分の床の副作用対策） |
| `B_hit` `sigma_max=1/3` | 「確率上位から**想定平均払戻 30,000円を割らない点数まで**」 | **価格帯**（ゲートの2万より厳しい自前の床） |
| `D_hit` `axis2_drop_fav` | 2026-09-01 の 4→3 は「型D は**的中頻度に対して払戻が足りない**（損益分岐に要る 37,222円 ↔ 実際 28,696円）」 | **払戻の工作**（読みではない） |
| `A_ana` `bust_top` | 「🔴 **軸1（p3 1位）を買い目から完全に外す。**「軸1が3着にも入らない」ことに賭ける商品なので、軸1を含む目を1点でも買うと**商品が矛盾する**」 | 🟢 **読みそのもの** |
| `_big` `bust=True` | 「**軸1を含む目を全部外す**」 | 🟢 **読みそのもの** |

🟢 **切り分けの一般形が出た**:
**読みを表現する除外は「車」で切る**（`bust_top` / `bust`）。
**「オッズ」で切る除外（帯・Σ床・drop_fav）は全部、価格帯を作るための道具。**
両者を混同すると「本命を買っていないのは設計だから正しい」と読み違える。

### 1.3 算術 — 帯の水準はゲートと点数から決まる

ダッチでも `conf`（床 `floor_mult=2.0`）でも、k 点を組める条件は **Σ(1/予測オッズ) ≤ 予算/T**。
つまり **予測オッズの調和平均 ≥ k×T/予算** が要る。T=20,000 / 予算10,000 で:

| プラン | 点数 k | ゲートが要求する調和平均オッズ | 実際の帯 | 差 |
|---|--:|--:|--:|--:|
| `C_hit` | 12 | 24.0 | 15.0 | −9.0 |
| `E_hit` | 14 | **28.0** | **30.0** | **+2.0** |
| `F_hit` | 12 | 24.0 | 5.0 | −19.0 |
| `B_hit` | 8 | 16.0 | （帯なし・Σ床3万で直接縛る） | — |

**`E_hit` の帯30は、14点を2万円ゲートに通すのに要る 28倍とほぼ同値。**
`C_hit` が要求値より低くていられるのは `underband_min=5.0` の差込と `GATE_FALLBACK` が
落ちた分を拾っているから。`F_hit` の 5.0 はそもそも帯として機能していない（§4 で実測）。

### 1.4 本番が既に「帯は切りすぎ」と認めている

`_insert_underband`（2026-09-08・`C_hit` と `F_hit` のフォールバック）は
**帯の下から最も人気の1点を買い戻す**操作である。docstring:

> 「🔴 **選ぶのは「モデルが最有力とみる目」ではなく「最も**人気**の目」**…
> 効いているのは**「帯の下の目を1点でも持つこと」自体**であって、モデルの目利きではない。」

＝ **本番自身が「帯が本命側を切りすぎている」と判断して1点だけ戻している。**
帯が読みの表現なら、この操作は商品を矛盾させるはずだが、そうは扱われていない
（`A_ana` で軸1を1点でも買うことは「商品が矛盾する」と明記されているのと対照的）。

## 3. 🔴🔴 外れを「読みの失敗」と「買い目の失敗」に分ける

依頼の中心。**同じ「外れ」でも打ち手が正反対**なので、5つに割って数える。
判定は `band_gate.py::classify()`（1商品1行に付く排他ラベル）。

| ラベル | 定義 | 意味 | 直し方 |
|---|---|---|---|
| ① `hit` | 的中 | — | — |
| ② `read_axis` | 軸2車（p3上位2車）のどちらかが3着外 | **前提の崩壊**（読みの失敗） | 型判定・軸選定 |
| ③ `read_band` | 軸2車はそろったが、**決着の目が商品の帯の下** | **型判定の失敗**。「荒れる」と読んだのに本命側で決まった。**買い目をいじって拾うのは、読みが正しいなら間違い** | 型判定（帯ではない） |
| ④a `legs_budget` | 帯の中で決着し、**モデルは決着の目を買う点数 k 位以内に置いていた**のに買えていない | **設計の破れ**。Σ床・`drop_fav`・配分の床が落とした | 買い目 |
| ④b `legs_model` | 帯の中で決着し、モデルの確率順位でも k 位より下 | **モデルの限界** | モデル |

### 読み方

- 🔴 **`C_hit` と `E_hit` の◎○△取りこぼしは、88.4% / 91.7% が③＝型判定の失敗。**
  「◎○△で決まったのに買えていない」の正体は買い目の粗さではなく、
  **「荒れる」と読んだレースが実際には本命で決まったこと**。
  したがって `mark_order` §3 の「1点足す」は**買い目の直し方で読みの失敗を埋める**操作で、
  ここに効いてしまうのは「読みの誤りを商品側で薄める」ことを意味する。
  設計を保つなら、直すのは**型判定**であって帯ではない。
- 🔴 **`D_hit` は逆。** ◎○△取りこぼし 74.74% が**100% ④＝買い目の失敗**で、
  かつ `D@drop4`（点数だけ4に戻す）では取りこぼしが 74.5% と動かない一方、
  `D@flow3/4`（最人気の相手を外すのをやめる）で **0%** になる（§7）。
  ＝ **`axis2_drop_fav` が、そして**それだけが**、`D_hit` に本命を買わせていない。**
- 🔴 **`B_hit` の取りこぼしの 59% は④a＝予算制約（Σ床3万）。** 帯を持たないのに
  本命を買えていないのはこの床のせい。
- 🟢 **`A_hit` の取りこぼしは 100% が④b＝モデルの限界**（3点しか買わないので当然）。
  ここは帯もゲートも無関係で、**打ち手は点数かモデルしかない**。
- 🟢 **`A_trio` の◎○△取りこぼしは 1.75%**（三連複なので並びで落ちない）。
- 🟢 **`A_ana` / `F_sign` の取りこぼし 100% / 87.5% は設計どおり**（当てにいかない商品）。
  ここを「外れ」として同じ表に混ぜて数えると全体の見え方が歪む。

### 提案（打ち手ではなく計測の器）

**この5分類を `keirin.type_lab_picks` の列として毎日焼き付ける**ことを勧める。
必要な入力（決着の目の予測オッズ・確率順位・軸2車の生死・商品の帯）は
すべて生成時に手元にあり、後から作り直せない（モデル再学習で確率が変わる。
`outcome_matrix_2026_08_27.md` §「決着の分類は後から作れない」と同型の罠）。
これがあれば、日々の「当たらない」に対して
**「読みが外れたのか / 買い目が外れたのか / モデルが届かなかったのか」を
その場で答えられる**。今はどれも「表示的中が低い」としか言えない。

決着を切るのは 1.5%）。コードの記述どおり。

| `A_trio` | 順序を捨てて当たる回数を取る | ◎○△取りこぼし 1.75%。**「本命を買えていない」問題が構造的に存在しない唯一の商品** |
| `B_hit` | 想定平均払戻 3万円の床 | 床は**価格の選択**。2.5万でも在庫は変わらず表示的中 +2.4〜3.1pt（両窓有意）。**3万を選んだ理由は払戻であって読みではない** |
| `C_hit` | 帯を切って点数を増やす | 帯15 は**ゲートに 12点を通すための下限**。既に `underband_min=5.0` で本命1点を戻している。**帯を単独で下げると在庫が消える**（設計として整合している） |
| `D_hit` | 最人気の相手を落として払戻を作る | **本命を買えない原因はこれ1つ**。読みではなく価格の工作なので、「型Dの読みだから本命を買わない」とは言えない |
| `E_hit` | **3〜5万円の価格帯へ商品を置く**（doc 明記） | 帯30 は**在庫を1件も増やしていない**（E@20/25 と同じ 3.74件/日）。買っているのは払戻中央 +24% と 10万+ 2.5倍。**価格設計としては筋が通っている**が、**「型Eは荒れると読んだから30倍+」という説明は成り立たない** |
| `F_hit` | 確率上位12点 | 帯5は帯ではない。取りこぼしは 54% がモデルの限界・15% が予算制約 |

### 依頼「狙うべきレース選定・推奨方法の再定義」に対して本稿が言えること

1. 🔴 **いま「読み」を担っているのは型判定と点数 k だけ**で、帯・Σ床・`drop_fav` は
   すべて**価格の道具**である。**この3つを「読みの表現」として扱うと設計の説明が破綻する。**
   説明を直すか、道具を読みへ結びつけ直すか、どちらかを選ぶ必要がある。
2. 🔴 **価格の道具は1本に畳める。** ダッチ／床つき配分では
   **「平均想定払戻 ≥ T」⟺「Σ(1/予測オッズ) ≤ 予算/T」**が恒等式なので、
   帯 L・点数 k・Σ床・ゲート T は**独立した4つのノブではなく1つの制約面**である
   （`coverage_framework_2026_08_31.md` の τ と同じ）。
   現状は同じ制約を4箇所で別々に表現しており、**1つを触ると他が黙って動く**
   （②「帯だけ下げる」が破壊 151 件を出したのがその実例）。
3. 🟢 **外れの分類（§3）は今すぐ器として置ける。**
   ②軸崩壊 / ③帯下決着（型判定の失敗）/ ④a 予算制約 / ④b モデルの限界。
   これは知見ではなく**計測の器**なので、設計の再定義とは独立に導入でき、
   再定義の後もそのまま使える。**後から作り直せない**（確率がモデル更新で変わる）ので、
   置くなら生成時に焼き付ける。
4. 🔴 **`q_m3` による型の細分化は今の入力では効かない**（§8・両窓で符号反転）。
   「型判定の失敗を型判定で直す」は、**新しい入力なしには成立しない**。

## 11. 限界

- ⚠️ **確認窓（2026-01〜08）をまた消費している。** 本稿だけで 100腕以上を見ている。
  §6・§9 の CI は多重比較の後に出てきたもので、単独では採用の根拠にならない。
- ⚠️ **9車・6車は対象外**（板が7車）。ゲートは 9車では向きが逆
  （`stake_allocation.py` の設計コメント）ので、本稿の結果を9車へ持ち込んではいけない。
- ⚠️ **高額枠（`_sign` / `_big` の B/C/D）と日次上限を模していない。**
  ゲートを下げると在庫が 4.4件/日 増えるが、それが日次上限で押し出す商品との
  相互作用は未検証（`GATE_FALLBACK` の設計コメントが同じ未検証を挙げている）。
- ⚠️ **`RaceShape.lines` を渡したのは本稿が初めて**なので、過去の exp doc の
  ベースラインとは `line_legs`（ライン決着への差し替え）のぶんだけ数字が違う。
  過去 doc と直接引き算しないこと。
- ⚠️ §3 の分類のうち ④a / ④b の境界は「モデルの確率順位 ≤ 買った点数 k」で引いている。
  k が大きい商品ほど ④a に寄る（`E_hit` は 14点なので ④a が 0.00% になる）。
  **商品間で ④a / ④b の比率を直接比べない。**
- ⚠️ ROI はどの腕でも判断に使っていない（±2.5pt に約15.6年）。
  本稿で ROI を根拠にした主張は「**動かない**」という否定形だけ。
