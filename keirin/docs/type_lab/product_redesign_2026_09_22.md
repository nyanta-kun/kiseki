# 商品設計の見直し — 「当たらない・払戻が下がりすぎ」への回答（2026-09-22）

ユーザー要望（2026-09-22）:

> 当たらないし、払い戻しが下がりすぎです。全般的な商品設計見直しが必要です。
> 4万以上の払い戻しを取り的中率、回収率が必要です。元の商品でそれなりの結果出ていたものが
> 変更なしに悪化しているようなので同程度に戻せるか、ダメなら別で検討いります

結論を先に3行:

1. **「変更なし」ではない。** 26日で `rule_version` が14回変わり、9/08〜9/21 の変更は
   すべて「払戻を下げて表示的中を買う」向きだった。実測で**当てにいく商品の計画払戻中央が
   30,100 → 24,440円（−19%）**、4万以上の払戻が **6.0% → 2.0%/商品**（週次・p≈0.01）。
2. **元（9/07）へ戻しても 4万+ は 1.23 → 1.46件/日 にしかならない**（両窓一致）。
   戻すだけでは要望に届かない。
3. **予算は既に netkeirin の上限（1商品 10,000円）** なので、払戻を上げる手段は
   「点数を絞る／高い目を買う」だけで、**表示的中との1本のダイヤル**になる。
   測った最良の操作点は **型A/B/C を「どの目が来ても5万円」のダッチ商品へ替える**:
   4万+ **+48%**・3万+ **+39%**・件数 **+1.35件/日**・**ROI 不変**、代償は表示的中 −4.0〜4.3pt。

## 2. 構造の制約（ここを外すと議論が空回りする）

### 2.1 予算は netkeirin の上限に張り付いている

`docs/netkeirin-input-api-spec.md` §7.3:

> 合計買い目金額(`bet_money_sokei`)は **1,000円以上10,000円以下**

本番の `BUDGET = 10,000` は**上限そのもの**。「単位を2万円にして払戻を倍にする」は
**プラットフォームが許さない**。

### 2.2 したがって払戻と的中率は1本のダイヤル

ダッチ配分では恒等式 **`P(払戻 >= X) ≒ ROI × 予算 / X`**（`type_lab.py` の
`SIGNBOARD_TYPES` 節と同じ式）。ROI は市場の控除率で 78〜82% に張り付いていて
（監査 `AUDIT_2026_09_20.md` §3: モデルは確定オッズに対し追加情報ゼロ）、予算は 10,000円で
固定。**残る自由度は「1商品あたりの狙う払戻」だけ**で、それを上げれば的中率は必ず下がる。

    計画払戻 2万円 → 的中 40%     4万円 → 20%     6万円 → 13%   （ROI 80% のとき）

🔴 **「4万以上の払戻」と「的中率」は同時に上げられない。** 上げられるのは、同じ的中率で
より高い払戻を取る＝**効率境界の上に乗ること**だけ。以下はその境界を測ったもの。
