直前の実測（`mark_second_third_bets_2026_09_12.md` §8 限界2・`low_confidence_axis_products_2026_09_12.md` §9 限界3）は

   `{型}_sign`(15万) / `{型}_big`(40万・軸1外し) にするかを決め、狙いの行が無ければもう片方。
   入稿ゲートに落ちたら**枠は消費しない**。

## 9. 限界

1. **paired bootstrap は日単位**（レース単位ではない）。純増の腕は増えた行が基準に存在しないため
   レース単位の対応が取れない。日は両腕で共有するので paired 性は保っている。
2. **日次上限落ちの本数が台では約半分**（§0.1）。並び未公開を再現できないため。
   λ=0.30〜0.35 で較正し、**結論が λ=0.25〜0.50 の全域で変わらないことを確認**した。
3. **台は7車のみ。** 本番の型ラボは 54.6件/日 で、台の 28件/日 は 7車ぶん。
   9車・6車は日次上限の**枠外**なので上限の分母には入らないが、
   **`daily_portfolio` の「件/日」と本稿の「件/日」を直接比べてはいけない**。
4. **`{型}_sign` / `{型}_big` は `build_legs`+`allocate` で組んでおり `build_with_gate_fallback` を通していない**
   （基準の売る商品だけが通っている）。signboard は `LINE_SWAP_PLANS`/`ORDER_SWAP_PLANS`/`OSAE_PLANS`/
   `tau_adaptive` のいずれにも入らず、計画15万ではゲート通過が 100%（`low_confidence` §2.1）なので
   fallback は発火しない。**実害は無いが厳密には同一経路ではない。**
5. **確認窓は既に焼けている**（`mark_second_third_bets_2026_09_12.md` §8 で延べ193腕）。
   本稿の確認窓の一致は「再現の確認」までで、採用の根拠は前向き実地に置く（計画 §0）。
6. **10万+ / 30万+ は Poisson ノイズが支配的**。確認窓 216日で 10万+ は 50〜123件なので
   0.03件/日 前後の差は判別できない（§3 の型F の CI 幅がそれ）。
7. **多重比較**: λ5通り × 商品4通り × 型3通り × 供給3通り × 2窓 ≒ 360セルを眺めている。
   結論に使ったのは「①単独はゼロ」「①+②は全セルで CI 0 跨がず」という**符号が全セル一致する所見**だけに絞った。
8. **`missing_lineup` の相互作用が未評価。** 軸ゲート落ちを高額枠へ回すと
   `submission_skips` の `axis_gate` が減る（計画 §2.1b の申し送り）。
   本稿はログの読み方の変化を数値化していない（在庫 12.7件/日 のうち高額枠へ回るのは 4〜6件/日）。
