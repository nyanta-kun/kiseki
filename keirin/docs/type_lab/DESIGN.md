# 型ラボ 設計の正本 — 狙うべきレース・推奨方法・外れの見方（2026-09-10）

> **なぜこの文書があるか**（2026-09-10 ユーザー指摘）:
>
> > 本命線はレース出走選手の力関係を見た結果、固い場合は軸から点数を絞り、波乱と見る
> > 場合は軸上位を場合によって外すなど、**レースの読みに合わせた提案をするのが現在の
> > 予想ロジック**。この前提を蔑ろにし、個別に変更を行なっていくと**全体としての設計が
> > 崩れる**。
>
> 実際、`docs/type_lab/` には40本近い検証記録があり、その多くが「1つのノブを動かして
> 表示的中が ±1pt」という形をしている。**個々の測定は正しくても、設計のどこを触って
> いるのかが記録されていないため、積み上げると設計が読めなくなる。**
> 本文書は**変更の可否を判断する土台**であり、数字の記録ではない。
>
> 🔴 **新しい案を持ち込むときは、まずこの文書のどの層を触るのかを言うこと。**
> 層を跨ぐ変更は単独で採否を決められない。

## 0. 一行で

**レースを「①軸の堅さ × ②荒れ度」で6型に読み、読みに合った買い方をちょうど1つ売る。**

型は排他なので `sell_plans_for()` が返すのは必ず 0 個か 1 個で、
**1レース1商品**（netkeirin の予想家アカウント1つ・1レース1万円固定）が構造的に保証される。
`tests/test_type_lab_submit.py` が全型・全車数でこれを固定している。

# 第1層 — レースを読む（型判定）

正本は `src/type_lab.py::race_shape()`。入力は当日朝に確定するものだけ
（3着内率 `p3` / ライン `line_group`・`line_pos` / 脚質 / 競走得点 / 遅れ率 / 開催日目）。

## 1.1 2つの軸

| 軸 | 量 | 定義 | 何を支配するか |
|---|---|---|---|
| ① 軸の堅さ | `axis_sum` | **3着内率の上位2車の合計**。境界 `AXIS_SUM_FIRM = 1.44` | **的中率** |
| ② 荒れ度 | `arare`（コード上は `s`） | ライン規模 / 先頭の遅れ率 / 先頭が「追」 / 開催日目 / 番手の競走得点が先頭超え、の加点 | **配当** |

    firm = axis_sum >= 1.44
    firm  かつ  s<=-1→A / s==0→B / s>=1→C
    not firm かつ s<=-1→D / s==0→E / s>=1→F

| 型 | 名前 | 読み |
|---|---|---|
| A | 鉄板 | 軸2車が堅い・荒れにくい |
| B | 堅い・中 | 軸2車が堅い |
| C | 堅いが崩れ筋 | 軸2車は堅いが荒れ要素あり |
| D | 混戦・軸あり | 軸は割れるが荒れにくい |
| E | 混戦・中 | 軸も割れ、荒れ要素もある |
| F | 大混戦 | 軸も割れ、荒れやすい |

## 1.2 🟢 読みは実測で再現している（確認窓 2026-01〜08・板 7車）

**① 軸の堅さ → 軸2車がそろう率**（`axis_sum` の主張）

| 型 | A | B | C | D | E | F |
|---|--:|--:|--:|--:|--:|--:|
| 軸2そろい% | 60.59 | 62.23 | 58.04 | 42.43 | 41.75 | 37.42 |

**③ 荒れ度 → 配当**（`arare` の主張）

| 型 | A | B | C | D | E | F |
|---|--:|--:|--:|--:|--:|--:|
| 確定三連単オッズ中央 | 24.9 | 27.3 | 36.0 | 47.5 | 52.2 | 62.2 |

🟢 **主張どおりに分かれている。** `axis_sum` は A/B/C（58〜62%）と D/E/F（37〜42%）を
分け、`arare` は A→F で配当を単調に上げる（探索窓も同形）。

🔴 **ただし `axis_sum` は A/B/C の間・D/E/F の間をほとんど分けていない**
（60.59 / 62.23 / 58.04）。**分けているのは境界 1.44 の一本だけ**で、
A↔B↔C の違いは `arare`＝配当の違いでしかない。
→ **「型Aは型Cより当たる」という前提で商品を設計してはいけない。**

## 1.3 🟢 型と商品は**逆向きに補償し合う**（設計の核心）

`docs/type_lab/race_split_2026_09_10.md` の実測:

| | A | B | C | D | E | F |
|---|--:|--:|--:|--:|--:|--:|
| 二軸そろい（**型**の力） | 72.5 | … | … | … | … | 40.1 |
| 変換効率 = 表示的中 ÷ 二軸そろい（**商品**の力） | 51.8 | … | … | … | … | 74.5 |
| 積 = 表示的中 | 37.6 | | | | | 24.2 |

🟢 **読みが弱い型ほど商品が点数で取り返している**（`A_hit` 3点 ↔ `F_hit` 12点）。
その結果 表示的中は 37.6〜24.2% に**圧縮される**。
🔴 **型ごとに商品を変えなければこの圧縮は起きない。** 全型を同じ買い方にすると
   型の分離がそのまま的中率の分離になり、型Fは売り物にならなくなる。
   ＝ **「読みに合わせて買い方を変える」は装飾ではなく、在庫を成立させている土台。**

## 1.4 境界 `AXIS_SUM_FIRM = 1.44` の位置づけ

🔴 **分離の最大点ではない**（分離は 1.58 まで単調に増える）。支持できるのは
**「堅い側が 55.6% になる均衡点＝6セル全部に在庫が残る位置」**という読みだけ。
⚠️ 境界を商品まで通して測ることは paper 台ではできない（型を動かすとレースが台から
   消えるので、件数の増減が効果に見える）。**商品として最適かは未回答。**

# 第2層 — 読みに応じた推奨方法（商品の定義）

正本は `src/type_lab.py::PLANS`（買い方の定義）と `sell_plans_for()`（どれを売るか）。

## 2.1 🔴🔴 商品は2種類あり、**KPI が違う**

これが本設計でいちばん誤解されやすい点。

| 種別 | 商品 | 仕事 | 見るべき KPI | 見てはいけない KPI |
|---|---|---|---|---|
| **当てにいく商品** | `A_hit` `A_trio` `B_hit` `C_hit` `D_hit` `E_hit` `F_hit` | 当てる | 表示的中・そろった時の的中率 | — |
| **一撃商品** | `A_ana` `F_sign` | **大きい払戻を出す** | 10万+/日・払戻中央 | **表示的中**（設計上 5%） |

実測（確認窓 2026・板 7車・入稿ゲート通過後）:

| | 件/日 | 表示的中 | 払戻中央 | 10万+/日 |
|---|--:|--:|--:|--:|
| 全商品 | 37.28 | **24.08%** | 26,230 | 0.231 |
| 当てにいく商品 | 31.66 | **27.46%** | 25,745 | 0.032 |
| 一撃商品 | 5.62 | **5.02%** | 143,780 | **0.199** |

🔴 **「全体の表示的中 24%」はどの商品の KPI でもない。** 27% の商品群と 5% の商品群を
17.5 : 82.5 で混ぜた**混合物**であって、24% を目標にした商品は1つも存在しない。
**日次の的中率を語るときは、必ずその日の商品構成を添えること。**

🟢 **10万+ の 86%（0.199/0.231）は一撃商品が作っている。** 当てにいく商品からは
ほとんど出ない（0.032件/日）。両者は同じ在庫を奪い合う関係にあり、
**片方を増やせばもう片方が減る**。

⚠️ 上表は板（7車・高額枠なし）。**高額枠（`{B,C,D}_sign` / `_big`・1日5本）を含めた
   役割別**は `docs/type_lab/daily_portfolio_2026_09_10.md` §5 に別台で測ってある
   （看板＋高額枠が 10万+ の 83%・全体 0.324件/日＝月9.7件、**71〜74% の日は 0件**）。
   高額枠は 4.40〜4.44本/日 で設計の5本に対し 68% の日が満杯＝設計どおりに機能している。
🔴 **日次表示的中が 24.9%→21.2% に下がるのは役割構成の算術**（検算一致）。
   同じ商品を出したまま日次の表示的中だけ上げる方法は無く、**上げれば 10万+ をそのまま失う。**

## 2.3 割り当ての規則（`sell_plans_for`）

優先順位つきで、返すのは常に1つ:

1. **看板枠**（他のどの分岐よりも先）: 型F × 7車 × `SIGNBOARD_RACE_TYPES`（決勝系・準決勝系）→ `F_sign`
2. **型A の3分割**（7車のみ）: `pw_ent >= 1.4076`（1着率が読めない上位10%）→ `A_ana` /
   三連複2点が入稿ゲートを通る → `A_trio` / 残り → `A_hit`
3. **型F**: 決勝系 → `F_pay` / 9車の非決勝 → `F_line` / それ以外 → `F_hit`
4. 残り（B/C/D/E）→ `{型}_hit`

🔴 **判定できないものは既定へ倒す**（`pw_ent` / `trio_ok` が `None` なら `A_hit`）。
「分からないこと」を理由に商品を変えない、という設計上の規律。

## 2.4 🔴🔴 「読み」を表現している道具と、「価格」を作っている道具は別

`docs/type_lab/band_and_gate_2026_09_10.md` が本番コードと既存 doc の**設計者自身の言葉**から
確定させた区別。**ここを混同したまま個別のノブを触るのが、設計が崩れる主因。**

| 道具 | 何をしているか | 根拠 |
|---|---|---|
| 型判定 `race_shape` | **読み** | 力関係でレースを分ける |
| 点数 `max_legs` | **読み** | 読みが弱いほど広げる（1.3 の補償） |
| **車**で切る除外 `bust_top` / `bust` | **読み** | 「軸1を1点でも買うと商品が矛盾する」とコードが明記 |
| **オッズ**で切る除外 `min_odds`（帯） | **価格** | `type_e.md` の採用根拠は「①平均想定が3〜5万帯（最も売れる帯）の中央 ②ガミ2%未満 ③30倍は既存定数」の3つで、**「荒れると読んだから」は1つも無い**。同 doc 自身が「型E固有の買い方ではない」「型Eを選ぶ根拠は成績ではなく在庫が薄いこと」と書いている |
| Σ床 `sigma_max`（B_hit 3万） | **価格** | 同上 |
| `axis2_drop_fav`（D_hit） | **価格** | 同上 |
| 入稿ゲート `MIN_MEAN_PAYOUT` | **価格** | 1件2万円という店頭方針 |

🔴 **算術的にも4つは同じ制約の言い換え。** ダッチ／床つき配分では

    平均想定払戻 >= T  ⟺  Σ(1/予測オッズ) <= 予算 / T

が恒等式。14点を T=20,000 に通すのに要る調和平均は 28倍で、**帯30倍はほぼその値そのもの**。
＝ **同じ1つの制約を4箇所で別々に表現している**ので、片方を触るともう片方が黙って動く。

🟢 本番自身が「帯は切りすぎ」と既に認めている（`C_hit` / `F_hit` の `underband_min`＝
   帯の下から本命1点を戻す機構）。

## 2.5 ユーザーの言葉との対応

> 固い場合は軸から点数を絞り

→ 型A `A_hit` **3点**（全型で最少）。堅いほど点数を絞る。
`B_hit` 8点上限 → `C_hit` 12点 → `E_hit` 14点 と、混戦になるほど広げる。

> 波乱と見る場合は軸上位を場合によって外す

→ `A_ana`（軸1を外した6車から5点）と `{型}_big`（軸1を含む目を全部外す）。
判定は `pw_ent`（1着率エントロピー）で、**型判定とは別の量**。

# 第3層 — どのレースを出すか（選別）

**買い目を作ることと、それを売ることは別の判断。** 4つのゲートが順に掛かる。
正本は `scripts/netkeirin_submit_type_lab.py` の入稿ループ と
`backend/src/services/keirin_type_lab_gate.py`。

| # | ゲート | 落とす理由 | 実運用の見送り（2026-09-01〜09・延べ/日） |
|---|---|---|--:|
| 1 | 並び未公開 `missing_lineup` | 印・ライン欠測。**欠測を最弱と読み違えるのを防ぐ** | 13.2 |
| 2 | 軸信頼ゲート `axis_gate` | `axis_sum` が **プラン内 p20 未満**（A/D/E/F_hit の4プランのみ） | 13.0 |
| 3 | 入稿ゲート `gate_mean_payout` | 平均想定払戻 <= 2万円 / 1点でも予測オッズ < 2.0倍 | 7.1 |
| 4 | 日次上限 `daily_cap` | 判定対象レース数 × **0.5**。決勝・準決勝・GIII以上・9車は枠外 | 17.4 |
| — | 締切後 `closed` | 波が回る前に発走 | 19.3 |

## 3.1 日次上限の順位づけ

`cap_priority(plan_key, axis_sum, rp_sd)` — **軸信頼だけでなく実力伯仲も混ぜる**
（`rp_sd` = 競走得点のレース内SD。`axis_sum` と相関 0.220 でほぼ独立）。
上限に当たった行は捨てる前に**高額枠**（`{型}_sign` / `{型}_big`・B/C/D のみ・1日5本）
へ差し替えられないか見る。

🔴 **半分は意図的に売り残している。** これが「狙うべきレースを選ぶ」の実体で、
高額枠はその**捨てている側**を使って既存商品を1件も減らさずに 10万+ を作る枠。

## 3.2 入稿ゲート 2万円は netkeirin の要件ではない

`src/stake_allocation.py::MIN_MEAN_PAYOUT = 20_000` は**こちらの選択**。
旧ランク商品での実測は「閾値なし 的中率40.6% ↔ 2万円 35.2%・**回収率は 72.7 → 71.7% で
ほぼ動かない**」。＝ **的中率と件数と投資額を売って、1件あたりの見栄えを買っている。**

🔴 **帯（`min_odds`）はこのゲートを通すための道具でもある。** `C_hit` の帯を下げると
在庫が消える（件/日 8.86 → 帯なし 1.40）。**帯を触るときは必ずゲートとセットで考える。**

## 3.3 🔴 ゲートに「確率」の第2軸を足すことはできない

`docs/type_lab/synth_odds_thin_2026_09_10.md`（2026-09-10 ユーザー提案
「合成オッズ2倍程度で的中率が低いレースは間引いた方が見た目上よさそう」の検証）。

**合成オッズ = 1/Σ(1/予測オッズ)。合成 2.0倍 ⟺ 入稿ゲート `MIN_MEAN_PAYOUT` ちょうど**
（`予算 × 合成 = 平均想定払戻`）。＝ **現行ゲートは価格だけの1次元条件。**

合成帯別（確認窓・入稿ゲート通過後）— **表示的中は単調減・ROI は平ら**:

| 合成 | 割合 | 表示的中 | 損益分岐に要る的中率 | 差 | ROI |
|---|--:|--:|--:|--:|--:|
| 2.0〜2.5 | 21.9% | **34.88%** | 44.4% | −9.5pt | 81.7 |

## 4.4 どの観点の問題かを見分ける手順

0. 🔴 **まず日次 z で「構成期待から何σか」を出す**（`docs/type_lab/daily_portfolio_2026_09_10.md` §6）。

       z = (実測的中数 − Σ p_i) / √(Σ p_i(1−p_i))     p_i は 2.2 の商品別 表示的中

   **|z| < 2 なら「読みどおりの日」**で、そこで買い方を触ると測っていないものを触ることになる。
   実測（2026-08-29〜09-09 の12日）は z 平均 +0.17 / SD 1.19 ＝ **構造なし**。
   落ち込んだ 09-02（11.63%）は z=−1.54、良かった 09-01（35.29%）は z=+1.61 で**対称**。
   **この2日を比べて何かが変わったと読んではいけない。**

   🟢 日次表示的中の分散は **①型構成 6〜8% ＋ ②1商品ごとの当たり外れ 77〜94%** でほぼ尽き、
      残差の過分散は両窓で符号が一致しない（探索 φ=1.012 / 確認 φ=1.160）。
      同一節から複数出したときの相関も両窓で符号反転。
      ＝ **日次の的中率そのものを目標にした介入は、効かせる先が存在しない。**

1. **その日の商品構成を出す**（一撃商品が何件混ざっているか）。
   構成の期待値と比べて残差が無ければ「読みどおりの日」であって異常ではない。
2. **2.2 の設計目標値と比べる**。商品ごとに比べる。全体で比べない。
3. **4.2 の2段に分ける**。
   - 軸2そろい率が目標より低い → **読み（モデル・型判定）の問題**
   - そろった時の的中率が目標より低い → **買い目（点数・帯・順序・相手）の問題**
4. 買い目の問題なら、外れの内訳でさらに絞る:
   - **順序違い** → 順序の選び方（λ/μ 隣接ボーナス・点数）
   - **相手外し** → 相手の選び方・点数
   - **軸崩壊** → ここは買い目では直らない。読みへ戻す

### 読み方

🟢 **直近9日は設計を下回っていない。** 当てにいく商品は 31.33%（設計 27.46%）で、
`A_trio`（n=12）以外はすべて設計以上か同等。**「直近だけ当たっていない」は成立しない。**

🔴 **体感が悪い理由は 2 つで、どちらも設計どおりの挙動**:

1. **一撃商品が 19.9%（板の 15.1% より多い）**。`F_sign` が 6.00件/日 出ており、
   これは表示的中 5% 台の商品。全体の数字を見ると必ず下がる。
2. **`E_hit` はそろった時ですら 26〜28% しか取れない**（他は 41〜58%）。
   帯 30倍+ で本命の並びを買わないため（`mark_order_2026_09_10.md` §2: ◎○△取りこぼし 79.1%）。
   ＝ 「印もあり近い目を多数買っているのに当たらない」の実体はここに最も濃く出る。

## 4.6b 順序（並び）— λ が「強さ」と「向き」を兼ねている

`docs/type_lab/line_order_2026_09_10.md`（2026-09-10 ユーザー依頼

- **券種ミックス（1商品内の分割）は商品仕様と両立しない。** 的中率は上がるがガミが 32〜57% になり
  表示的中が 24.08% → 17〜21% に落ちる（3,000円を2〜3倍に置いても1万円に届かないという算数）。

🟢 **どの券種でも、入稿ゲートを通ると払戻中央は 19,000〜29,000円（ゲート下限のすぐ上）に
   張り付き、表示的中は型A〜F を通じて 20〜30% の狭い帯に収束する。**
   ＝ **券種を下げると型の読みがゲートに吸収されて消える。**
   券種・点数・帯の使い分けが、力関係の読みを商品に残している唯一の手段。

⚠️ **私（親）の「2車券は予測オッズモデルが無いので検討できない」も誤りだった。**
   三連単板から `1/Σ(1/PO)` で導出でき（三連複が既にこの方式）、較正は本番の三連複と
   同等以上（的中側 logMAE ワイド 0.229 / 二車複 0.289 ↔ 三連複 0.294 / 三連単 0.401）。
   **券種を縛っているのはモデルではなく `MIN_POINT_ODDS = 2.0`＝店頭方針。**

# 第5層 — 設計の不変条件（触ってはいけない前提）

| # | 不変条件 | 破ると何が壊れるか |
|---|---|---|
| 1 | `sell_plans_for` は必ず 0 or 1 個を返す | 1レース1商品（netkeirin の口座制約）が壊れる |
| 2 | 型は排他 | 型ごとの商品は共食いではなく**棲み分け**。「置き換えると損」という計算が成立しなくなる |
| 3 | 一撃商品を的中率で測らない | `A_ana` / `F_sign` を「改善」すると 10万+ の 86% が消える |
| 4 | 判定できないものは既定へ倒す | 欠測を「最弱」と読む事故（2026-08-26 熊本の全7R） |
| 5 | 帯とゲートはセット | 帯だけ下げると在庫が消える（`C_hit` 8.86 → 1.48件/日）。**在庫を保てるのは対角線上だけ**（帯8倍+T15,000 で在庫8.79・表示的中 33.33→36.81%） |
| 5b | 帯・Σ床・`drop_fav`・ゲートは**同じ制約の言い換え** | 1つ触ると他が黙って動く（2.4 の恒等式） |
| 5c | 「読み」と「価格」を混同しない | 帯を「荒れると読んだから」と説明すると、③の失敗を④として直しにいく（4.3） |
| 6 | ROI で採否を決めない | ±2.5pt の判別に約15.6年。窓で符号が反転する案を掴む |
| 6b | 日次KPIを直接いじらない | 日次の振れは構成と1件ごとの運で尽きる。介入先が存在しない（4.3 の 0） |
| 6c | 件数を減らして日次を安定させない | 日次SD は √(p(1−p)/n)。**減らすほど日ごとの振れは必ず増える**（上限0.5→0.25 で 半減日 5.0→10.1%・10万+のある日 15.5→11.8%） |
| 10 | 型ごとに商品を変えることをやめない | 1.3 の補償が消え、型Fが売り物でなくなる |
| 7 | 件数を減らす案には無作為対照20seed | 件数減による CI 拡大を効果と誤読する（`race_filter_2026_08_27`） |
| 8 | 7車の分位を9車に当てない | 「上位10%」が絶対値切りになる（`ANA_PW_ENT_MIN` / `AXIS_GATE`） |
| 9 | 両窓で符号が一致しない案は採らない | 探索窓の上振れを掴む |
| 13 | ゲートに確率の軸を足さない | 合成で条件付けると τ の情報が消える（AUC 0.495）。**モデルEV は実収支の並べ替えとして情報ゼロ**（3.3） |
| 14 | 選別のノブを入稿ループ側に置かない | 日次上限が binding なので、間引いた枠を「いま捨てている側」が埋める。**件数は減らず代償だけ払う**（3.3） |
| 12 | 券種を下げて「当たりやすさ」を買わない | どの券種でもゲート通過後は払戻中央 19,000〜29,000円・表示的中 20〜30% に収束する。**券種を下げると型の読みがゲートに吸収されて消える**（4.7） |

# 第6層 — 変更の作法

新しい案を持ち込むときは、**次の3つを先に言う**:

1. **どの層を触るか**（読み / 商品の定義 / 選別 / 配分）
2. **どの商品の設計意図に対する変更か**（2.2 の表のどの行が動くか）
3. **何を売って何を買う取引か**（表示的中・払戻中央・10万+・件/日 のどれを失うか）

🔴 **「表示的中が +1pt 上がる」だけでは採否を決められない。**
その +1pt がどの商品から来ていて、代わりに何を失うのかが言えないなら、
それは設計を触っているのに層が特定できていないということ。
