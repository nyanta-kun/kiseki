## 0. 結論

🟢 **効果は残る。消えない。`apply_line_swap` とは重なっていない。**

知りたいのは **②−①（λr の純増分）**。τ適応は `C_hit` だけ・λr は `B_hit`/`F_hit` だけに
掛かるので、**①−⓪ は `B_hit`/`F_hit` で厳密に 0.00pt**（検算として取れている）。

帯の外へ移った点は **0 件**。ゲートで見送った並べ替えも **0 件**。

🟢 **`apply_line_swap` との重なりは無い**（§5）。差し替えを切った 2×2 で測っても
`B_hit`+`F_hit` の Δ は **+1.06 / +0.83** で、差し替え込みの **+1.14 / +0.78** と
**差は ±0.08pt＝誤差**。差し替えは λr の**発動率を半分に減らす**（`B_hit` 78.6→42.9%）が、
**残した分だけで同じ量を取る**。τ適応のときと同じ形の観測。

🟢 **効いているのは「並べ替えたこと」ではなく「λr の選び方」**（§6）。
同じレースで**同じ点数だけ**無作為に別の並びへ移す対照 20seed は、

🔴 **払う代償は払戻中央。** `B_hit` −6.9 / −7.4%・`F_hit` −3.6 / −0.8%・

🟡 **`F_hit` は `line_order_2026_09_10.md` §7 の +1.12 / +1.15 より小さい（+0.81 / +0.71）。

## 1. 先に読んだもの（CLAUDE.md「測る前に本番コードを読む」）

- `ORDER_SWAP_PLANS = {"B_hit", "F_hit"}`。`apply_order_swap` は
  **`build_with_gate_fallback._done` の中で `apply_line_swap` の直後**に掛かる。
- `LINE_SWAP_PLANS = {"B_hit", "C_hit", "E_hit", "F_hit"}` ＝ **`B_hit`/`F_hit` は両方に入る**。

  **λr と掛かるプランが1つも重ならない**ので、②−① は λr の純増分そのもの。
- プランの設定（実測）:

  | | `bet_type` | `min_odds` | `max_odds` | `max_legs` | `alloc` | `underband_min` |
  |---|---|--:|--:|--:|---|--:|
  | `B_hit` | trifecta | **0.0**（帯なし・`sigma_max=1/3`） | — | 8 | conf | 0 |
  | `F_hit` | trifecta | **5.0** | — | 12 | conf | 0 |

- `apply_order_swap` は **再配分に `order_probs`（λr 版）を使う**
  （`allocate(out, pred_odds, order_probs, plan)`）。`alloc="conf"` は確率を見るので、

- 🔴 `apply_order_swap` は**平均想定払戻しか見ていない**（全点2.0倍のゲートは見ない）。
  `B_hit` は `min_odds=0` なので理屈の上では2.0倍未満の並びへ移りうる。
  **実測では ①②で入稿ゲートの合否が食い違う行は 0 件**（§4）だが、

## 5. 🔴 本題 — `apply_line_swap` との重なり（2×2）

`LINE_SWAP_PLANS` を空にした腕③④を同じ台で回し、同じ母集団で差し引きした。

| `apply_line_swap` | **Δ表示的中 `B_hit`+`F_hit`**（確認 / 探索） |
|---|---|
| **OFF**（腕④−③） | **+1.06 [+0.42,+1.70] / +0.83 [+0.42,+1.24]** |
| **ON**（腕②−①） | **+1.14 [+0.61,+1.67] / +0.78 [+0.43,+1.11]** |
| | **差 +0.08 / −0.05pt** |

| `apply_line_swap` | ラインナップ全体 Δ（確認 / 探索） |
|---|---|
| OFF | +0.39 [+0.17,+0.63] / +0.32 [+0.16,+0.48] |
| ON | +0.42 [+0.22,+0.63] / +0.31 [+0.17,+0.45] |

🟢 **重なっていない。差は ±0.1pt 未満で、向きも窓で割れる＝誤差。**

### 🔴 ただし「重ならない理由」は τ適応のときと同じ形

差し替えを切ると **λr の発動率は倍になる**:

| プラン | 発動率 差し替えON → OFF（確認 / 探索） |
|---|---|
| `B_hit` | 42.9 → **78.6%** / 43.8 → **79.9%** |
| `F_hit` | 33.3 → 35.9% / 33.0 → 35.3% |
| 合計 | 36.2 → 48.6% / 36.1 → 47.9% |

＝ **差し替えは λr が直したい並びの半分を先に直している**（`B_hit` で顕著。
`LINE_SWAP_LEGS=(2,1)` は先頭×番手を1-2着に置く操作なので、当然ながら λr と狙いが重なる）。
**それでも残った分だけで同じ量を取る。** 前稿の τ適応（差し替え発動 58→26% で
効果は据え置き）と**同じ観測が独立に2回出た**ことになる。

### 差し替えが起きたレースだけで見ても消えない

⓪側で `apply_line_swap` が発動したかでレースを割り、その中で ②−① を測る:

| 窓 | `B_hit`+`F_hit` | n | ① → ② | Δ 95%CI |
|---|---|--:|---|---|
| 確認 | 差し替え **発動** | 1,407 | 29.57 → 31.27% | **+1.71 [+0.92,+2.56]** |
| 確認 | 差し替え 非発動 | 1,233 | 29.76 → 30.25% | +0.49 [−0.16,+1.22] |
| 探索 | 差し替え **発動** | 3,580 | 29.75 → 30.36% | **+0.61 [+0.06,+1.17]** |
| 探索 | 差し替え 非発動 | 3,329 | 29.11 → 30.07% | **+0.96 [+0.48,+1.44]** |

🔴 **発動 / 非発動のどちらが大きいかは窓で反転する**（確認は発動側・探索は非発動側）。
＝ **「差し替えが掛かったところでは λr が弱い」とは言えない。** 4つのセルはすべて
点推定が正で、両窓合わせて見れば差し替えの有無で傾きは変わらない。

## 6. 🟢 無作為対照 — 効いているのは λr の選び方

`apply_order_swap` の入口を捕まえ、**同じレースで実装が動かしたのとちょうど同じ点数 `d`** を
無作為な別の並びへ移す対照を 20 seed 作った（候補の制約も再配分もゲートも実装と同一。
`scripts/exp_type_lab/order_swap_control.py`）。

| 窓 | n | ①現行 | **②λr** | 無作為対照20seed 中央（範囲） | λr の勝ち | 対照が現行に勝った seed |
|---|--:|--:|--:|---|--:|--:|
| 確認 | 2,640 | 29.66% | **30.80%** | 28.18%（27.31〜28.79） | **20/20** | **0/20** |
| 探索 | 6,909 | 29.44% | **30.22%** | 28.30%（27.95〜28.64） | **20/20** | **0/20** |

🟢 **無作為に並べ替えると現行より 1.1〜1.5pt 悪くなる**（20seed すべてが現行を下回る）。
λr は対照中央より **+2.61 / +1.93pt** 上。**「並べ替えたこと」自体には価値が無く、
価値は全部「どの並びを選ぶか」にある。**

### 6.1 配分ではなく並べ替えが効いている

`apply_order_swap` は再配分に `order_probs` を使うので、並べ替えと配分が同時に動く。
同じ台で片方ずつに割った:

| 腕 | 確認 | 探索 |
|---|--:|--:|
| ①現行 | 29.66% | 29.44% |
| **配分だけ λr**（並びは元のまま・`allocate(legs_in, po, orp)`） | 29.66%（**+0.00**） | 29.50%（**+0.06**） |
| **並べ替えだけ**（配分は元の `probs`） | 30.80%（**+1.14**） | 30.22%（**+0.78**） |
| ②実装（両方） | 30.80% | 30.22% |

🟢 **効果は丸ごと並べ替え由来。** 再配分の寄与は 0.0〜0.1pt で、実装と分解の
「並べ替えだけ」が桁まで一致する（`alloc="conf"` は確率の**順位**をほぼ見ているため、
λr で確率を入れ替えても賭け金配分はほとんど変わらない）。

| 軸信頼ゲート **なし**（n=2,311 / 6,222） | **+0.91 / +0.79** | +1.83 / +1.13 |

＝ #565 の軸信頼ゲートが `F_hit` を 2,311 → 1,854 に絞った分で 0.1pt 弱。残りは
doc §7 の台（別スクリプト・`C_hit` の τ適応なし・型判定の分岐条件も当時のまま）との
組み方の差で、**符号も桁も変わっていない**。

### 残す申し送り

- 🔴 **`apply_order_swap` は全点2.0倍の入稿ゲートを見ていない。** 実測では
