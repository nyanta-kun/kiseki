## 2. 仮説

組番確率を「PL 板の確率」と「予測オッズの含意確率」の合成で作り直し、準決勝で重みを分ければ、
(1) 組番確率の対数損失が下がり、(2) 同じ商品構造のまま商品が当たりやすい目を選ぶようになり
**表示的中率が上がる**。(3) 1日の上限枠を較正後の当たりやすさの順に使えば、さらに上がる。

## 3. モデル（固定）

各レース（7車・210目）で

    q_k  = (1/PO_k) / Σ_j (1/PO_j)                    # 予測オッズの含意確率（レース内で和1）
    p_k  = rank_7t3_blend_probs(...)                  # 本番の PL 板（ライン加点込み）
    p*_k ∝ exp( a_g · log p_k + b_g · log q_k )       # レース内で和1に正規化

- `g` = 準決勝系（`RTYPE` に「準決勝」を含む＝準決勝・チャレンジ準決勝）/ それ以外
- 推定: 勝ち目の条件付きロジット（210 目のソフトマックス）の最尤。下限 `log` は 1e-9 で切る
- M0 = 本番の p（基準）/ M1 = `g` で分けない (a, b) / **M2 = `g` 別の (a, b)（本命）**
- 三連複の確率は p* を本番と同じ `_fold_to_trio` で畳む。並べ替え用の `order_probs` は**変えない**

## 6. 指標と判定（確認窓 2026 で）

指標: 表示的中率（払戻＞賭け金）/ 回収率 / 上位5レースの払戻を除いた回収率 /
4万+/日・10万+/日 / 件/日。差は `current` との**開催日単位の対応ブートストラップ**（2,000回・95%）。

前向き（paper）へ進める条件（すべて満たす）:

1. **較正**: 勝ち目の対数損失が M2 < M0 で、差の CI（レース単位ブートストラップ）が 0 を跨がない
2. **的中**: `C2P` の表示的中率 − `current` ≥ **+2.0pt** かつ CI 下限 > 0
3. **回収**: `C2P` の回収率（上位5除き）の点推定 ≥ `current` の同じ値、かつ回収率 ≥ 75%

どれかを満たさなければ不採用として記録する。C2P が落ちて C2 が満たす場合は C2 を候補にする
（優先順の寄与と較正の寄与を分けて書く）。係数・群分け・閾値の掃引はしない。
10万+/日 の減少は判定に入れないが必ず並べて書く（的中と高額は同じダイヤルの両端）。

### 7.3 なぜ上がらないか（事後の診断・判定には使わない）

**表示的中率は「計画払戻」でほぼ決まる。** 市場が効率的なら、1万円で計画払戻 X 円の買い方の的中は
約 0.75×1万÷X。台の current（`diag.py`）:

| プラン | 表示的中 | 0.75×1万/計画払戻 | 売った目の 実/Σp（PL） |
|---|---|---|---|
| F_hit | 31.4% | 32.7% | 0.99 |
| C_hit | 28.6% | 27.9% | 1.13 |
| A_trio | 32.7% | 33.5% | 0.88 |
| *_sign | 5.1〜6.0% | 4.9% | 0.63〜0.71 |

ライブ実売（9/16〜10/28・公開・7車）でも 実際の表示的中 ↔ 式: F_hit 34.8↔31.1 / C_hit 20.2↔19.5 /
B_hit 27.2↔24.6 / E_hit 24.9↔23.8 / A_trio 38.6↔33.6 / sign系 5.8↔4.8。**商品は市場の値付けどおりに当たっている。**
ライブで「見込みより当たらない」と見えたのは、**モデルの見込み（Σp）が楽観的**だからで（E_hit 32.6% など）、
商品が市場より下振れしているからではない。例外は **D_hit（14.6% ↔ 式 22.5%・n=96）** だけ。

- 台の *_hit が売った目は PL 板のままでも較正が合っている（0.97〜1.13）。ライブの 0.87 は台で再現しない
  （[[keirin-ac-hit-retarget-2026-10-24]] の「台は実売の見込み過大を再現しない」と同じ）
- 確率を市場寄りに直しても、同じ計画払戻の制約の中で選ぶ目が「市場が安く見ている目」へ寄るだけで、的中は動かない
- 回収の差（−2〜−6pt）はどれも CI が 0 を跨ぎ、雑音と区別できない。確率の差し替えは目の選び方だけでなく
  賭け金の傾け方（`allocate`）と入稿ゲートの通過（件/日 29.1→28.6・点数 6.5→5.8）も変えるので、原因は一つに絞れない。
  なお §7.1 の係数のとおり、予測オッズに対して PL 板が上乗せする情報はほぼ無い（監査 §3 の「1/8 の重み」は最終オッズに対する値）

### 7.4 結論

- 確率の合成・準決勝の条件分け・Σp* 順の優先推奨は、いずれも的中を上げない（市場効率の壁）。
- **的中率を上げる手段は計画払戻を下げることだけ**（[[keirin-upset-switch-2026-10-27]] の「表示的中と10万+ は同じダイヤル」と同じ）。
- **ライブで過大なのは `type_lab_picks.legs[].prob`（ライブ入力の Σp）の方で、的中そのものは市場どおり。**
  「昨日・今日は見込みより悪い」の見込みが楽観だった。較正済みの p*（予測オッズ由来の見込み）を
  **日々の見込みの表示・監視**に並べれば、この誤読はなくなる（商品の選び方は変えない）。
- 市場どおりを下回る唯一のプランは D_hit（ライブ 14.6% ↔ 式 22.5%・n=96・二項 p≈0.03）。
  D の下振れは 10/02・10/04 から既知（[[keirin-plan-calibration-2026-10-04]]）で、新しい発見ではない。
