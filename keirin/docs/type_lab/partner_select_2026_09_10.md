# 相手（3着候補）の選定は、型ごとに違ってよいのか（2026-09-10）

> **問いの立て方**（2026-09-10 ユーザー指摘を受けて再定義）
>
> 現行の予想ロジックは「レースの読み」に合わせた提案をする建て付けになっている。
> `race_shape()` が力関係（`axis_sum` / `arare` / ライン構成）でレースを **型 A〜F** に
> 分け、`sell_plans_for` が型ごとに商品を割り当てる——固い型は軸から**絞り**（`A_hit` 3点）、
> 崩れ筋・混戦は帯で**広げ**（`C_hit` 12点 / `E_hit` 14点 / `F_hit` 12点）、
> 波乱狙いは軸を**外し**（`A_ana` / `_big`）、看板は当てにいかない（`_sign`）。
>
> したがって本稿は「相手の選び方を1つ差し替えるべきか」ではなく
> **「型ごとに相手の選び方が違ってよいはずだ、という設計上の問い」** として測る。
> 3着が実際にどこから出ているかと、いまの型ごとの広げ方は整合しているか。

## 結論（先に）

**答え: 「型ごとに相手の選び方が違ってよいはずだ」は実測に支持される。
ただし現行は全型を1つの規則（確率降順）で処理しており、型ごとにプラスとマイナスが
相殺して、全体KPI では何も動かない。**

| # | 現行設計のどの前提か | 実測はどう読めるか |
|---|---|---|
| 1 | **型で広げ方を変える**（固い型は絞る・荒れる型は広げる） | 🟢 **支持。** 軸2車がそろった回の3着車の散らばりは A→F で**単調に広がる**（相手上位3車で覆える率 A 88.3% → F 80.2%・両窓一致） |

| 3 | 相手は**全型とも同じ確率順**で選ぶ（`prob_top`／`axis2_flow`／`axis2_drop_fav`） | 🔴 **不整合。** 相手を当てる情報は型で別物で、**荒れる型ほどモデルの確率順が市場・ラインに負ける**（市場−モデルの top1 差: A +2.4/+0.7pt ↔ **E +5.7/+8.9** ↔ F +5.0/+5.0）。§5 でも同じ操作が **`F_hit` で両窓プラス（+1.19/+0.82pt）・`B_hit`/`C_hit` で両窓マイナス**と**型で逆を向く** |

| 5 | `D_hit` は最人気の相手を落とす／`A_ana`・`_sign` は軸を買わない | 🟢 **設計どおりの代償。** 相手カバー率 `D_hit` 57.5%・`A_ana` 0%・`F_sign` 40.0% は**失敗ではない**（`type_d.md` の「相手外し 18.65% は設計どおり」と同じ読み） |
| 6 | `A_trio` は相手2車を p3 順で決め打ち | 🟡 **この商品だけ伸びしろが残る。** ライン優先の相手選定が **両窓 +2.3 / +2.4pt**（確率も市場も一切見ない唯一の実装だから）。ただし n=331 と薄い |

🔴 **全体KPI（件/日 42.03・表示的中 26.94%・ROI 81.3）は、11腕すべてで
両窓 CI が 0 を跨ぐか符号が反転する。** 相手選定を**全型共通のノブ**として
動かしてはいけない、というのが本稿のいちばん確かな結果。

## 1. 台と作法

板 `/tmp/race_type_board.npz`（vintage walk-forward の 7車 36,427R）。
窓は **探索 2024-07〜2025-12 / 確認 2026-01〜08**（予測オッズ `odds_tf_n7` の
train_end が 2025-12-31 なので**確認窓が本番相当**・探索窓は in-sample）。

- 買い目は本番の `build_legs` / `allocate` / `apply_line_swap` / `GATE_FALLBACK` を通す。
  選抜用の確率と配分用の確率を分けるために制御フローを写した `_build` を使うが、
  **`prb_sel is prb` のとき `build_with_gate_fallback` と1レースも食い違わないことを
  実行ごとに突き合わせている**（本稿の全実行で不一致 0 件）。
- ゲートは3段: 軸信頼（`AXIS_GATE_MIN`）→ 組む → 入稿ゲート（平均想定払戻 > 20,000円・
  全点の予測オッズ >= 2.0倍）。**通してから比べる。**
- ROI では採否を決めない。判断指標は 件/日・表示的中（ガミ除く）・払戻中央・10万+/日。
- 🔴 **商品の失敗はフラットな表示的中では測らない。** その商品の仕事
  （当てにいく `_hit` / 配当を取りにいく `_pay`・`_ana` / 看板 `_sign`）に照らして読む。

### 🔴 台の罠（本稿で実際に踏んだ・他のスクリプトも要確認）

`race_shape()` は `str(line_pos.get(c)) == "1"` で先頭・番手を探し、`_lines_of()` は
`int(str(v))` で隊列順に並べる。**板の `A_line_pos` は float32** なので、そのまま渡すと
`"1.0" != "1"` / `int("1.0")` → ValueError となり:

- `lead` / `second` が**永久に None** → `arare` が「先頭の遅れ率」「追込」「番手の得点」の
  3項を落とし、**型ラベルが板の `TYPE` とずれる**。切り分けの実測（確認窓の先頭3,000R）:
  **型ラベル不一致 1,247件（41.6%）・予測オッズ不足 0件**＝脱落は全部これ。
  修正で台の母集団は 確認窓 48% → **87%**（件/日 22.93 → 42.03・既存 doc の実測と同水準）へ戻った
- `shape.lines` が**隊列順ではなく車番順**になり、`line_legs` の「先頭×番手だけ
  入れ替えた並びを優先する」設計が壊れる

⚠️ **`rank_7t3_blend_probs` の `_line_next` は `int(pb)` なので float でも正しく動く。**
＝ **確率は正しいのに型とラインだけが静かにずれる。例外もログも出ない。**

⚠️ 既存の `typef_racetype.ctx` / `miss_anatomy_build.py` は `RaceShape` を直接組み立てて
`lines=()` のままにしているので、**あの台には `apply_line_swap` が一度も掛かっていない**
（本番との差。数字を再利用するときは注意）。

## 5. 商品KPI に現れるか — 型ごとに**逆を向く**ので、一律に当てると消える

ラインナップ全体を本番の関数で組み直し、相手選定だけを替えた腕を測る。
**組めない／ゲートに落ちた腕は現行へ落とすので件/日は1件も動かない**（42.03 で全腕同じ）。

腕:

| 腕 | 何を替えるか |
|---|---|
| `trio_mkt` / `trio_line` | 三連複2プラン（`A_trio` は `shape.order[2:]` の並べ替え・`D_hit` は選抜確率）を市場順／同ライン優先へ |
| `set_w25` / `set_w50` / `set_mkt` | `prob_top` の選抜確率を **「集合はモデル順位と市場順位の加重平均・並びはモデルの構成比」** へ（順序の情報は一切変えない） |
| `fill3〜5_p3` / `fill3〜4_mkt` | 相手を上位 m 車まで**必ず1点持つ**ように先頭へ差し込み、末尾を落とす（点数据え置き） |

### 全体（`base` = 現行）

## 7. 限界

⚠️ **確認窓は既に何度も使っている。** 本稿の per-plan の符号一致も、
   多重比較（11腕 × 7商品 × 2窓）の中から拾った形になっている。
⚠️ **測ったのは既存の入力（p3 / pw / 予測オッズ / 印 / ライン / 脚質 / 競走得点）を
   並べ替える腕だけ。** `miss_anatomy_2026_09_10.md` §8 と同じ射程で、
   **新しい入力**や**まだ試していない条件でのレース選別**は対象外。
⚠️ **`A_trio` は n=331（確認窓）と薄い。** +2.4pt は 8件ぶんの差でしかない。
⚠️ **§3 の「市場」は予測オッズ（`odds_tf_n7`）。探索窓は in-sample** なので、
   市場が勝つ量は探索窓で過大に出る（`A_trio` の +10.2 ↔ +6.1 がその典型）。
⚠️ 9車・高額枠（`_big`）は対象外。7車の本線プランのみ。
⚠️ 型の分布そのもの（`race_shape` の `axis_sum` / `arare` の作り）は本稿では一切触れていない。
