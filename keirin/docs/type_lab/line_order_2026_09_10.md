# ライン構造で「順序」を当て直せるか（2026-09-10）

> 発端（ユーザー・2026-09-10）:
>
> > 昨日今日と外れているレースは、レースとしての**波乱度の読みは正しいか**？
> > また正しい場合、**なぜ外れているか**？
> > **当てるために点数を増やすのではなく、外れている買い目を減らして当てる必要がある。**
> > **ライン内の順番、ライン毎の総得点、ライン先頭・番手の複勝率**などの組み合わせによる
> > 傾向が掴めないか検証してほしい。
>
> 親の実測（09-09/09-10 の実入稿・7車）で、**軸崩壊が設計より 14.9pt 少なく、
> その分がまるごと「順序違い」へ流れている**（22.7% → 33.8%）ことが分かっている。
> ＝ 前提（軸2車がそろう）は揃っているのに並びで落としている。本稿はその「並び」だけを扱う。

## 0. 結論（一行）

🟢 **減らせる。ただし打ち手は「新しいライン情報」ではなく、既にあるライン隣接ボーナス
λ が"向き"を一方向にしか掛けていない歪みの是正で、ユーザーが挙げた3量
（ライン内の順番・ライン毎の総得点・先頭/番手の複勝率）は、**
**そのうち「ライン内の順番」だけが効き、残り2つは足すと必ず効果が減る。**

**帯を守り一撃商品を除いて適用したときの取引条件（全商品KPI・両窓）**:

## 5. 🔴🔴 本命の発見 — λ は**2方向に**ずれている（`line_order_calib.py`）

同じ確率分布から、2つの量を別々に較正した:

| | | モデル | ボーナス無し | 実測 | ずれ |
|---|---|--:|--:|--:|--:|
| **①隣接そのもの** | P(1-2着が同ライン) 探索 | 43.19% | 34.79% | **57.60%** | **−14.41pt（過小）** |
| | 同 確認 | 42.99% | 34.54% | **56.33%** | **−13.34pt（過小）** |
| **②向き** | P(隊列順 \| 同ライン) 探索 | 75.30% | — | **63.38%** | **+11.92pt（過大）** |
| | 同 確認 | 75.21% | — | **63.76%** | **+11.45pt（過大）** |

先頭×番手のペアに限った頭対頭（そのペアが1-2着を占めたレース）:

| 窓 | n | モデルの含意 P(先頭が先着) | 実測 | 過大 |
|---|--:|--:|--:|--:|
| 探索 | 12,458 | **74.15%** | 60.36% | **+13.79pt** |
| 確認 | 4,961 | **74.14%** | 61.50% | **+12.64pt** |

🟢 **両窓で数字がほぼ同一**（74.15 ↔ 74.14）＝ 偶然ではない。

🔴🔴 **λ という1つのノブが2つの仕事を兼ねているのが歪みの正体。**
λ を上げると①は直るが②はもっと過大になる。λ を下げると②は直るが①が悪化する。
**②を直すには「逆向きの係数 λr」という第2のノブが要る。**

**較正から出る λr**: 現行の係数比 λ/λr = 2.0 が implied 75.3% を作っている。
実測 63.4% に合わせるには係数比を **1.14** にすればよく、
**λr ≈ 2.0 / 1.14 ≈ 1.76**。後述の掃引で最良だった **1.9** とほぼ一致する。

⚠️ ①（隣接が過小）を直すのは**買い目の選択そのもの**を変える操作で、本稿の
「同じ点数の中で並びを入れ替える」の外にある（6章で測ったが件数を 7〜8% 失う）。
**②（向き）は組合せを変えずに直せる**——それが 7章。

| \|Δ`axis_sum`\| が 0.001 以内 | **7 / 134** | ❌ |
| \|Δ`pw_ent`\| 中央 | 0.0010（最大 0.0127） | 中央は丸め相当・最大は超過 |

🔴 **`wt_entries.pred_top3_pct` は生成時の値ではない。**

日別に割っても同じ（09-09 中央 0.0123 / 09-10 中央 0.0148）。
🔴 **09-10 18:12 生成の行でも一致しない**ので、
「本日 14:15 / 15:04 の `lgbm_wt_eval` / `lgbm_wt_win` 再学習で上書きされた」だけでは説明できない。
本番の生成経路（`build_type_lab_picks.run_live` → `predict_p3_pw(day, "lgbm_wt_eval", "lgbm_wt_win")`）は
**実行時にその場で予測する**一方、`wt_entries.pred_*_pct` を書くのは
`backfill_index_pct_wt.py`（**月次凍結 vintage モデル `lgbm_wt_eval_mYYMM`**）で、
**そもそも別のモデルの出力**。＝ **この列は最初から生成時の値ではない。**

### 1.2 予測オッズも復元できない

`odds_tf_n7.txt`（2026-08-12・以後変更なし）はモデルとしては当時と同一だが、
`predict_board(cars, p3, pw, meta)` の入力に **p3 / pw が要る**。
1.1 のとおりそれが復元できないので、**盤面 210点の予測オッズも復元できない。**
焼き付いているのは**買った点の `pred_odds` だけ**で、
**入れ替え先（買っていない並び）の予測オッズは手元に無い。**

⚠️ `type_lab_picks.win_tf_odds` は**確定**三連単オッズ（`wt_odds` 由来・`settle_type_lab_picks.py`）で、
予測オッズではない。帯（`plan.min_odds`）の判定には使えない。

### 1.3 🟢 ライン情報は壊れていない

`line_group` / `line_pos` は並び予想のスクレイプで、モデル出力ではない。
傍証として、入稿ぶんの買い目に **「1着→2着も2着→3着も同ライン隣接」の点が 49点**残っている
（`apply_line_swap` が入れる同一ライン3車の形）。
ライン情報が入れ替わっていればこの形はほぼ 0 になるので、**当時のままとみなす**。
＝ **追補-3 の構造的な判定はライン情報だけに依存するので成立する。**

### 1.4 したがってやったこと

**λr 版の買い目を組み直して表示的中を出すことは、この2日については断念した。**
無理に `pred_*_pct` で組み直すと「**当時と違うモデルの目で裁いた数字**」になり、
それは現行版のベースラインすら再現しない（1.1 のとおり `p3_order` が 46R でずれる＝
**型判定も商品選択も変わってしまう**）。

代わりに、**モデルに一切依存しない包絡**を出す（追補-3）。

## 追補-3. 🟢 λr が触りうる範囲（モデル非依存の包絡）

## 追補-4. この規模で何が言えるか

板（7車 25,296商品・両窓）で実測した**1商品あたりの発生率**をこの母集団に当てる:

| | 探索窓の実測率 | 確認窓の実測率 | 67商品での期待件数 |
|---|--:|--:|--:|
| 救済 | 202/15,117 = **1.34%** | 79/6,099 = **1.30%** | **0.87〜0.90 件** |
| 破壊 | 121/15,117 = **0.80%** | 43/6,099 = **0.70%** | **0.47〜0.54 件** |
| **純** | +0.54pt | +0.59pt | **+0.36〜+0.40 件** |

🔴🔴 **期待される差は 1 レースに満たない。** n=67 では 1件 = 表示的中 1.49pt なので、
**この2日の数字が動くかどうかは、ほぼコイン投げ 1回で決まる。**
両窓の +0.62 / +0.70pt（当てにいく商品）を「2日で確認する」ことは原理的にできない。

🟢 **したがって本追補は事例報告であって、効果の証拠でも反証でもない。**
包絡（救済 ≤6 / 破壊 ≤15）は「上限として何件が対象になりうるか」を示すだけで、
**実際に何件動いたかは復元できない。**

### 4.1 この2日について、包絡から言えること

- 🟢 **②順序違いが設計より多い**（40.3% ↔ 設計 22.7%）のは実入稿でも再現した。
- 🔴 **その多さの主因は λr が触れる層ではない**（78% が別ライン決着・隊列順決着）。
- 🔴 **救済候補6件のうち少なくとも3件は帯の下**（確定 2.4 / 6.7 / 11.4倍）で、
  帯順守版では届かない見込み。＝ **これらは DESIGN 4.3 の ③帯下決着＝型判定の失敗**であり、
  順序の直しではなく**型判定で扱うべき層**。
- 🟢 **09-10 の 13.04% が悪いのは、λr で説明できる幅を大きく超えている。**
  同日は ③相手/軸外し が 43.5%（09-09 は 27.3%）で、
  **外れの主因が「順序」ではなく「そもそも組合せが違う」側**に寄っている。

## 追補-6. 🔴 設計側への申し送り

**この2日を再現できなかったこと自体が、DESIGN 4.3 末尾の
「5分類を毎日焼き付ける」の必要性を裏づけている。**

いま `type_lab_picks` に焼き付いているのは
`axis_sum` / `p3_order` / `pw_ent` / `legs[].prob` / `legs[].pred_odds`（**買った点だけ**）で、
**買わなかった点の確率と予測オッズが無い**。そのため

- 「別の並びを買っていたらどうだったか」を後から測れない
- ベースラインの再現すらできない（`p3_order` が 46/134R でずれる＝型判定から違ってしまう）

🔴 **`p3` / `pw` の 7 値をレース単位で焼き付けておけば、
確率も予測オッズ盤面も後から完全に再現できる**（`odds_tf_n7` は固定なので）。
14 個の数値で、今回のような事後検証がすべて可能になる。
