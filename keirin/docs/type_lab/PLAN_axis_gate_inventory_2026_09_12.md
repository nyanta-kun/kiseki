## 1. 立案の根拠（確認窓を消費した数字・再測が要る）

母集団は **軸信頼ゲート（`passes_axis_gate`）で落ちて今は売っていない 12.72件/日**。
ここは「1着が◎○以外」が 37.4%（全体 31〜33%）と**波乱寄りに偏った在庫**。

`bust`（軸1を含む目を1点も買わず、残り120通りから確率上位を選び直す＝既存 `{型}_big` と同型）:

| | 件/日 | 表示的中 | 10万+/日 | 30万+/日 | ROI | 投資/日 |
|---|--:|--:|--:|--:|--:|--:|
| 現行 | 33.02 | 27.70% | 0.213 | 0.023 | 84.6 | 330,231 |
| **`bust@150000` を純増** | 45.75 | **21.75%** | **0.708** | 0.051 | **84.2** | 457,454 |
| （参考）`bust@400000` | 45.75 | 20.57% | 0.477 | **0.162** | 81.1 | 同 |

### 🟢 交換レートが既存機構より良い（これが採用検討の理由）

`ceiling_and_instrumentation_2026_09_11.md` の実測では、既存3機構
（`A_ana`/`F_pay`・`F_sign`・高額枠）はすべて **10万+/日 ≒ 0.030 × 譲った表示的中pt** の
1本の直線に乗る。本案は

    Δ10万+ 0.495 ÷ Δ表示的中 5.95pt = 0.083 /pt  ＝ 既存の約 2.8倍

🔴 **なぜ良いのか（仮説・要検証）**: 既存3機構は**同じ在庫の中で**的中と払戻を交換している。
本案は**今まったく売っていないレース**を使うので、既存商品の的中率は1つも下がらず、
下がるのは**混ぜた後の平均だけ**（算術）。
→ **この「既存商品は無傷・平均だけ下がる」が本当かを §3 で必ず検算する。**

## 2. 🔴 最初に決めること

### 2.1 ✅ 枠の本数 = **10本/日**（ユーザー判断・2026-09-12）

現在 `HIGHPAY_SLOTS_PER_DAY = 5`（実測 4.40〜4.44本/日＝68%の日が満杯）を **10本**へ。
想定 10万+/日 は **約0.60**（全量 12.7本なら 0.708）。
前向きの判定は成立する: **30日で期待 18件 ↔ 現行 6.4件**（Poisson・SE≈4.2）。

🔴 **表示的中の代償も比例する**（全量で −5.95pt なので 10本なら概算 −4.7pt）。
実測は §3 の腕③で出すこと（概算を結論に使わない）。

### 2.1b 🔴🔴 実装は「定数を上げるだけ」では足りない（2026-09-12 コード確認）

`scripts/netkeirin_submit_type_lab.py` の入稿ループを読んだ結果、**現在の高額枠の供給源は
「日次上限で捨てた行」だけ**で、そこへ到達する行は**軸信頼ゲートを既に通過している**
（コード内コメント「ここへ来た行は他のゲートを全部通っている——並びも印もある・締切前・
**軸信頼も通過**」）。

→ **軸ゲートで落ちた行は、いまの高額枠の候補に一度も入っていない。** 必要な変更は3つ:

| # | 変更 | 理由 |
|---|---|---|
| 1 | `HIGHPAY_SLOTS_PER_DAY` 5 → **10** | ユーザー判断 |
| 2 | **軸ゲート落ちを高額枠の供給源に足す** | 現在は `skip()` して `continue` するだけ |
| 3 | `HIGHPAY_TYPES = ("B","C","D")` の制限 | ✅ **実測で確定（2026-09-12）**: 低信頼層の **43〜70% が型F** で、`{型}_big` は B/C/D 限定なので **13〜34% しか届かない**。＝ **型F を足さないと在庫の大半が使えない**（`low_confidence_axis_products_2026_09_12.md` §4） |

⚠️ 2 を足す位置は**軸ゲートの棄却点**（`rj` が `axis_gate` のとき）。そこで高額枠へ回すと
`submission_skips` の見送り件数が減るので、**ログと画面の読み方が変わる**ことを申し送る。

### 2.1c 旧・枠の本数の選択肢（判断済み・記録として残す）

高額枠は現在 `HIGHPAY_SLOTS_PER_DAY = 5`・実測 4.40〜4.44本/日＝**68% の日が満杯**
（`daily_portfolio_2026_09_10.md`）。本案は 12.7件/日 なので、

| 案 | 1日の本数 | 想定 10万+/日 |
|---|--:|--:|
| (i) 既存枠のまま5本に押し込む | 5 | 0.213 + 約0.20 |
| (ii) 枠を10本へ | 10 | 約0.60 |
| (iii) 枠を設けず全量（12.7本） | 12.7 | 0.708 |

🔴 **(iii) は店頭の表示的中を 27.70 → 21.75% に下げる。** (i)(ii) は下げ幅が小さいが
10万+ の増分も比例して小さい。**先にどこまで表示的中を譲れるかを決めること。**

### 2.2 純増か置換か

本案の母集団は**いま1商品も出していないレース**なので、原理的に**純増**（既存商品を1件も
減らさない）。⚠️ ただし 🔴 **日次上限（`判定対象 × 0.5`）の分母を動かさないこと**を確認する。
`synth_odds_thin_2026_09_10.md` の「実装場所で結論が変わる — 日次上限は binding」と同型の罠。

### 2.3 `A_ana` との関係

`A_ana` は **型A × `pw_ent` 上位10%** だけに掛かる。本案は同じ `bust` 構造を
**軸ゲート落ち全体**へ広げるので、**`A_ana` の射程拡大**という位置づけになりうる。
→ 🔴 **同一レースで `A_ana` と重ならないこと**（1レース1商品）を実装前に確認する。

## 8. 追記（2026-09-12 夕・軸の案の検証から確定したこと）

`axis_swap_by_confidence_2026_09_12.md` / `low_confidence_axis_products_2026_09_12.md` の実測で、
本計画に直接効く3点が確定した。

### 8.1 ✅ 使う層は `pw_gap12` 下位25%（または `axis_sum` 下位25%）

計画払戻 T=150,000 の3者対決で **両窓とも CI が 0 を跨がないのは `bust` の2セルだけ**:

| 層 | Δ表示的中（探索 / 確認） |
|---|---|
| `axis_sum` 下位25% | **+1.44 [+0.70,+2.18] / +1.44 [+0.22,+2.70]** |
| `pw_gap12` 下位25% | **+1.08 [+0.29,+1.89] / +1.44 [+0.04,+2.88]** |

🟢 **一撃の本来KPI（10万+/日）で無作為対照に勝つのは `bust` × `pw_gap12` 下位25% だけ**
（探索 19/20・確認 20/20）。他の層・他の腕は 0〜7/20 で負ける。
→ **層は `pw_gap12` 下位25% を第一候補に据える。**

🟢 `p3_gap12`（軸1と軸2の**3着内率**の差）は `axis_sum` と Spearman **−0.023**＝**本当に別の層**
（Jaccard 0.171）。一方 `pw_gap12` / `pw_max` / `pw_ent` は互いに 0.65〜0.85 で `axis_sum` の
言い換えに近い。**層を2つ以上足すなら `p3_gap12` を見ること。**

### 8.2 🔴 `A_ana` とは重ならない（射程拡大ではなく新規）

型A は定義上 `axis_sum >= 1.4401` なので、**低信頼層と `A_ana` の重なりは構造上 0**。
＝ §2.3 に書いた「`A_ana` の射程拡大」という位置づけは**誤り**。本案は新しい在庫。

### 8.3 🔴🔴 ROI の改善を根拠にしてはいけない（裾依存）

低信頼層で `bust` が見せる **ROI +10〜+15pt（両窓 CI 0跨がず）は裾依存**で、
**払戻に10万円の上限を掛けると +0.2 / +0.5pt に消える**（上位1%の的中が払戻の 27〜32%）。
＝ edge ではなく一撃商品の性質そのもの。**§4 の「ROI で採否を決めない」を厳守すること。**

### 8.4 実装の最短形（更新）

低信頼層（`pw_gap12 <= 0.1188` または `axis_sum <= 1.3533`）へ
**`signboard` + `bust` + `target=150,000`** の枠を **`highpay_plan_for` 側に1つ**足す
＝ 実質「**型F にも `_big` 相当を用意する**」。見込みは **表示的中 −4.1pt で 10万+/日 2倍**。

## 10. ✅ 実測の結果（制約込み・2026-09-12）

| 変更 | Δ10万+/日（探索 / 確認） | 判定 |
|---|---|---|
| ① 定数 5→10 **だけ** | +0.000〜+0.029 / +0.000〜+0.028 | 🔴 **実質ゼロ** |
| ② 軸ゲート落ちを供給源に**だけ**（5本） | +0.032〜+0.091 / +0.000〜+0.106 | 🔴 枠が無い |
| **①+②（`HIGHPAY_TYPES` は B/C/D のまま・10本）** | **+0.195〜+0.226 / +0.125〜+0.204** | 🟢 **全λ・両窓で CI 0 跨がず** |
| ③ `HIGHPAY_TYPES` に型F／全6型を足す | +0.004〜+0.069 / +0.009〜+0.074 | 🔴 **12セル中8つで CI 0 跨ぎ＝不要** |
| ② を層（`pw_gap12` 下位25%）に限る | 10万+ が**減る**（0.426 ↔ 層なし 0.537） | 🔴 不要 |

**機序（1行）**: **B/C/D の「日次上限落ち」は 1日 4.1〜5.7本で飽和**しており現行5枠を既に埋めている
（本番実測も 4.67本/日＝充填 93%）。**枠を10本にしても玉が無い。玉を増やす唯一の手が軸ゲート落ち 12.8本/日。**

- 代償: 全体の表示的中 **−3.3〜−3.8pt**（計画の見込み −4.1pt より小さい）
- 🟢 **既存商品は1件も減らない**（通常 17.088 / 枠外 8.542 が全腕で完全一致＝純増を検算済み）
- 台の検算: §1 の「45.75件・21.75%・0.708・0.051・84.2」→ **45.82・21.71%・0.708・0.051・84.1** で再現
- ⚠️ 台は**上限落ちの本数だけ本番の約半分**（並び未公開を再現できない）→ 分母に λ を掛けて較正
  （λ=0.30〜0.35 で本番一致）。**結論は λ=0.25〜0.50 の全域で不変。**

### 🔴 計画の前提2つを実測が訂正した

1. **§2.1b「低信頼層の 43〜70% が型F」は本案の在庫には当てはまらない。**
   軸ゲート落ちの在庫は **B/C/D が 51.3%・型F は 22.5%**。43〜70% は
   `pw_gap12` 下位25% で定義した**別の母集団**の数字だった。→ `HIGHPAY_TYPES` は触らない。
