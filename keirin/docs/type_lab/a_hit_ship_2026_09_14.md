# `A_hit` の位置の段 — 出荷可否（2026-09-14）

> `line_inner_2026_09_14.md` の採用候補（Δ表示的中 +1.01/+1.40pt）には限界が2つあった。
> **① 段の強さの選択に確認窓を見ている ② 台が本番の `build_with_gate_fallback` を
> 通っていない**。その2つを潰した結果の記録。
>
> 再現: `PYTHONPATH=. .venv/bin/python scripts/exp_type_lab/a_hit_ship.py build|select|confirm "<段>"`

## 0. 結論

🔴 **出荷しない。** 理由は「効かない」ではなく **「効きの大きさを事前に決められない」**:

1. **事前登録した選択規則（探索窓で Δ 最大）が選ぶ段は、確認窓で落ちる**
   （強 2.0/1.2/1.0/0.4: 探索 +1.83 [+0.87,+2.84] → 確認 **+0.37 [−0.99,+1.85]**）
2. **両窓を通るのは「中」だけだが、その選択自体が確認窓を見て決めたもの**（post-hoc）
3. **無害な部分（罰のみ）は確認窓で効果ゼロ**（買い目が1レースも変わらない）
4. 通る腕でも件数を **16.4%** 失い、`A_hit` はラインナップの約14%なので
   **全体へは +0.1pt 程度**

🟢 **位置の情報そのものは本物**（`line_conditional_summary_2026_09_14` §3・6型すべてで
相手被覆 +5.0pt）。否定しているのは「いま `A_hit` の確率へ段として載せる」形だけ。

## 1. 🔴 踏んだバグ — `build_with_gate_fallback` はゲートを判定しない

```
# どれもゲートに落ちるなら、元の結果をそのまま返す（見送りの判断は入稿側）
return _done(got, plan) if got else None
```

呼ぶ側で `mean_expected_payout > 20,000 ∧ min(予測オッズ) >= 2.0` を掛け忘れると:

- `A_trio` が**常に組めたこと**になる
- `_plan_for` が `"A_trio" if trio_ok else "A_hit"` なので **`A_hit` を一度も返さない**
- 台が **0行**になる（2026-09-14 に実際に踏んだ）

**本番関数を使うときは、その関数が何を判定して何を判定しないかを読むこと。**

## 2. 台の違い — 本番経路にすると土台が上がり、効果が縮む

| 台 | 探索窓 `A_hit` の表示的中 |
|---|--:|
| `rows.pkl`（`build_legs`+`allocate` のみ） | 31.80% |
| **本番経路（`build_with_gate_fallback`）** | **34.55%** |

差は λr の並べ替え（`apply_order_swap`）・押さえ目（`apply_osae`）・
配分フォールバック（`ALLOC_BEFORE_MIN_PAYOUT`）。
＝ **これらが位置の段と同じ方向の改善を既に取っている。**
⚠️ `rows.pkl` は `allocate` が None を返した行が丸ごと落ちている（hit系の 8.3〜8.5%）。

## 4. 出すなら

段「中」を `A_hit` のみに入れ、**前向き記録で確認する**（`low_confidence_axis_products` §8
と同じ扱い＝単独では踏み切らない）。期待値は `A_hit` で +0.9pt・全体で +0.1pt 程度、
代償は `A_hit` の件数 −16%。ROI は両窓とも上がる（+1.4 / +2.3pt）が
**ROI で採否を決めない**（不変条件）。
