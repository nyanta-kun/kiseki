# 帯（`min_odds`）と点数を、レースごとに条件付きで同時に逆向きへ動かす（2026-09-10・ユーザー依頼）

> 発端（ユーザーの生の言葉）:
>
> > `C_hit` で狙っているレースが、**二軸が堅く波乱もあまり想定されない**のであれば、
> > **人気でも中心の買い目に厚く張り、購入点数を減らす**必要があるように思う。
> > `E_hit` の狙うレンジにより**高オッズ想定のレースか否かで、どのオッズ帯を対象に、
> > 点数を減らして厚くか、少し増やして広くか**の戦略だと思う。
>
> 再現: `scripts/exp_type_lab/band_by_race_build.py` → `band_by_race.py A|B|C|D|E|F|G|H|I`

## 0. 結論

🟢 **設計の向きは正しい。ただし「条件量」は新しく作る必要がなく、既にある入稿ゲート

型E の τ適応（帯0・T=2万）が選ぶ平均点数は `sig14` の3群で

## 3. A — 条件量: 「決着がどの配当帯に落ちるか」は朝に読めるか

帯は**予測オッズ**で切るので、目標は「決着の目の予測オッズが現行帯を下回るか」。
順当決着（指数1位2位がそろい3着も指数3〜4位）も併記した。

**確認窓（本番相当）**

| 条件量 | 型C AUC(帯15未満) | 型C AUC(順当) | 型E AUC(帯30未満) | 型E AUC(順当) |
|---|--:|--:|--:|--:|
| **`sig14`** = Σ(1/予測オッズ)・確率上位14点・帯なし | **0.660** | 0.609 | **0.631** | 0.573 |
| `sig12` 同・12点 | 0.656 | 0.610 | 0.622 | 0.573 |
| `sp5` 確率上位5点の確率合計（§5 の量） | 0.654 | 0.599 | 0.615 | 0.580 |
| `sp12` / `sp14` | 0.647 | 0.591 | 0.611 | 0.582 |
| **`q_m3`**（§8 が使った量） | 0.628 | 0.596 | 0.561 | 0.588 |
| `axis_sum` | 0.601 | 0.573 | 0.541 | 0.518 |
| **本線オッズ `hs_trio`**（三連複◎○▲の予測オッズ・向きが逆） | 0.383 → **0.617** | 0.396 → 0.604 | 0.406 → **0.594** | 0.420 → 0.580 |
| `gap` | 0.540 | 0.543 | 0.523 | 0.565 |
| `arare` | 0.478 | 0.495 | 0.496 | 0.484 |
| 確率上位k点の予測オッズ**中央値** `med_po12` | 0.465 → 0.535 | 0.489 | 0.409 → 0.591 | 0.453 |

探索窓も同順（`sig14` 0.675 / 0.646、`sp5` 0.657 / 0.636、`q_m3` 0.617 / 0.573、`hs_trio` 0.363 / 0.412）。

`sig14` の十分位（確認窓・型C）: 決着の予測オッズ中央 D1 **60.1倍** → D5 41.7 → D10 **14.6倍**、
帯15未満で決まった率 D1 **9.9%** → D5 30.2 → D10 **50.3%**。型E も同形（D1 11.1% → D10 40.7%）。

🟢 **結論: 読める。しかも `q_m3` を明確に上回る（+0.03〜0.07 AUC・両窓）。**
🔴 **中央値ではなく合計を使うこと。** `med_po12`（買おうとしている目の価格の中央値）は
`sig14`（同じ目の価格の**逆数の和**）よりはっきり弱い。効いているのは「1点いくらか」ではなく
「その集合を買うのにいくら要るか」＝**入稿ゲートが見ているのと同じ量**である。
🔴 **本線オッズは効くが最良ではない**（`mark_order` 追補の「本線が安いほど◎○▲決着が多い」と整合）。

## 9. 限界

- 🔴 **確認窓を消費している。** 格子・T・帯を確認窓の値を見ながら比べた。候補①が
  「帯＝現行の15・T＝`MIN_MEAN_PAYOUT`＝新しい定数ゼロ」という**探索の外にある自然な点**で
  あることだけが、多重比較に対する弁明になる。前向きの実地で確かめること。
- 🔴 **点数の格子が粗い**（3/4/5/6/8/10/12/14/16）。型C の τ適応は**上限16 を 18%（確認）/ 17%（探索）
  のレースで叩いている**ので、本当の最適点はもっと上にある可能性がある。実装するなら k を
  1点刻みで積み、ガミ率（5.0%・現行 3.9%）を見ながら上限を決めること。
- 🔴 **`sigma_max` で実装してはいけない。** 本稿の τ適応は `mean_expected_payout`（**算術平均**）が
  T を割る手前で止める規則で、`conf` 傾斜では `Σ(1/予測オッズ) <= 予算/T` と**同値ではない**
  （恒等式が成り立つのはダッチのみ）。`B_hit` の `sigma_max=1/3.0` は近似であり、
  同じ書き方をすると別の腕になる。
- ⚠️ `apply_line_swap` と日次上限を掛けていない。**率の差の向き**は動かないが絶対値は動く。
- ⚠️ 型E の帯撤廃系は**現行の的中の 45〜51% を壊す**（維持95 / 破壊78 / 救済132）。
  「同じ商品の改良」ではなく作り替えなので、前向き記録の比較は世代を分けること。
- ⚠️ **9車では測っていない**（`AXIS_GATE` / `underband` と同じ理由）。
- ⚠️ 条件量 `sig14` は結局採用しないが、A章の分離自体は本物で**別用途（例: p3 モデルの特徴量、
  日次上限の優先順位）には再利用できる**。ここで否定したのは「それで買い方を切り替えること」だけ。
