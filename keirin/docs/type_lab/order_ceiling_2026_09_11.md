# 「順序」に残っている伸び幅 — 学習した順序モデル vs 手作り4定数（2026-09-11）

## 0. 結論（1行）

🔴 **否定。順序の確率は学習すれば確かに良くなる（条件付きの並び当て +1.65〜2.10pt・
両窓 CI 0跨がず・市場より上）が、商品に落とすと 0.00pt。** 天井（並べ替えオラクル
**+16.5pt**）は大きいままだが、**その天井は確率の精度で塞がっているのではなく
「並べ替え」という操作の自由度で塞がっている。**

🟢 **したがって「順序は諦めて軸崩壊（外れの55%）へ資源を回す」判断材料になる。**
ただし理由は「順序に情報が無い」ではない——**情報はある。変換できない。**

## 2. 🔴 天井を測り直した（brief §1）— 前稿と違う数字が出た

### 2.1 商品は「1集合につき複数の並び」を買っているので、6並びの top-1 は天井ではない

`line_order_2026_09_10.md` §8.3 の診断（「6並びから1つ選ぶと当たる率」現行 38.3/39.1%）は
**商品の制約を反映していない**。実際の商品は1集合あたり 1.0〜2.4点を使うので:

その 83% が 100% でないのは次の 2.2 のとおり。

### 2.2 並べ替えで**到達できる**範囲（三連単の当てにいく商品・本番経路）

| | 確認（n=5,344商品） | OOS 2025H2（n=4,730） |

## 3. 🟢 学習した順序モデルは本当に強い（条件付き確率としては）

### 3.1 モデルクラス

**条件付きロジット（Plackett-Luce のライン交互作用込み直接学習）**。
基礎 PL（＝本番 `rank_7t3_blend_probs` の `adj_w=(1,1)`）の log 確率を**オフセット**に置き、
そこへ特徴を学習する。**λ/μ/λr/μr はこの係数を手で置いた特殊形**なので、学習すれば
下回らないはず——という brief の設計をそのまま実装した。

- 教師: 各レースの**決着の3車集合の6並び**、正解は実際の並び（6択の softmax MLE）
- 🔴 板に全着順が無い（`WIN` は上位3着の順列だけ）ので、**教師は決着集合しか作れない**
- 腕: `L1_pair4`（λ/μ/λr/μr の4定数だけ学習）/ `L4_inter`（ライン隣接15 + 隊列位置・
  ライン規模・先頭/単騎・脚質・印 + pw/p3/競走得点の交互作用8 = 45特徴）/
  `L5_mkt`（+市場）/ LightGBM lambdarank（group=6・同特徴）
- 🔴 **vintage 2 fold**（対象レースより未来を使わない）:
  fold A train ≤2025-06-30 → eval 2025-07〜12 / fold B train ≤2025-12-31 → eval 2026-01〜08
- 基礎 PL のベクトル化は本番関数と `max|Δ| = 6.9e-18` で一致、
  210順列の特徴は学習台と `max|Δ| = 1.2e-07`（float32 丸めのみ）で一致することを確認済み

## 7. 🔴🔴 なぜ変換できないのか（機序・本稿で最も価値のある数字）

並べ替えで**直せた**（正解が帯の中・ゲートも通る）ケースだけを取り出し、
**実装が選べる候補（同じ3車・まだ買っていない・帯の中）の中で、各モデルが正解を何位に
置いたか**を数えた。

### 確認窓・直せた 878件

| 候補の本数（元の1点を含む） | 2本 | 3本 | 4本 | 5本 | 6本 |
|---|--:|--:|--:|--:|--:|
| 件数 | 10 | 40 | 125 | 191 | **512** |

| 腕 | 正解を**1位**に置いた | 順位分布（1位/2位/3位/4位/5位/6位） |
|---|--:|---|
| 現行 λr | **23 / 878 = 2.6%** | 23 / **409** / 207 / 134 / 68 / 37 |
| L1 学習4定数 | 51 / 878 = 5.8% | 51 / 386 / 212 / 119 / 73 / 37 |
| **L4 学習モデル** | **67 / 878 = 7.6%** | 67 / **372** / 213 / 122 / 65 / 39 |
| 市場 | 83 / 878 = 9.5% | 83 / 372 / 196 / 117 / 73 / 37 |

（OOS 771件も同じ: 2.6% / 5.1% / 6.9% / 8.2%・最頻は2位）

🔴🔴 **正解は「その集合の 2番目にありそうな並び」であることが最も多く（42〜47%）、
1番目はすでに買っている。** 並べ替えは1点を1本しか動かせないので、
**「1位を2位に入れ替える」＝期待値を下げる操作**になり、正しく発動しない。

＝ **これは順序の精度の問題ではなく「1つの集合に何本の並びを買うか」の問題。**
点数は `Σ(1/予測オッズ) < 0.5`（平均想定払戻2万円）の枠で決まっており、
**その層（τ適応・帯・点数・三連複への振替）は既に出尽くしている**
（`coverage_framework` / `tau_adaptive_stacked` / `type_e_order_split` / `five_point`）。

🟢 **モデルを最良にしても 7.6%、市場でも 9.5%。** 天井 +16.6pt のうち
事前情報で触れるのは **その 3〜10%＝表示的中で +0.5〜1.6pt 相当が上限**で、
実際にはそれを取りに行くと他の点を壊して差し引きゼロになる（§4 の 維持/破壊/救済）。

## 8. 限界

⚠️ **教師は「決着の3車集合の6並び」しか作れない。** 板 (`race_type_board.npz`) は
`WIN`（上位3着の順列）しか持たず**全7車の着順が無い**ので、買った非的中集合の
並びを教師にできない。全着順があれば1レース35集合＝教師が35倍になる（未測定の改善余地）。

⚠️ **探索側の窓が doc と違う。** 本稿の OOS 窓は **2025-07〜12 のみ**
（fold A = train ≤2025-06-30 の out-of-sample）。doc の探索窓 2024-07〜2025-12 は
モデルの学習に使ってしまうので評価に使えない。また fold A の eval 期間は
`odds_tf_n7`（train_end 2025-12-31）の in-sample なので、**市場を使う腕は fold A で過大**。
**本番相当は確認窓（fold B）**で、そこでの `L4` は **−0.06pt**。

⚠️ **確認窓をさらに消費した**（腕8本 + 診断・多重比較）。ただし採用ゼロ。

⚠️ **9車は未測定**（`F_line` は三連複で順序が無く、`F_pay` は一撃商品）。

⚠️ **一撃商品（`A_ana` / `F_sign`）には掛けていない**（doc §7.2・掛けると 10万+ が −7〜22%）。

⚠️ **押さえ目・τ適応・`apply_line_swap` は main のまま入れて測った**（土台が本日の PR#567）。
`apply_line_swap` は λr と狙いが重なり発動率を半分にするが、効果は消えないことが
前稿で確認済み。学習モデルについては 2×2 の切り分けをしていない。

⚠️ **オラクルは「その集合の1点を正解の並びへ置き換える」形**で、帯とゲートを守っている。
点数を増やす形のオラクル（＝2本買う）は測っていない（それは点数層）。

## 9. 申し送り

1. 🟢 **順序層は打ち切ってよい。** 残り幅は大きい（+16.5pt）が、**塞いでいるのは確率の
   精度ではなく操作の自由度**で、確率を最良にしても取れるのは 0.0〜0.2pt。
   **軸崩壊（外れの55%）へ資源を回す判断を支持する。**
2. 🔴 **記録として残すべき較正**: `RANK_7T3_LINE_ADJ_W` の **μ=1.5 は推定値 0.95 の 1.55倍
   過大**（両窓で 3% 以内に再現・λ は 2.0 → 2.4、λr は 1.9 → 2.08 でほぼ正しい）。
   ただし **`rank_7t3_blend_probs` を直すと選択が変わって負ける**（§6）ので触らない。
   「定数がずれている」と「直すと良くなる」は別。
3. 🟡 **もし順序へ戻るなら**、直すべきは確率ではなく **「1集合あたり何本の並びを買うか」**。
   正解は 42〜47% のケースで「モデルの2番目」に居る（§7）。これは点数＝Σ枠の問題で、
   既に何度も測られている層（`coverage_framework` の τ・`type_e_order_split` の 1集合1点制限は
   逆向きに失敗している）。
4. 🟡 **未測定の唯一の余地**: 板に全7車の着順を載せて教師を35倍にする（§8）。
   ただし §7 の機序（正解が2位に居る）は教師量では動かないので、期待値は低い。
