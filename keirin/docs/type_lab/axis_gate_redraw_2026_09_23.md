# 軸信頼ゲートを引き直す — と、「買っていない側」の答え合わせ（2026-09-23）

発端はユーザー観察:

> 現在の的中率だと買ってる側より買ってない側に的中、回収があると思います

結論を先に3行:

1. **観察は正しい。** 見送った側の表示的中は 31.1% ↔ 売った側 23.2%
   （Δ **+7.86pt [+3.18, +12.85]**・CIが0を跨がない）。
2. 🔴 **ただし正体は「安い当たりを意図的に捨てている」こと。** 想定払戻2万円未満で
   見送る枠だけ表示的中 53.2% ／**当たっても中央13,020円**。そこを除くと
   Δ表示的中 +2.78 [−1.55, +7.23]・ΔROI +5.93 [−15.88, +26.71] で**どちらも判別不能**。
   **「回収もいい」はデータから言えない。**
3. 🟢 **実利は別のところにあった。** 2026-09-22 に堅い3型がダッチへ移ったので
   `AXIS_GATE_MIN` が p19〜p44 とばらけていた。**p20 で揃え直す**と
   件/日 +1.5・4万+/日 +0.08（両窓ともCIが0を跨がない）・表示的中は据え置き。

---

## 1. 「買った側」と「見送った側」を同じ台で突き合わせる

売ったかは `netkeirin_submissions`、見送りの理由は `submission_skips`。
🔴 `picks_history`（旧ランクの候補）は使わない。
再現: `scripts/exp_type_lab/skip_vs_sold.py --start 2026-08-27`

## 2. なぜ軸信頼ゲートが効かなくなっていたか

`AXIS_GATE_MIN` は「**入稿ゲートを先に当てた後のプラン内 p30**」として引いた値
（2026-09-12）。2026-09-22 に堅い3型（A/B/C）が「計画払戻5万円のダッチ」へ移ったので
母集団が変わり、**同じ絶対値が別の分位を意味する**ようになっていた。

引き直して当ててみた実測（`scripts/exp_type_lab/axis_gate_redraw.py`・

だから「探索窓で引いて確認窓で評価する」が実質的に無意味なほど、これは
outcome に当てた値ではなく**母集団の記述統計**。

## 4. 決定（2026-09-23・ユーザー判断）

**p20 で揃え直す。ゲートは外さない。**

- 2026-09-12 に広げた理由は「**件数を減らすこと自体が目的**」だった。
  9/22 に目標が「4万円以上の払戻の件数」へ変わったので、その理由は失効している。
- 全部外すほうが 4万+ は取れる（+0.19/日）が、ユーザーが「引き直す」を選んだ。
  **外すのは1行（`AXIS_GATE_MIN = {}`）で、いつでもできる。**

実装後、本番コードを台で回して**測った腕と1件もずれない**ことを確認済み:

    件/日 34.2 / 表示的中 19.32% / ROI 82.2 / 払戻中央 28,880 /
    3万+ 3.14 / 4万+ 1.90 / 10万+ 0.454 / 計画中央 40,710

## 5. 先週売った商品の外れの内訳（2026-09-16〜22・278件）

| | 割合 | 意味 |
|---|---:|---|
| **軸崩壊**（◎○のうち3着内が1車以下） | **56%** | どう買っても取れない |
| 相手外し（◎○はそろったが3着目を買っていない） | 20% | 点数・相手の選び方の問題 |
| 順序違い（3車は合っているが並びが違う） | 23% | 三連単のみ |

プラン別では `F_hit` が 74% 軸崩壊、`C_hit` / `E_hit` / `A_hit` は約4割が順序違い。
⚠️ これは**旧構成（9/22 以前）で売った商品**の内訳。新構成では点数が減るので比率は動く。

## 6. 限界

- 台は7車のみ（9車の `F_line` / `F_pay` を含まない）。
- §1 の見送りの成績は `type_lab_picks` の live 行（＝その朝に組んだもの）で採点しており、
  売った側と同じ採点系だが **n=415 と小さい**。理由別はさらに小さい（17〜193件）。
- §3 の掃引は確認窓を再び使っている。ただし測っているのは新しいエッジではなく
  **既知の量のダイヤル**で、両窓で単調に一致する。
