# 「軸崩壊」を直接の学習目標にできるか — 第1層（型判定）（2026-09-11）

> 🔴 **結論: 否定。** 「p3 上位2車がともに3着以内（そろい）」をレース単位で学習したモデルは
> `axis_sum`（周辺和）より **AUC +0.012〜+0.024 で確かに当たる**（両窓 CI 0 跨がず）。
> しかし ①その大半は**本番が買い目に既に使っている同時確率 `p_both`**（`rank_7t3_blend_probs`・
> λ/μ の同ライン補正込み）に入っており、`p_both` へ足した増分は **+0.004〜+0.007**
> （`board_pattern` +0.003 / `old_rank_ideas` +0.0027 と同じ桁）。
> ②商品まで通すと **3通り（型判定の差し替え／境界の分位／軸信頼ゲート）とも現行に
> 両窓で勝てない**（Δ表示的中 の CI が 0 を跨ぐか、無作為対照との勝敗が窓で反転）。
> ③機序は実測で割れた: **判定は正しくなるが、商品がそれを表示的中に変換できない**
> （食い違い集合で「堅い」へ振ると +6pt・「混戦」へ振ると −4pt で相殺）＋
> **入稿ゲート（価格）が最もそろう側を落としている**（そろい上位1/5の通過率 59% ↔ 下位1/5 92%）。
>
> 本番コードは一切変更していない。触る層は **①型判定**（腕 a/b）と **③選別**（腕 c）。

## 0. 先に本番と既存の否定を読んだ結果（CLAUDE.md「測る前に本番コードを読む」）

- 型判定 `race_shape()` の `axis_sum` は **p3 の周辺和**。ライン情報を一切見ない（`DESIGN.md` 1.1）。
- 一方、**買い目の確率** `rank_7t3_blend_probs` は λ=2.0/μ=1.5 の同ライン隣接ボーナスを掛ける。
  そこから作った「軸2車そろい確率」`p_both`（`/tmp/p_both_blend.npz`）は
  `board_pattern_2026_09_10.md` §3 で **軸2そろいの AUC 0.6741（確認）** と既に測られており、
  `axis_sum` 0.6627 を **+0.011** 上回る。＝ **「周辺和では足りない」ことは本番の別の場所が
  既に知っていて、型判定だけがそれを使っていない**。本稿の問いはここへ収束する。
- `old_rank_ideas_2026_09_11.md` §3.4 は同じ目的（`nosplit`）で既存6量ロジスティック 0.6765 に
  favbust を足して +0.0018。二重計上（`win_entropy`=`pw_ent` / `top3_sum_top2`=`axis_sum`）が原因。
  本稿はこの穴を避けるため **対照を `p_both` にし、レース単位の構造量を非線形に混ぜる**。

### 5.3 「なぜ周辺和で十分に見えるのか」

- 周辺和 `axis_sum`・周辺積・λなし同時確率は AUC が**同じ**（0.669/0.662）。周辺確率を
  どう組み合わせても依存は出てこない——**「p3 に同時確率の情報が入っている」からではない**。
- 依存の実体は **軸2車が同ライン・隣接か**（同ライン 60.1% ↔ 別ライン 38.8%・型内でも +15〜23pt）で、
  本番はこれを **λ/μ（`rank_7t3_blend_probs`）で買い目側に既に入れている**。`p_both` が
  周辺和を +0.011〜0.016 上回るのはその分。レース単位モデルの増分の大半は同じ情報の再発見で、
  `p_both` の上に残るのは +0.004〜0.007（確認窓の CI は 0 に接する）。
- したがって「型判定が周辺和で足りている」のではなく、**「型判定の精度を上げても商品側の
  補償とゲートに吸収されるので、周辺和の粗さが露出しない」**が正しい読み。

## 6. 触る層と、残る道

- 本稿の腕は **①型判定**（a/b）と **③選別**（c）。両方とも否定。
- 🟡 **設計として残る唯一の道は、第1層ではなく第2層**: 「軸が崩れる」と正しく読めたレース
  （新=混戦 / 現行=堅い）を**軸2車前提でない商品**へ送ること。ただし
  `axis_bust_conditional_2026_09_03.md`（軸1外しは検出なしでも同じ看板）・
  `type_a_upset_2026_08_31.md`（軸崩壊 40.5% は軸商品では取れない）が既に否定しており、
  本稿の `s_full` は `pw_ent` と ρ=−0.77 で、そこで使われている検出量の言い換えに近い。
  **再提案はしない。**
- 🟡 `p_both` を型判定へ入れる（λ/μ を第1層にも効かせる）案は、判定としては
  +0.011〜0.016 AUC で本物だが、**商品 KPI では確認窓で無作為対照に 1/20**（4.1）。採用しない。

## 7. 限界

1. 型判定を動かす腕は**売る商品ごと変わる**ので、板の `apply_line_swap` 未反映（`DESIGN.md` 2.2 の注意）
   と日次上限・高額枠なし、の2点で実運用とは絶対値がずれる。**率の比較にだけ使うこと。**
2. firm 率を「学習窓の現行率」に揃えたのは件数を揃えるための約束事で、最適な firm 率は測っていない
   （4.2 は ×0.8〜1.2 の掃引のみ）。
3. 探索OOS は四半期 WF の 2025年（4 モデル）、確認は 2026年（3 モデル）。2025Q1 の学習は 8,172R と薄い。
   `l_exist_pb_full`（スタック）は学習窓に OOS 予測が要るため **2025Q1 は現行判定のまま**。
4. 多重比較: 腕は (a)5 ×2窓 + (b)12×2 + (c)6×2 ＝ 46。無作為対照は各 20 seed。
5. G3 集約（420列）は特徴の作り方に恣意性がある。ただし `s_struct` 単体が `p_both` に届かず、
   `s_full` の gain は `p3_prod`/`axis_sum`/`same_line`/`adjacent` で 5割超なので、
   別の集約で結論が変わる余地は小さい。
6. 較正（3.2 末尾）の別ライン −9pt（Q2）/ −15pt（Q6・n=143）は買い目の**配分**には効きうるが、
   本稿は順位付け（AUC）と型判定・ゲートしか測っていない。配分側は別腕。
