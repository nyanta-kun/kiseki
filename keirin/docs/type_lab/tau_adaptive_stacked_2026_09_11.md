平均点数 12.0 → **13.5**（doc の τ適応は 11.9）・払戻中央 **−7.6 / −8.1%**（doc は −3.7 / −3.1%）・

`band_by_race` §9 が「本当の最適点はもっと上にあるかもしれない」と書いた側へ実装が寄っている。

## 1. 先に読んだもの（CLAUDE.md「測る前に本番コードを読む」）

- `PLANS["C_hit"]` = `prob_top` / `min_odds=15.0` / `max_legs=12` / `alloc='conf'` /
  `floor_mult=MIN_PAYOUT_MULT` / `underband_min=5.0` ＋ **`tau_adaptive=True`（本ブランチ）**。
- `build_with_gate_fallback` の順序は **① `_build`（τ適応はここ）→ ② `GATE_FALLBACK` →
  ③ `_done` の中で `apply_line_swap`**。つまり **τ適応が先・ライン差し替えが後**。
- `LINE_SWAP_PLANS = {B_hit, C_hit, E_hit, F_hit}`。差し替えは `LINE_SWAP_LEGS=(2,1)` を
  順に試し、**入稿ゲート（平均想定払戻2万円）を割るなら差し替えない**。
- 🔴 **ここが噛み合う場所。** τ適応は「平均想定払戻がゲートを割らない**最大**点数」を採るので、
  差し替えに残る余白が構造的に薄くなる。実測でも `C_hit` の差し替え発動率は
  **58% → 26%**（現行 → τ適応・両窓とも）に落ちる。**「発動が半減しても表示的中は落ちない」**
  のが本稿の中心的な観測。
- 軸信頼ゲート: **2026-09-11 の #565 で `C_hit` も対象**（`AXIS_GATE_MIN["C_hit"]=1.500`・p30）。
  `band_by_race` の台は `C_hit` exempt 時代なので母集団が 1,914 → 1,233（確認）に減る。
- `UPPER_BANDS = ()`（2026-09-04 に切り戻し済み）なので `add_upper_band` は no-op。

### 🔴 実装の副作用を1つ見つけた（本稿の測定対象そのもの）

`GATE_FALLBACK["C_hit"] = replace(PLANS["C_hit"], underband_min=0.0, ...)` は
**`tau_adaptive=True` を継承する**。つまり τ適応は代替の買い方にも掛かる。
`C_hit` は **22.2% のレースで主プランがゲートに落ちて代替へ回る**ので、
これは無視できる量ではない。挙動としては一貫している（同じ商品の差込なし版）が、
**意図したものかを確認しておくこと**。検証側では実際にここを踏んだ（6章）。

## 2. 台の作り方と検算

板は `/tmp/race_type_board.npz`（7車 36,427R・2024-07-01〜2026-08-04・vintage walk-forward の p3/pw）。
`scripts/exp_type_lab/tau_stacked_build.py` が1レース1商品を組む。

- 売る商品は本番 **`sell_plans_for`**（型A の `pw_ent` / `trio_ok` 分岐込み）。
- 買い目は本番 **`build_with_gate_fallback`**（`GATE_FALLBACK` ＋ `apply_line_swap` 込み）。
- 入稿ゲートは `netkeirin_submit_type_lab._gate_reason` と同じ2条件
  （平均想定払戻 > 20,000円・全点の予測オッズ >= 2.0倍）。
- 現行側は **main の `src/type_lab.py`**、τ適応側は **worktree の `src/type_lab.py`** を
  `--repo` で切り替えて**別プロセス**で読む（同一プロセスでの module 差し替えはしない）。

### 🔴 `RaceShape` に `lines` / `line_pair` を渡す（既存台の欠陥）

`band_by_race_build.py` は `typef_racetype.ctx` を使っており、`RaceShape` の位置引数が
`pw_ent` で止まっていて **`lines=()`** だった。`apply_line_swap` は `shape.lines` が空だと
**一度も発動しない**ので、あの台は「ライン差し替えの掛かっていない `C_hit`」を測っていた。

```python
lp = {c: (int(v) if np.isfinite(v) else None) for c, v in ...}   # 🔴 int() する
lines = _lines_of(lg, lp)
shape = RaceShape(..., order, win_entropy(pw), lines, _strongest_pair(lines, p3))
```

⚠️ **`A_line_pos` は float32。`_lines_of` は `int(str(v))` で読むので `"1.0"` は
`ValueError` になり（例外は握りつぶされる）全車が最後尾 99 扱い＝ライン内が車番順になる。**
実測で **91.5% のレースで並びが変わる**（例: `line_pos` 7=1,1=2,4=3,5=4 →
`int` 版 `(7,1,4,5)` ↔ `float` 版 `(1,4,5,7)`）。
🔴 **`lines` が空になるわけではないので「発動 0% で気づく」ことはできない。**
先頭×番手の2通りを優先する `line_legs` の設計だけが静かに壊れる。

## 5. 🔴 副産物 — `apply_line_swap` は `C_hit` にほとんど効いていない

上の 2×2 を「同じ側の中で OFF→ON」に読み替えると、差し替えそのものの実力が出る。

| プラン | 発動 | 表示的中 OFF→ON（確認） | Δ 95%CI | 同（探索） | Δ 95%CI |
|---|--:|---|---|---|---|
| **`C_hit`** | 58% | 33.41 → 33.58 | **+0.16 [−0.89,+1.30]** | 33.38 → 33.64 | **+0.26 [−0.32,+0.81]** |
| `B_hit` | 79% | 28.37 → 31.55 | +3.18 [+1.91,+4.58] | 27.86 → 29.91 | +2.04 [+1.23,+2.91] |
| `E_hit` | 68% | 22.32 → 25.14 | +2.82 [+1.27,+4.52] | 19.58 → 22.03 | +2.46 [+1.23,+3.75] |
| `F_hit` | 42% | 27.89 → 28.86 | +0.97 [+0.11,+1.83] | 28.65 → 29.25 | +0.61 [+0.06,+1.13] |
| 全体 | 37% | 26.03 → 26.94 | +0.91 [+0.55,+1.28] | 26.44 → 27.09 | +0.65 [+0.43,+0.88] |

🔴🔴 **`C_hit` だけ両窓とも CI が 0 を跨ぐ。** `LINE_SWAP_LEGS` の節の
`C_hit +2.89 / +3.88pt` は**この台では再現しない**。他の3プランは向きも量も概ね再現する
（`B_hit` は doc より大きく、`E_hit` は doc より小さい）ので、台の壊れではなく
**`C_hit` 固有**の話と読むべき。考えられる差は2つ:

1. **確定オッズ ↔ 予測オッズ。** `line_legs_2026_09_05.md` が自分で挙げている限界
   （「並べ替えは確定オッズで測っている。向きは変わらないはずだが量は前向き実測で
   確かめること」）。差し替え先の並び順も `LINE_SWAP_MIN_ODDS=10` の判定も、
   どちらのオッズで見るかで別物になる。
2. **`underband_min=5.0` が後（#508・2026-09-08）に入った。** 帯の下の最人気1点を
   **先頭へ**差し込むので、末尾 m 点を置き換える `line_legs` と同じ買い目の中で
   逆向きに働く（安い1点で平均想定払戻が下がり、差し替えの余白が減る）。

⚠️ **本稿の目的の外なので「測ったらこうだった」以上のことは言わない。**
`C_hit` から差し替えを外すかどうかは別途決めること。

## 6. 🔴 必須の対照 — 点数の多重集合を無作為に割り当て直す 20 seed

τ適応 が選んだ点数の**多重集合はそのままに、どのレースへ割り当てるかだけを壊す**。
件数を変えない振り分け操作なので、CLAUDE.md の作法どおり同数の無作為対照を置く。
**`apply_line_swap` 込みの本番経路で**測った。

| 窓 | 現行(12点) | **τ適応** | 無作為対照 20seed 中央（範囲） | 勝敗 |
|---|--:|--:|---|---|
| 確認 2026-01〜08（n=1,233） | 33.58% | **37.23%** | 33.05%（32.28〜34.55） | **20/20** |
| 探索 2024-07〜2025-12（n=3,442） | 33.64% | **36.64%** | 32.07%（31.64〜32.83） | **20/20** |

🟢 **対照の中央値は両窓とも現行より低い。** ＝「12点をばらけさせること」自体には価値がなく、
**どのレースで何点にするかの割り当てに情報がある**。`band_by_race` §8 の 20/20 を
`apply_line_swap` 込みでも再現した。

🔴 **この対照を作る時に実バグを2つ踏んだ**（どちらも例外を出さない）:

1. `replace(BASE, max_legs=k)` は `tau_adaptive=True` を**残す**ので、どの k でも
   τ適応の結果が返り、20 seed が全部同値（範囲 0.00）になった。
2. それを直しても **`GATE_FALLBACK["C_hit"]` が `tau_adaptive` を継承している**ので、
   ゲートに落ちたレースでは代替側で τ適応が走り、固定k の腕が汚染された
   （現行腕が 33.58 → 33.82% に上振れ）。**代替も含めて切る**必要がある。

＝ **「対照の範囲が異様に狭い／現行の再現値がずれる」は台の汚染を疑う合図。**

### 読み方

- 🟢 **きれいな単調ダイヤル。** 上限を上げると 表示的中 ↑・払戻中央 ↓・ガミ率 ↑ が
  **両窓で同じ向き**に動く。**符号が窓で食い違う水準はゼロ**（全水準・両窓で CI が 0 を跨がない）。
- ⚠️ **隣り合う水準の差は窓で順序が入れ替わる。** 確認窓では 16 (+3.65) > 18 (+3.57) だが
  探索窓では 16 (+2.99) < 18 (+3.08)。**「16 と 18 のどちらが良いか」は判別できない**
  （CI が大きく重なる）。読めるのは 12 ↔ 16 ↔ 上限なし のような**離れた水準の間だけ**。
- 交換レートの目安（確認 / 探索）: 払戻中央を **1% 削るごとに 表示的中 +0.2〜0.4pt**。
  12 → 上限なし で 払戻中央 −9.3 / −6.9pt ぶん余計に削って 表示的中 +2.0 / +2.2pt を足す。
- ROI はどの水準でも 81〜86 / 81〜82% に収まり**水準間で判別できない**（採否に使わない）。
- 🔴 **上限を上げるほど「上限張付」が減る**＝制約が `TAU_ADAPTIVE_MAX_LEGS` から
  **入稿ゲートそのもの**へ移る。上限なしでは平均15.0点・実測最大45点まで伸びる。
  ＝ **上限は「ゲートに任せきらないための安全弁」として働いている。**
