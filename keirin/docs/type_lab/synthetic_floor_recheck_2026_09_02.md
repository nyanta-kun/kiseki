# 型C の合成オッズ下限 — 帯15倍の上で測り直して不採用（2026-09-02）

## 何を決めたか

**合成オッズの下限は入れない。** 2026-08-31 にユーザー承認を得ていたが、
その測定は**帯20倍の paper の上**で行われており、翌 09-01 の PR#395 で
帯を **15倍**へ下げたあとは前提が変わっていた。現行設定で測り直した結果、
代償が承認時の約2倍になっていたため不採用とした（2026-09-02 ユーザー判断）。

## 測り直しの手順（ここが今回の本体）

🔴 **paper テーブルは商品の定義を変えると古い版のまま残る。**
`type_lab_picks` の paper 行は `rule_version 7ba9b58d7dff`（帯20倍）のままで、
そこで下限を掛けても **いま売っている商品の話にならない**。
現行版 `cf39e62d1442` で 20か月ぶん（98,244行）を作り直してから測った。

| 窓 | 期間 | 行数 | 予測の出どころ |
|---|---|---|---|
| 探索 | 2025-01-01〜12-31 | 66,992 | 月次 vintage モデル + `odds_tf_te20241231` |
| 確認 | 2026-01-01〜**08-04** | 31,252 | 板 npz（四半期 walk-forward） |

🔴 **2025 に板 npz を使ってはいけない。** 板の予測オッズは本番モデルと100%一致で、
2025 では in-sample になる。既存の paper が両窓とも OOS なのは
「2025=vintage / 2026=板」で作り分けているからで、それを踏襲した
（[[keirin_type_lab_vintage_odds_models_2026_08_28]]）。

⚠️ 確認窓の終端が 08-26 → **08-04** に短くなる（板 npz の収録終端）。
⚠️ 再生成は 1本だと約8時間かかる。**四半期4本の並列**で約2.5時間。

    KEIRIN_ODDS_TF_MODEL_DIR=$PWD/data/models_vintage/odds_tf_te20241231 \
    PYTHONPATH=. .venv/bin/python scripts/build_type_lab_picks.py \
      --mode paper --from 2025-01-01 --to 2025-03-31 --models vintage
    # 2026 は --models board（板 npz は 2024-07-01〜2026-08-04）
    PYTHONPATH=. .venv/bin/python scripts/settle_type_lab_picks.py \
      --from 2025-01-01 --to 2026-08-04
    PYTHONPATH=. .venv/bin/python scripts/exp_type_lab/points_floor_current.py

## 承認時（帯20倍）と何が変わったか

| | 2026-08-31（帯20倍） | 2026-09-02（帯15倍） |
|---|---|---|
| 4倍で C_hit が失う表示的中 | −3.0pt | **−7.4pt** |
| 全体の表示的中 | −0.88 / −0.70pt | **−1.65 / −1.57pt** |
| 元返しの改善 | −5.5 / −4.3pt | −6.0 / −4.1pt（同程度） |
| ROI | 73.4 / 76.7（ほぼ不変） | 77.0 / **78.4**（確認窓 −3.8pt） |

機序は算数。帯を下げると1点あたりが安くなるので、同じ12点でも合成オッズが下がる
（live 実測の中央 3.39 → **2.61**倍・4倍未満が 85% → **100%**）。
そこへ4倍の下限を掛けると切る点数が増える（**12点 → 6点**）。

🔴 **`type_lab.py` の「帯を下げる」と「点数を減らす」を同時にやってはいけない
という規律そのもの**（両方が払戻を同じ向きへ押す）。PR#395 が既にそのレバーを
使っており、下限はその上に重ねる形になる。

## 読み方

- **ROI では選べない**（探索 +0.8pt ↔ 確認 −3.8pt で符号反転）。
  8/31 の測定でも ROI はほぼ不変で、これは一貫している
- **2万円ゲートの通過件数はどの水準でも動かない**（47.8→47.9 / 36.3→36.3）
- 確実なのは「表示的中を 1.6pt 払って、的中中央 +3,400〜4,800円・元返し −4〜6pt」
  という交換。承認時に見えていた代償の約2倍
- 3倍は無害だが効果も小さい（表示的中 −0.4/−0.2pt・元返し −1.3/−1.0pt）

## 再測定するとき

`scripts/exp_type_lab/points_floor_current.py`。**現行 `rule_version` の
`mode='paper'` だけ**を読む（新旧が同じテーブルに混ざるため必ず版で絞る）。
商品の定義を変えたら、まず paper を作り直してから測ること。
