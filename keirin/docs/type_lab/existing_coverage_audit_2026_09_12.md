# 既存商品カバレッジ監査 — 「◎○が2・3着に回る万車券」をどこまで既に取っているか（2026-09-12）

## 結論（1行目）

**この事象自体は既存ドキュメント（`type_a_upset_2026_08_31.md` の `T` 指標・`mark_order_2026_09_10.md`）で既に測定済みで、しかも今この同じフリート内の `07_mark_upset` / `08_mark_second_third` が全型版を並行して測っている。新規性は「全型に一般化した頻度・現行の的中率・取り逃し額」の再確認どまりで、既存商品側の構造は — 三連複（`A_trio`/`D_hit`/9車`F_line`）だけが定義上この事象を100%捕捉でき、残り9種の三連単系プランは軸1・軸2の並び順に賭けているため構造的にほとんど捕まえられない — という、コードを読めば分かる話に尽きる。買い方の設計は②③（下記）を直接どうするかの選択問題であり、「読み」を新設する必要は無い。**

## 0. 監査の前提・作法

- 台は `/tmp/race_type_board.npz`（7車 36,427R・探索2024-07〜2025-12 / 確認2026-01〜08）。
- **`07_mark_upset` が同じ台・同じ本番経路（`sell_plans_for` → `passes_axis_gate` →
  `build_with_gate_fallback`（GATE_FALLBACK・line_swap・order_swap 込み・osae は現行 OFF））
  で作った `product.pkl`（1レース1行＝実際に組んだ買い目）と `event_table.pkl`（◎○の位置）
  を読み取り専用で再利用**し、自分の追加集計だけ `09_existing_coverage_audit/analyze.py`
  として書いた（リポジトリ・他セッションのファイルは一切編集していない）。
- 定義（`event_table.py` を確認済み）:
  `hon`=◎（`prediction_mark==1`）、`tai`=○（`==2`）。`w`=決着1着車。
  **`y` = w ∉ {hon,tai}**（1着が◎○以外）。**`mk23` = hon または tai が2-3着**
  （＝ユーザーの「この選手」を単数として読む広い定義）。**`both23`** = 両方が2-3着
  （＝「◎○が2・3着に回る」を字義通り読む狭い定義）。**`y23` = y ∧ mk23**。
  万車券 = 確定三連単オッズ `tf_odds`（`PAY/100`）**≥100倍**（100円で1万円以上）。
- `passes_axis_gate` / `build_with_gate_fallback` / `sell_plans_for` は本番の実装
  （`src/type_lab.py` / `backend/src/services/keirin_type_lab_gate.py`）そのもの。
  高額枠（`{B,C,D}_sign`/`_big`）と**日次上限**は per-race純関数ではない（日ごとの
  優先順位付け状態を要る）ため、この監査では**シミュレートしていない**——限界に明記。

## 1. 現行ラインナップの「穴・一撃」側 — `build_legs` を読んで確定させた表

`src/type_lab.py::PLANS` と `build_legs()`（同ファイル 1229〜1367行）を読み、
**軸1（p3上位1位）を1着に固定していない商品**を全て洗い出した。

| 商品 | `structure` | 1着に置けるのは誰か | ◎○(軸1/軸2)はどこに入るか | 「◎○が2-3着」を捕捉できるか |
|---|---|---|---|---|
| `A_hit`/`B_hit`/`C_hit`/`E_hit`/`F_hit` | `prob_top`（三連単・確率上位k点） | **誰でも**（210通りの確率順位そのまま。軸固定は無い） | 決まらない（モデルが高確率と見た並びに依存） | **偶発のみ**。モデルの確率が「軸1負け」の並びを上位k点に入れたときだけ。帯（`min_odds`）がある型は逆に高オッズの並びを拾いやすいが的中率は最初から低い |
| `A_pay`/`F_pay` | `axis1_second2` | **軸1に固定**（`(a1, s, c) for s in seconds...`） | 軸1が1着なので対象外 | **不可**（構造上、軸1が勝つ前提の商品。狙いが逆） |
| `A_ana` | `bust_top` | pool=軸1を除く6車内の**どれでも** | 軸1は**全3ポジションから完全排除**（`pool = order[1:]`、候補は `set(k) <= pool` のみ） | **原理的に対象外**。「軸1が2-3着に回る」ことを買うのではなく「軸1が3着内にも一切来ない」ことに賭ける別の商品。軸1が2着/3着に来た決着はA_anaの候補集合に**存在しない** |
| `{B,C,D}_big` | `signboard`(`bust=True`) | A_anaと同じ pool 排除 | 同上（軸1完全排除） | **同上・対象外**（A_anaの高額版） |
| `D_hit` | `axis2_drop_fav`（**三連複**） | 三連複なので順序不問 | 軸1・軸2は**必ず両方**買い目に入る（`{a1,a2,c}`） | **型D×最人気1車を落とした4点構成なら100%捕捉**（③相手外しに落ちるのは、決着の3着候補がD_hitが落とした「最人気の相手」だった場合のみ） |
| `A_trio` | `axis2_flow`（**三連複**） | 同上 | 同上 | **型Aで`trio_ok`成立時は捕捉**（相手2点しか買わないので③相手外しの割合は高い） |
| `F_line`（9車） | `line_axis2_flow`（**三連複**） | 同上（ライン基準の2車） | 同上 | 同上（本監査の7車台には無し・9車専用） |
| `F_sign`/`{B,C,D}_sign` | `signboard`（`bust=False`） | pool制限なし＝**誰でも** | 決まらない（確率順に詰めるだけ） | **偶発のみ**（`A_hit`系と同じ理由）だが、帯が広く点数も多いぶん実測では拾う量が目立つ（§4） |

**結論**: 「◎○が揃って2-3着に回る」を**買い目の構造として100%保証**しているのは
**三連複3商品（`A_trio`/`D_hit`/9車`F_line`）だけ**。他の10商品（`A_hit`〜`F_sign`・
`A_ana`・`{型}_big`・`A_pay`/`F_pay`）はいずれも「順序込みで賭ける」構造か、
「軸1を丸ごと除外する」構造かのどちらかで、ユーザーの言う事象を**狙って**買う仕組みは
現行に存在しない。

## 3. ユーザーの体感は正しいか

> 「この選手が2,3着になった場合の万車券が買えないことが多い」

**数字で肯定できる。** 頻度・取り逃し・原因を分けて示す（再現: analyze.py §5）。

| | 確認窓 | 探索窓 |
|---|--:|--:|
| `y23`の頻度（全レース比） | 24.58%（n=2,557/10,403） | 23.74%（n=6,132/25,832） |
| そのうち確定100倍+（万車券化） | 49.2% → 全体比12.08% | 49.6% → 全体比11.77% |
| 万車券(`y23`∧100倍+)のうち**そもそも入稿できていた**割合 | 68.3%（859/1,257） | 69.7%（2,118/3,040） |
| 入稿できていた分のうち**実際に的中**した割合 | 2.1%（18/859） | 2.6%（56/2,118） |
| ＝万車券化した`y23`全体のうち回収できた割合 | **1.4%** | **1.8%** |
| 入稿されなかった万車券(`y23`)の**軸信頼ゲート落ち**率 | 94.2% | 96.1% |
| 同・入稿ゲート(平均想定払戻/最低倍率)落ち率 | 6.0% | 4.1% |
| 取り逃した配当（確定オッズ）の中央 | 210.3倍 | 224.6倍 |

🔴🔴 **「買えないことが多い」は数字上ほぼ「買えない」に近い。** 万車券化した`y23`の
うち回収できているのは1.4〜1.8%だけで、残り98%超を逃している。中央210〜225倍
（≒1万円の予算に対し200万円級の払戻の目）を取り逃している。

**原因の内訳（BRIEF §3の要求どおり分解）**:

1. **②順序違い**: 入稿できていた分のうち19%（軸は捕まえたが並びが違う）。
2. **③相手外し**: 6〜7%（三連複D_hit/A_trioで相手を削った分に該当）。
3. **④軸崩壊**（このシナリオの中でもモデル軸自体が◎○とは別だった）: 73%
   （入稿できていた分の外れの大多数）。
4. **入稿ゲートで見送り**: 万車券`y23`のうち4〜6%はそもそも平均想定払戻2万円/最低倍率
   のゲートで見送られている（**設計どおり**——薄い点しか買えないレースは店頭方針で
   落としている）。
5. **軸信頼ゲートで見送り**: 万車券`y23`のうち**94〜96%が原因**——`passes_axis_gate`
   はプラン内で軸信頼(axis_sum)下位を落とす設計（DESIGN 3.1・§1.4参照）で、
   軸が弱い（＝◎○が割れやすい）レースを積極的に排除している。**軸が弱いレースほど
   ◎○が2-3着に回りやすい**ので、この商品群の入り口の時点で最も相性の悪い母集団を
   捨てている構造がある。**これは設計どおりの意図的な選別**（軸信頼ゲートは
   両窓で表示的中を+3〜5pt改善する実測済みの機構・`keirin_type_lab_gate.py`）で、
   バグではない。
6. **日次上限**: 未測定（下記「限界」）。

⚠️ **「取り逃している」と「取るべきだった」は別**——上記5番は明確に意図的な設計判断
（軸信頼が低いレースを捨てることで全体の的中率を上げるトレードオフ）であり、
「直せば良くなる」種類の不備ではない。1〜3番（入稿できていた分の中での外れ）は
買い方の改善余地が理論上ある領域だが、②③は`A_trio`/`D_hit`（三連複）にしか無く、
④は§2.3で見たとおり「読み」の問題が大半を占める。

## 4. 新しいのはどこか（他の2体への引き渡し）

**断定できる形で書く**:

1. **「◎○が2-3着に回る万車券の頻度・現行の的中率・取り逃し額」を全型・全期間で
   数値化したのは新規**——ただし`type_a_upset_2026_08_31.md`の`T`指標（型Aのみ・
   条件が「軸が届く∧30倍+」で1着が誰かは問わない）と`mark_order_2026_09_10.md`
   （◎○△の3車が"ちょうど"決着する20%の並び違い）の**間を埋める**位置づけで、
   手法上のブレークスルーは無い。実際、`T`の中で「1着が軸でも軸2でもない第3車」
   なのは**23〜29%だけ**（残りは軸1か軸2が普通に勝っている高オッズ決着）——
   本事象は`T`の**部分集合**であることも確認した（§0の定義参照）。
2. **商品構造の面から「なぜ買えないか」を`build_legs`のコードで確定させたのは新規**
   ——三連複3商品だけが構造的に捕捉可能、他10商品は偶発でしか捕まえられない、
   という整理は既存docに明文化された形では無かった（DESIGN.mdの5分類②③④は
   「なぜ外れたか」の事後分解であって「どの商品が構造的に捕まえられるか」の
   事前分類ではない）。
3. **軸信頼ゲートがこの事象の母集団を94〜96%排除しているという定量**は新規。
   DESIGN 3.1は軸信頼ゲートの全体効果（+3〜5pt）は書いているが、
   「弱軸レース＝このシナリオの主要な発生源」との相関は書かれていない。
4. **④軸崩壊（`y23`の59%）の大半がモデル軸と公式印の不一致由来**という切り出しは新規
   （§2.3）。これは**読みの精度**（他エージェントの担当領域）に属する話であり、
   買い方をどう変えても解決しない——**買い方設計の担当エージェントには
   「三連複2商品の対象範囲を広げる/相手選びを変える」以外の打ち手は残っていない**
   （②③の合計は入稿できていた分の25%程度しかなく、天井が低い）ことを明示できる。
5. **すでに10万+の3割はこのシナリオ由来**（§2.4）という事実は、
   「新しい一撃商品を作る」動機を弱める——`A_ana`/`F_sign`という**既存の別目的の
   商品が副産物として既にこの需要の多くを満たしている**。新設するなら
   「既存`A_ana`/`F_sign`を置き換えるのか、共存させるのか」を先に決める必要があり、
   `type_a_upset_2026_08_31.md`追補3（§12、3分割の実測）と同じ機会費用の議論が
   そのまま当てはまる。

🔴 **この監査だけでは「新しい買い方を作るべきか」を決められない**（採否はROI/表示的中
のトレードオフで、CLAUDE.mdの検証作法どおり無作為対照・両窓CIが要る＝設計担当の仕事）。
本監査が確定させたのは**土台**（既存はどこまで/どう取っているか）だけ。

## 5. 限界

- **日次上限は未シミュレート**。`cap_priority`（`2×axis_sum + rp_sd`降順で上位半分）
  は日ごとの他レースとの相対順位に依存する状態機械で、per-race純関数では再現できない。
  §3の「入稿ゲート/軸信頼ゲート」通過率は**日次上限をかける前**の数字。実運用では
  ここからさらに絞られる（DESIGN 3.1「半分は意図的に売り残している」）。
- **高額枠（`{B,C,D}_sign`/`_big`・1日5本）も未シミュレート**——同じ理由（日次状態）。
  §1の構造分析（`bust=True`で軸1完全排除）はコードとして確定しているが、実際に
  どのレースへ配られるかは別問題。
- **osaeは現行`OSAE_PLANS=frozenset()`で無効**（2026-09-11時点でユーザーが「様子見」と
  判断済み・`src/type_lab.py`1824-1840行）。有効化された場合の影響は測っていない。
- **`agree`（モデル軸=公式印）は板の`AGREE`列に依存**——AGREEは「モデル上位2車の**集合**が
