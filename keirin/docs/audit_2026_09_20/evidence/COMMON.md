したがって **ドキュメント（CLAUDE.md・docs/・メモリ）の記述は証拠として扱わない**。証拠は ①本番コード（呼び出し元まで辿る）②DB の実データ ③自分で走らせた計算 だけ。

## 絶対ルール
- **読み取り専用**。DB へ INSERT/UPDATE/DELETE/DDL 禁止。git の操作（switch/commit/stash 等）禁止。リポジトリ内のファイルを変更・作成しない。
- スクリプト・中間生成物・レポートは自分の作業フォルダ（各依頼で指定）だけに書く。
- DB は **本番と同居する VPS（メモリ1.9GB）の PostgreSQL**。`keirin.wt_odds`(3,600万行)・`wt_odds_snapshot`(880万行) の全走査は禁止。必ず race_key/日付で範囲を切り、1クエリは1か月分以下、同時に1本だけ、連続実行の間に数秒空ける。まず `data/exp_cache` `data/feature_cache` `data/exp` のローカルキャッシュで足りないか確認する（ただしキャッシュの中身・生成日・生成コードを確かめてから使う）。
- 接続: `zsh -ic 'psql "$KEIRIN_DB_URL" -c "..."'`（`KEIRIN_DB_URL` は ~/.zshrc で export 済み。出力先頭の "Restored session" 行は無視）。Python は `cd /Users/ysuzuki/GitHub/kiseki/keirin && zsh -ic '.venv/bin/python ...'`（src を import するなら keirin をカレントに）。重い学習は Mac で行ってよいが、1本10分を超える計算は事前に規模を見積もって縮小する。
- `race_date` の型がテーブルで違う（DATE / VARCHAR）。race_key は `YYYYMMDD_場_R`。`fetched_at` 等の TZ に注意。
- このリポジトリの作法: **測る前に本番コードを読む**（実際の点数・賭け金配分・母集団・ゲートの例外・学習窓と評価窓の分離）。実験スクリプトの定数を本番の挙動と見なさない。baseline は実データ1件を表示して目視確認する。件数を減らす検証には無作為対照を置く。探索窓と確認窓は年をまたいで分ける。「変わりうる」と「変わっている」を区別し、測ってから言う。
- 過去のバックフィル済み予測値は in-sample の可能性がある（モデルが後から再学習されている）。予測値を使うときは **その予測がいつのモデルで作られたか** を必ず確かめ、確かめられないなら「honest でない可能性」と明記する。
