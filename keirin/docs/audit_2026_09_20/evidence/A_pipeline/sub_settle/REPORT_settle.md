## 1. 実行経路

| 段 | 実体 |
|---|---|
| cron | `5,20,35,50 8-23,0 * * * $KEIRIN_HOME/scripts/type_lab_settle.sh`（`docs/type_lab/RUNBOOK.md:79`） |
| shell | `keirin/scripts/type_lab_settle.sh:22-23` — 前日と当日の **2 本**を実行 |
| python | `keirin/scripts/settle_type_lab_picks.py::main`（`:116`） |
| 当たり目生成 | `keirin/src/result_top3.py::winning_trifectas/winning_trios/representative` を **実際に import して使用**（`settle_type_lab_picks.py:36-38, 149-150, 185`） |
| 日次バッチ側 | `keirin/scripts/type_lab_daily.sh:68,70` も同じ python を前日/当日で呼ぶ |

- **対象日の決め方**: `--date` 1 日ぶんのみ。`race_date = ?`（`:125`）。窓は「今日」と「昨日」だけで、
  **2 日以上前に結果・オッズが遅れて入っても自動では拾わない**（拾う経路が存在しない）。
- **冪等性**: `_load_targets`（`:41-52`）が `settled_at IS NULL AND ...` で絞るので、
  採点済み行は二度と触らない。何度流しても害はない。
- **採点済みの取り直し**: `--redo`（`:121`）のときだけ `settled_at IS NOT NULL` も対象に入る。
  つまり **着順が後から訂正されても既存行は更新されない**（後述 §7 で実測 0 件）。
- 旧実装（`{着順:車番}` 辞書）は残っていない。`grep "finish_order BETWEEN 1 AND 3"` で
  採点経路に残る呼び出し（`notify_results_wt.py`・`sold_performance_report.py:49`・
  `notify_race_result_wt.py:458`）はいずれも `(着順, 車番)` のタプルへ `sorted()` してから
  正本へ渡しており、`[:3]` で畳む実装は見つからなかった。

## 2. 「的中(hit)」の定義

`settle_type_lab_picks.py:147-169`:

```
legs  = jsonb の買い目（combo / stake / pred_odds / prob）
wins  = winning_trios(f) if bet_type=='trio' else winning_trifectas(f)     # 同着なら複数
won_legs = [l for l in legs if l["combo"] in win_strs]
hit   = bool(won_legs)
```

- 表記: 三連複 `1=2=4`（車番昇順）／三連単 `1-2-4`（着順どおり）。`_combo_str`（`:108`）。
- **券種は行の `bet_type` 列**（`trio` / `trifecta`）で決まり、区切り文字から推測していない。
  実データ上も `trio`↔`=`・`trifecta`↔`-` が一致（不整合 0 件）。ワイド等は型ラボには存在しない
  （`bet_type` の値は 2 種のみ）。
- **同着**: `result_top3.winning_trifectas`（`src/result_top3.py:74-101`）が同着グループの
  順列をすべて展開する。`hit_trio()`/`hit_trifecta()` は**使っていない**——これらは 1 目しか
  返さず払戻を取りこぼすため、settle 側で `won_legs` を全部舐めている（`:152-168` のコメントどおり）。
- **3 着までが確定しないレースは採点しない**: `_finish`（`:55-74`）が `winning_trifectas(v)` が
  空のレースを落とし、`main` で `n_wait` に数えて `settled_at` を NULL のまま残す。
- **当たっているのに確定オッズが引けないレースも採点しない**（`:160-165`）。

## 3. 払戻(payout)の取得

- 出どころは **`keirin.wt_odds`**（`bet_type IN ('trio','trifecta')`・`_odds()` `:77-99`）。
  `keirin.wt_race_payouts` は**使っていない**（そもそも `max(collected_at)=2026-07-04` で更新停止・
  中身は odds×100 の同値なので情報量は同じ）。
- `wt_odds` は `UNIQUE(race_key, bet_type, combination)`（`\d keirin.wt_odds`）なので、
  `_odds()` に `ORDER BY` が無くても**非決定性は生じない**。
- 値が「確定オッズ」であることの実測: `20260918_28_08`（発走 14:00 JST）で
  `wt_odds_snapshot` と突き合わせると **h14(14:00) は 266 点中 259 点が現在値と異なり、
  evening(16:04) は 329 点すべて一致**。＝レース後に上書きされた値を使っている。
  （`collected_at` は ON CONFLICT 更新で据え置かれるため初回収集時刻のままで、時刻からは判断できない）
- 計算式: `payout = Σ_{当たった leg} round(stake × odds)`（`:166-168`）。
  **同着で 2 目とも買っていれば両方足す**。
- 単位: `stake` は円（実額）、`odds` は倍率。`budget` 列は **全 114k 行で Σstake と完全一致**、
  `stake=0` の leg も 0 件（SQL 実測）。→ 賭け金と払戻の単位は揃っている。
- 🔴 **kiseki 側の正本（`backend/src/services/keirin_settlement.py:103-114 payout_per_100`）は
  「100 円あたり払戻＝10 円未満切り捨て」**なのに、型ラボ側は `round(stake×odds)` で切り捨てない。
  実測では **live 1,179 的中行すべてで両式の結果が一致**（`wt_odds` の値が実質 1 桁小数のため）。
  潜在的な二重管理だが、現時点の実害は 0 件。
- `final_odds` は「買った当たり目 1 つ」のオッズ。同着で 2 目当たった行では
  `payout ≠ final_odds × stake` になる（実測 4 行・`20260915_13_09` 2着同着 など）。

### baseline（実データ 1 件・目視）

## 4. 「表示的中」とROI

| 指標 | 実装 | 定義 |
|---|---|---|
| 表示的中（Web/API） | `backend/src/api/keirin_type_lab_router.py:507, 623` | `hit AND payout > budget`（`<=` をガミ） |

## 5. 欠車・失格・レース中止

| 事象 | DB の見え方 | settle の挙動 | 評価 |
|---|---|---|---|
| 中止（`wt_races.cancel=1`） | top3 が 0 件 | `_finish` が落とす → **永久に `settled_at IS NULL`** | 集計から丸ごと除外。返還なので実害は小さいが「記録が無い」状態 |
| 落車・失格（`finish_order=0`） | 202609 で 140 行 | 単に 3 着以内に入らないだけ。返還なし | 実際のルールと一致 |
| 欠車（出走取消） | **`wt_entries` から行ごと消える**（`wt_races.n_entries=7` に対し entry 行が 6） | 欠車した車番を含む leg も**全額損失として計上**。返還が反映されない | 🔴 不整合（下記） |

- 🔴 **欠車の返還が計上されていない**。live（08-27〜09-19）で、買い目に
  `wt_entries` に存在しない車番を含む行が **9 行 / 6 レース**。
  返還相当の賭け金は合計 **25,400 円**（例: `20260830_13_06 B_hit` は
  budget 10,000 のうち **9,900 円が返還対象**なのに全損として記録）。
  全体 66,010,000 円に対して 0.04% なので ROI への影響は無視できるが、
  **個別行の勝敗表示は誤り**。
- 落車等で 3 着以内が 3 車そろわないレース（`top3=2`）は永久保留になる
  （paper の `20250519_37_02` / `20250702_11_06` で計 6 行）。実ルールでは返還なので
  「保留」でも集計は歪まないが、明示的な返還扱いではない。

## 確認できなかった点

- `wt_odds` の値が主催者公表の**確定払戻と一致するか**は、外部ソースが無く直接照合できていない。
  確認できたのは「レース後に上書きされた値であること」（発走前スナップショットと不一致・
  レース後スナップショットと完全一致）まで。
- `finish_order=0` が「落車」か「失格」か「欠車」かは DB からは区別できない（`factor` 列は空）。
  欠車の判定は「`wt_entries` に行が無い」で代用した。
- 中止レースが netkeirin で実際に返金処理されたかは DB から追えない。
