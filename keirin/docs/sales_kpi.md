# netkeirin 販売KPI — 売れ筋10位への設計書

> **最終更新**: 2026-08-24
> **目標**: netkeirin 売れ筋ランキング **10位**（現在17位／36人中）
> **前提**: 販売価格は **300pt 据え置き**（`SALE_PRICE_DEFAULT`・変更しない）
> **本書の位置づけ**: 商品構成・入稿対象・的中ターゲットの**指標の正本**。
> 週次で実績を追記し、四半期ごとに目標値を見直す。

## 0. 用語と単位

| 語 | 定義 |
|---|---|
| 有償pt | `netkeirin_sales_race.sold_paid_points`。無償pt利用分を除いた売上。**収益の対象はこれだけ** |
| 個/R | 1レースあたり販売個数（`n_sold`）。**上位陣が握っている唯一の変数** |
| 有償率 | 有償pt ÷ 総pt。実測 78.6%（日により 38〜97% と振れる。netkeirin の無償ptキャンペーンで動く） |
| 表示的中率 | `n_hits_excl_garami` ÷ 入稿数。**払戻＞賭け金のみを的中と数える**（netkeirin の公表値） |
| ガミ | 買い目は当たったが払戻 < 賭け金。表示的中率には入らないが「直近の的中」の看板には出る |
| 高配当系 | 7T1 / 7H1 / 7H2 / 9H1（三連単フォーメーション系） |
| 的中系 | 7S / 7C / 7B / 9C / 7M1（三連複・軸2車系） |
| 収益 | 有償pt × 0.30（`keirin_sales_report.REVENUE_RATE`） |

## 1. 目標の定義

### 1.1 「売れ筋10位」を pt に翻訳する

netkeirin は**他予想家の販売数を一切公開していない**（順位のみ・DOM にも隠し値なし）。
そのため 10位相当の売上は推定値である。

自社の17位＝12,264 有償pt/日 を水準に、売上 ∝ 順位^−α（α = 0.5〜0.7）を当てた推定:

| 売れ筋 | 有償pt/日 | 収益/日 |
|---|---|---|
| 1位 | 50,000〜86,000 | 1.5万〜2.6万円 |
| 5位 | 23,000〜30,000 | 0.7万〜0.9万円 |
| **10位（目標）** | **16,000〜18,000** | **約5,000円** |
| 17位（現在・実測） | 12,264 | 3,679円 |

**運用目標値 = 有償 17,000pt/日**（週 119,000pt）。現状比 **+38.6%**。

🔴 **この 17,000 は推定であって測定ではない。** α とライバルの販売価格という2つの
未知数に依存する。**§8 の週次記録で自社の pt と順位の対応を蓄積すれば、
半年で推定を実測に置き換えられる。それが本書を継続更新する最大の理由**である。

### 1.2 なぜ10位か

- 3万pt/日（当初目標）は推定で**売れ筋3〜5位**に相当する。64週連続1位の Mr.T や
  お気に入り5,000人級と同じ土俵で、お気に入り103人の現状からは現実的でない
- 10位は現状から**3〜5ランク**。かつ収益5,000円/日の要求（16,667pt/日）とほぼ一致する

## 3. KPIツリーとギャップ

```
有償pt/日 = 入稿R/日 × 個/R × 300pt × 有償率0.786
17,000    = R × (個/R) × 235.8
          → R × (個/R) = 72.1 個/日
現状        47.3 × 1.10  = 52.0 個/日        ← ギャップ +20.1個/日（+38.6%）
```

到達経路は3つしかない:

| 経路 | 入稿R/日 | 個/R | 判定 |
|---|--:|--:|---|
| A 現状本数のまま質を上げる | 47 | 1.53 | 可（+39%） |
| B 絞って質を上げる | 36 | 2.00 | **推奨**（無売上率も改善） |
| C 本数を増やす | 66 | 1.10 | ❌ **先週これをやって失敗した** |

## 4. 何が個/R を決めているか（実測）

### 4.1 商品系統（8/03〜08/23・21日・736R の日次回帰）

```
有償pt/日 = 2,705 + 775 × 高配当系R + 121 × 的中系R
corr(高配当系R, 有償pt) = +0.759   corr(的中系R, 有償pt) = +0.455
```

**高配当系1本 ＝ 的中系6.4本。** 現状は 高配当系 6.0本/日・的中系 29.0本/日。

## 6. 運用基準（この4つを本書の指標とする）

### 6.1 販売すべき予想レース数

**1日 36〜43本**（現状 47.3本）。

- 上限を設けるのは、先週 47.3本で個/R 1.10・無売上54% になったため
- 下限を設けるのは、回帰係数（高配当775 / 的中系121）がどちらも正で、
  本数を削ること自体は売上を減らすため。**削るのは "売れない対象" だけ**

### 6.2 対象（どのレースに出すか）

**出す（優先度順）**

1. 決勝・準決勝（相対1.43 / 1.26）
2. GI 開催の全レース（相対1.21・無売上28%）
3. モーニング（〜10時）とミッドナイト（20時〜）の全帯（相対1.19 / 1.17）
4. 特選・選抜（相対1.08）

**原則出さない**

- **予選 × デイ/ナイター帯**（相対0.56 × 0.85〜0.89・無売上53%）。
  8月の無売上307件のうち89件がここ。売上への寄与は 194pt/R で、
  当たると「直近の的中」の看板を平均16,833円で塗り替えるという副作用まで持つ
- 例外: 予選でも **7H2/7T1 の候補になっているレースは出す**。
  高配当系は種別の影響を受けにくく、pt/R が 4〜5倍違う

### 6.3 的中時のターゲット条件

netkeirin のレース予想一覧は各予想家の**直近の的中の払戻金を1枠だけ**表示し、
当たるたびに時系列で上書きされる。2026-08-24 実測の他13者の中央値は **22,440円**。

| 指標 | 目標 | 現状 |
|---|---|---|
| 的中1件あたり払戻 **中央値** | **22,000円 以上** | 15,335円 |
| ガミ率（払戻 < 賭け金） | **5% 以下** | 18.5% |
| 月に1回以上 | **10万円超の的中** | 8月は2回（8/16・8/17 いずれも7T1） |

商品別の到達状況（2026-08-17〜23 の的中中央払戻）:

| ランク | 中央払戻 | 判定 |
|---|--:|---|
| 7T1 | 212,160 | ✅ |
| 7H1 | 70,500 | ✅ |
| 7B | 25,290 | ✅ |
| 7M1 | 23,410 | ✅ |
| 7C | 19,530 | △ |
| 9C | 15,190 | ❌ |
| **7S** | **14,670** | ❌ **入稿の52%を占める最大の商品がここ** |

🔴 **7S の的中中央値を上げないと、看板は改善しない。** 7S は的中頻度が高い
（171R で68件的中）ため、たまに出る 7T1 の20万円をその日のうちに何度も塗り替える。
実例: 8/16 の 176,500円 と 8/17 の 212,160円 は**どちらも同日中に消えた**。

### 6.4 的中率

| 指標 | 目標 | 根拠 |
|---|---|---|
| 表示的中率 | **20% 以上** | 売れ筋1位の Mr.T が 20%。20%あれば売上1位は取れる |
| 想定着地 | 23.4% | 高配当系14本＋的中系29本の構成での試算（下記） |

```
表示的中率 = (14本 × 5.0% + 29本 × 32.3%) ÷ 43本 = 23.4%
（高配当系の表示的中 4.9% / 的中系 32.3% はいずれも 08/17-23 の実測）
```

現状28.9%から **−5.5pt** 落ちるが、14者中では依然3〜4位相当。
**20%を割ったら高配当系の本数を戻す**、というのが停止ラインになる。

## 7. 移行計画（段階的に・毎週測る）

係数775が本数を増やしても保たれる保証はないため、一度に14本へ増やさない。

| フェーズ | 高配当系/日 | 的中系/日 | 合計 | 予測 有償pt/日 | 見るもの |
|---|--:|--:|--:|--:|---|
| 現状 | 6.0 | 29.0 | 35.0 | 11,038（実測） | — |
| **P1**（1〜2週） | 9 | 27 | 36 | 12,900 | 高配当系の pt/R が 800 を維持できるか |
| **P2**（3〜4週） | 12 | 24 | 36 | 14,900 | 表示的中率が20%を割らないか |
| **P3** | 15 | 21 | 36 | 16,900 | 売れ筋順位が10位台前半へ動くか |

各フェーズで **高配当系の pt/R が 600 を下回ったら次へ進まない**
（希釈が始まった合図。6.0本時点の実測は 873〜1,011）。

**実装上の前提（別 PR）**

1. `7H2` / `9H1` の `netkeirin_settings.enabled` を有効化する
2. `RANK_7T1_DAILY_CAP = 5` の引き上げを検討する（候補は4.9件/日でほぼ上限に張り付いている）
3. 予選×デイ/ナイターの的中系を入稿対象から外す
4. 7S の配分に着地下限を入れる（ガミ18.5%と的中中央15,335円の同時改善）

⚠️ 1〜3 はいずれも「1レース1商品」の取り合いを通じて相互に影響する。
**同時に入れると効果を分離できない。1つずつ、1週間ずつ。**

### 11.6 平均払戻ゲートの自動化（2026-08-24 ユーザー判断）

> 「本日見る限り、手動の安い配当取り消しは他同様に自動として良さそう」（2026-08-24）

これは `tests/test_min_mean_payout_gate.py` の冒頭に記録されている
**「🔴 自動では落とさない。人が確認して一括取消する（2026-08-24 ユーザー指定）」を
同日中に上書きする判断**である。テストの docstring とアサーションを
**新しい判断に書き換える**こと（消すのではなく反転させ、日付と理由を残す）。

#### 11.6.1 🟢 自動化は手動より売上が増える（設計上の副作用）

ランク自動入稿ループのゲートは **`continue` で抜ける**規約になっている:

> 🔴 **`continue` で抜けること。** ここで「処理済み」にすると 1レース1商品の
> 取り合いで後続ランクがそのレースを取れなくなる。落としたいのはこのランクの
> 商品であって、そのレース自体ではない。（`netkeirin_submit_wt.py` L1964）

つまり **自動化すると、安い三連複が落ちた枠を後続ランクが自動的に拾う**。
手動取消は「取消 → 枠が空く」で終わるが、自動化では差し替えが無料で付いてくる。

- 実効の優先順位は 7S > 9C > 7B > 7C > **7T1 > 7H1** > 7M1
- **7T1 / 7H1 は三連単経路なのでゲートの対象外**（必ず通る）
- §11.2 の実測で、取消対象230件のうち 31%（72件）に高配当系の候補がある

→ 期待効果: 約2.9件/日 が 130pt/R の三連複から **808pt/R の三連単へ置き換わる**（+2,300pt/日）。
**これで打ち手 H（差し替えUI）は不要になる。**

#### 11.6.2 🔴 看板穴埋め経路にはゲートが1つも入っていない

`stake_allocation.py` の記述:

> 🔴 **看板レースにも掛ける**（2026-08-24 ユーザー判断）。
> ゲートは2箇所に入っている（片方だけだと看板が素通りする）:
> `netkeirin_submit_wt.py` のランク自動入稿ループ と `_process_manual()`

**実装を読むと、これは事実ではない。** `_process_manual()`（＝看板穴埋めの入口）には
**3つのゲートがどれも入っていない**:

| ゲート | ランク自動入稿ループ | `_process_manual()`（看板） |
|---|---|---|
| `MIN_POINT_ODDS`（1点2倍未満） | ✅ L1979-1988 | ❌ **無し** |
| `MIN_EXPECTED_PAYOUT_BY_RANK`（下限倍率） | ✅ L1989-1997 | ❌ **無し** |
| `MIN_MEAN_PAYOUT`（平均2万円） | ❌ 無し | ❌ **無し** |

経路: `submit_marquee_wt.py` → `subprocess` → `netkeirin_submit_wt.py --marquee
--manual-rank-key ...` → `_process_manual(..., marquee=True)`。

🔴 **看板穴埋めは 240/562 件 ＝ 実入稿の43%**（`stake_allocation.py` の実測表）。
ここを通さないと、平均払戻ゲートは**対象の半分以下にしか効かない**。
`_process_manual()` にも同じ判定を入れること。

⚠️ **`MIN_POINT_ODDS` と `MIN_EXPECTED_PAYOUT_BY_RANK` を看板へ広げるかは別問題**で、
本件のユーザー判断には含まれていない。**勝手に広げないこと**（母集団が変わり、
「看板レースには必ず推奨を出す」という 2026-08-09 の決定との衝突範囲も変わる）。

#### 11.6.3 自動化で失う可視性と、その手当て

手動取消は `netkeirin_submissions.status='deleted'` の行を残すので
**Web からも DB からも「何件落としたか」が見えた**。自動化すると入稿自体が
行われないので、**この痕跡が消える**。ゲートが壊れても誰も気づけない状態になる。

最低限の要件:

1. `MIN_POINT_ODDS` と同じ形式の1行ログ（`[netkeirin_submit] スキップ ... 平均払戻 X円 <= 20,000円`）
2. **実行サマリーに見送り件数**を出す（0件が続いたら壊れている合図）
3. 日次 Discord 通知に「安い配当で N 件見送り」の1行

⚠️ `netkeirin_submissions` に新しい status 値（`skipped` 等）を足すのは**推奨しない**。
`_already_submitted()` と各所の status フィルタに波及し、
オッズが後から取れて再入稿すべきケースを恒久的に塞ぐ。

#### 11.6.4 レビュー画面の一括取消は残す

`mean_expected_payout` は**オッズが1点でも欠けたら None を返して入稿側へ倒す**設計なので、
朝の時点でオッズが揃わなかったレースは自動ゲートを素通りする。
レビュー画面で後からオッズが揃えば判定できるので、**UI は保険として残すこと**。
自動化後は表示件数が大きく減るはずで、**減らなければ自動ゲートが効いていない合図**になる。

### 11.7 公開時刻（後日の検討材料）

入稿は毎日 07:08〜07:10（朝）と 18:00（夕）。公開はそのあと人が押す。
2026-08-24 の実測で自社の公開は **07:17**、競合は Mr.T 前夜23:45 / 二ノ輪・LONEFOX 00:31 /
シュウ系 03:54 / Aiライン極 04:31 で、**露出時間に3〜7時間の差**がある。

個/R がボトルネックである以上これは効きうるレバーだが、
**朝バッチを前倒しできるかは出走表・並び・予測オッズの可用性次第**で未確認。
⚠️ ベースライン週には入れないこと（個/R を直接動かすので測定が濁る）。
