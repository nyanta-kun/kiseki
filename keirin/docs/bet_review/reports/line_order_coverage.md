# ライン内の前後の入れ替わり（S/H/B）は既に入っているか（2026-10-05・読み取り調査）

ユーザーの問い: 「ラインの実際の前後は戦法・能力で入れ替わり、結果は S/H/B で確認できる。
これを予測できればラインの前後・決着を予想できる。既に含まれているか」。
根拠はコードと文書のみ（ローカル DB は空のため実測なし）。パスは `keirin/` 起点。

## データ

| 種類 | 列 | 出どころ |

| 発走前の累計 | `s_count` / `h_count` / `b_count`、決まり手累計 `front_runner`(逃げ) / `deep_closer`(捲り) / `stalker`(差し) / `marker`(マーク) | `src/scraper/winticket.py:315-325` |

## (a) 既に含まれている

- 選手の S/B/上がりの傾向: `s_count`・`h_count`・`b_count`、`b_rate_90`・`s_rate_90`・`fh_rel_90`・`fh_best_rate_90`（過去90日・`feature_wt.py:844-965`）
- ラインの前後の推定: `formation_pos_frac`・`formation_line_rank`（ラインの前後を `b_rate_90` の最大で並べる・`feature_wt.py:573-649`）
- ラインの構造・強さ: `line_size`・`line_pos`・`is_line_leader`・`n_lines`・`is_isolated`・`line_frac`・先頭/番手の得点・ライン実力5特徴
- 確率の補正: 同ライン直後が来やすい λ=2.0 / μ=1.5（`src/strategy_wt.py:4567`）、番手が先頭を差す向きの λr=1.9（並べ替えの評価のみ・`strategy_wt.py:4589`）
- 買い目の入れ替え対応: `line_swap`（`src/type_lab.py:2515`）・`order_swap`（`type_lab.py:2609`）・`add_perm`（`type_lab.py:2767`）

## (b) 含まれていない

1. **「このレースのこの並び・相手で、誰が前に出るか（S/B を取るか）」「ライン内の着順が入れ替わる確率」を発走前に予測する専用のモデル**。
   近いのは `b_rate_90` による並びの推定だけ（選手の過去率であって、その日の相手との組み合わせではない）
2. S/H/B の選手別傾向を**その日の相手・並びとの組み合わせ**で使うこと（例: 同じレースに B 率の高い先行が2人いるときに誰が取るか）。該当する検証は見つからなかった
3. 決まり手累計4列（未使用。ただし自前集計 `km_*` は `b_rate_90`・`style_enc` と冗長で ΔAUC ±0.0001 だった）

## 未検証で残る筋（事前登録が要る）

レース後の実績 `res_standing`（S）/ `res_back`（B）を**目的変数**にして、「このレースで誰が S/B を取るか」を
発走前の情報（その日の相手の S/B 傾向・並び・脚質）から予測するモデルを作り、
その予測を (1) 隊列推定（現在は `b_rate_90` の最大で並べている）の置き換え、(2) 三連単の位置別確率の入力に使う。
(c) の否定はいずれも「選手の過去率をそのまま足す／条件で分ける」形で、
**「その日の組み合わせで S/B を取る人」を予測してから使う形は試されていない**。
ただし一般則（市場と同じ向きの分類器は ROI にならない）に照らすと、市場（並び予想・記者予想を見て買う）が
既に織り込んでいる可能性が高い。検証はまず「予測した B 取りが、最終オッズに対して1-2着の発生倍率を動かすか」の
停止判定から始めるのが筋。
