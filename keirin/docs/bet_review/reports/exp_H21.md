## 実装の決め（走らせる前に固定したこと）

走らせる前に決めたこと。事前登録（README）が決めていない点はここで決めた。**②③の ΔROI を見る前に決め、見たあとで動かしていない**（腕ごとの回収率の一行だけは動作確認で先に見た。**主表を見たあとに足したもの**: 三連複を畳む感度 `A2f/A3f`・§2.3b（スナップショットが無い28日を除く前半）・§2.6（高額払戻の上位k行を除く）・§1.1 の「取れなかった理由」。いずれも記述で、判定には使っていない）。

1. **オッズが入る場所（`src/type_lab.py`・本番コードを読んで書き出した）**。DB を読む経路は無く（`wt_odds` / `snapshot` / `predicted_*board` / `get_connection` の参照が 0 件）、すべて `pred_odds` 引数で受ける。引数を差し替える1点（`lineup_sim.Ctx.po_tf` / `po_t3`）で次のすべてに効く:
   - 買い目の選択: `build_legs`（`min_odds` の帯・`sigma_max` / `cap = 予算÷計画払戻` に対する Σ1/オッズの枠・看板枠の `max_odds`・`axis2_drop_fav` の人気順・`line_axis2_flow` の枠・`prob_top` の枠）、`_insert_underband`（帯の下の最安の1点）、`line_lead_legs` / `flat_lead_legs` の `c in pred_odds`
   - 絞り・追加: `apply_cheap_target`（`cheap_share`＝予測5倍未満の確率）、`_tau_adaptive_legs`、`apply_line_swap`（`LINE_SWAP_MIN_ODDS`=10）、`apply_order_swap`、`apply_osae`（無効）、`apply_add_perm`、`add_upper_band` / `_upper_legs`（`UPPER_BANDS = ()` で現状は無効＝掛からない）
   - 配分: `allocate` / `_allocate_once`（`dutch`＝賭け金∝1/オッズ・`conf`＝floor が 予算×floor_mult÷オッズ）
   - ゲート: `build_with_gate_fallback` と `GATE_FALLBACK` / `ALLOC_BEFORE_MIN_PAYOUT`（平均想定払戻 > 20,000円）、入稿ゲート `gate_ok`（平均想定払戻 > 20,000円 ∧ 最小オッズ ≥ 2）、A_trio の `trio_ok`（`sell_plans_for` の入力）
   - オッズを見ないもの: 軸信頼ゲート（`passes_axis_gate`）・日次上限の優先度（`cap_priority`）・高額枠の割当・L_lead の除外判定
2. **腕の作り方**: 日次ラインナップ全体（軸信頼ゲート → 入稿ゲート → 日次上限（枠外を除く判定対象×0.5）→ 高額枠5本 → L_lead 段）を `alloc_common.run_day`（本番の入稿経路の写し）で組む。①②③は**板だけ**が違い、p3/pw・出走表・結果・最終オッズは共通。
3. **売れていない組（`odds_value` ≥ 9999）**: 板に載せない（数値として入れない）。9999 を入れると平均想定払戻が跳ね、ゲートを誤って通る。載せないので `_pos(...)` で候補から自然に落ち、買い目が組めない商品が出るのは**実オッズ化のコストとして ΔROI に含める**。有効な三連単が60組未満の板は台の組み立て下限（`lineup_sim.ctx`）なので使えず ① のまま（② 18R・③ 10R）。感度として「有効組 ≥90%の板だけ実オッズ（他は①）」を併記（`A2s90`/`A3s90`・R3 と同じ切り方・判定には使わない）。
4. **三連複のオッズ**: 主腕は**実三連複スナップショットをそのまま使う**（②③の使用レースは全て三連複の板もある・有効組の中央値 35/35）。感度として、本番の導出（三連単の板を畳む）を実三連単の板に当てた版（`A2f`/`A3f`）も出す。実三連複 ÷ 畳んだ値は中央値 0.96（p10 0.51・p90 1.8）。A_trio の件数は主腕 387行・畳む版 379行でほぼ同じ（①は104行）なので、商品の切替（A_hit → A_trio）は三連複スナップショット由来ではなく**三連単の実板**由来（§2.2b）。
5. **①の予測板**: ≤08-04 は台の `PO`（本番 `odds_tf_n7`・学習終端 2025-12-31）、08-05〜は `odds_prediction_tf.predict_board(出走表, p3/100, pw/100)`（`data/models/odds_tf_n7.txt`＝本番モデル）。**台の `PO` を同じ関数で再現できる**ことを確かめた（70レース・相対差の最大 5.9e-8・§9）。
6. **p3/pw の出所（事前登録の「DB に朝書かれた値」は使えない・08-05〜は混在）**: ≤08-04 は、`wt_entries.pred_*_pct` が月次 vintage のバックフィル（`backfill_index_pct_wt.py`）で書き換わっていて、台の P3（`type_lab_picks` の paper と並び・axis_sum が完全一致する出所）とは別物（上位2車の並びの一致 45%）。**台を使う**。08-05〜: `wt_entries.pred_top3_pct / pred_win_pct`（0.1%刻み）を使う。この列は**日によって出所が混ざっている**: live の `type_lab_picks`（08-27〜・朝に焼き付けた並び）との並び一致が 09-23 0.97 / 09-24 1.00 / 09-27 1.00 / 09-30 0.98 / 10-03 1.00 の日は**バックフィルがまだ上書きしておらず、朝の live 値が残っている**と読め、それ以外の日は 0.49〜0.88（全体 72.4%）で月次 vintage に上書き済みと読める（paper 08-05〜26 とは 90.6% 一致）。どちらも学習はレース日より前（live モデルは 09-21・月次 vintage は前月末まで）なので**リークは無い**が、①②③は同じ値を共有するだけで、**①は実際に売った買い目を再現しない**（§9）。日別の一致率は §10。
7. **結果**: 着順は `wt_entries.finish_order` から `src/result_top3` で当たり目を決め、同着は代表1通り（59R・全腕共通）。払戻 = 最終オッズ（`wt_odds`）× 賭け金。台の `WIN` との不一致は 2,812R 中 26R（同着の代表の違いと推測・払戻は他の 2,786R すべて一致）。
8. **時間帯**: **レースの発走時刻（JST）**で 朝 <12:00 / 昼 12:00〜14:59 / 夕 15:00〜17:59 / 夜 18:00〜。第1R基準の開催区分（`meeting_band`）とは別物（スナップショットの被覆が発走時刻で決まるため）。
9. **統計**: ΔROI = 腕の回収率 − ①の回収率（Σ払戻/Σ投資・同じ開催日の添字を両腕へ）。前半/後半は各半分の日で別に BS。表示的中 = 払戻 > 投資の行 / 売った行。10万+/日 = 払戻 ≥10万円の行 ÷ 120日。的中時払戻の中央値 = 払戻 > 0 の行。

- **前半/後半の境（2026-08-04）は p3/pw の出所が変わる境**（台 → DB の月次 vintage）。さらに前半の 28日（06-17・06-19〜07-15）はスナップショットが無く ②③ = ① のまま。符号の割れ（前半 +3.5 / 後半 −3〜−4）は「効果が不安定」とも「入力・被覆が違う」とも読め、このデータでは分けられない。

- **「120分前」「60分前」は目安**: 規則どおり「その時刻以前の最後の1枚」を使うため、板の取得は発走の 130〜239分前（②・p10〜p90・中央 184分）／77〜200分前（③・p10〜p90・中央 133分）。スナップショットは 07:04（morning）・10:00 / 12:00 / 14:00 / 16:04（evening）/ 18:00 / 20:00 の固定格子で、朝のレースは 07:04 の morning 板になる（②で morning を使った 1,055R の有効組は p10/中央/p90 = 141/197/210 で、**38% が有効組 90% 未満**。③の 963R は 166/206/210・20%が90%未満。他の種別は 6%・2% が90%未満）。
