# netkeirin 売上レビュー（2026-08-19）

対象: `keirin.netkeirin_sales_race` の全データ（**2026-08-01〜08-18 / 509レース**）。
主眼は直近1週間 **2026-08-12〜08-18（265レース）**。売上はすべて
**`sold_paid_points`（販売*有償*pt）**。的中は **含ガミ `n_hits_incl_garami`** と
**除ガミ `n_hits_excl_garami`（＝netkeirin の表示的中率）** の両方を併記する。

---

## 結論（3〜5行）

1. **売上を分けている頑健な要因は「レースの性質」ではなく「そこへ何の商品を置いたか」**。
   高配当系（7T1/7H1/7H2/9H1/7SS）は的中系（7C/7S/7A/7B/9C/9A/9S）の **2.8倍売れる**
   （相対購入指数 2.03 vs 0.73・無売上率 10% vs 39%）。一方その表示的中率は **9.8% vs 29.6%**。
2. **グレード・時間帯・看板/非看板で見えた売上差は、ほぼ全部この商品配置の反映**。
   的中系だけに絞ると GI も看板もモーニングも優位が消える。**唯一残るのは「通常予選は売れない」**
   （相対 0.56・無売上率 46%）だけ。
3. **「当たった翌日は売れる／売れた日に当たっている」という関係は観測できない。**
   ラグ0/1/2 の相関はどれも n=14〜18 で有意水準に届かず、符号も窓の取り方で反転する。
   前日の的中率で層別した翌日の 1Rあたり購入数は 1.94 / 2.15 / 2.14 とほぼ平坦。
4. **需要の総量は曜日で決まり、出品数を増やしても総需要は増えない**（1日のR数 × 総購入数 r=+0.15、
   × 1Rあたり購入数 r=**−0.48**）。土曜 5.00購入/R に対し水曜 1.08購入/R。
5. ただし **全データが18日・n=509 しかない**。ここに書いた区分別の数字は、通常予選と商品系統以外は
   すべて「今後の確認待ち」であり、単独で採否を決められるものではない。

- **「当たった翌日は売れる」は観測されない。** lag1 の相関はどれも |r| ≤ 0.37 で有意でなく、

  よく売れる日＝土日・お盆の高需要日で、そこには 7T1（表示的中率 3.6%）が集中して置かれている。
  つまり**その日の商品ミックスの反映**であって、時間の前後関係を含んでいない。

## 8. 言えること / 言えないこと

### 言える（両方の窓で・交絡をそろえても向きが変わらなかったもの）

- **高配当系の商品（7T1/7H1/7H2/9H1）は的中系より 2〜3倍売れる。** 無売上率 10% vs 39%。
  日効果を除いた指標でも、同日・同層内の直接比較（9/10対で正）でも成立する。
- **7C は最も出品数が多く最も売れない**（無売上率 49%・pt/R 171）。表示的中率は最上位グループ。
- **通常予選（接頭辞のない「予選」）は売れない。** 商品系統をそろえても相対 0.56、無売上率 46%。
- **開催1日目は売れない**（相対 0.81・無売上率 43%）。
- **需要の総量は日（曜日・お盆等）で決まり、出品数を増やしても総需要は増えない。**
- **売れるレースと当たるレースは同じではない**（レース単位の相関 −0.09〜−0.17）。
  ただし回収率では高配当系 0.649 / 的中系 0.634 と差が無い。

### 言えない（この窓では判断できない）

- **「当たった翌日は売れる」／「売れた日に当たっている」。** ラグ1の相関は有意でなく符号も不安定。
  前日的中率で層別した翌日の売れ行きも平坦。**肯定も否定もできない**（日次データが18点しかない）。
- **グレード（GI/FI/FII）そのものの売上効果。** 直近週の GI は松山1開催・9車のみで、
  会場・車立てと完全に交絡している。
- **看板レース／時間帯そのものの売上効果。** 7T1 を除くと符号が反転する（看板 1.05→0.75、
  ミッドナイト 1.01→0.48）。「枠が良い」のか「そこに置いた商品が良い」のかを分離できていない。
- **会場別の良し悪し。** 31会場を走査した両端であり、n が一桁〜十数。多重比較の範囲。
- **7T1 の効果が持続するか。** 08/13 稼働で6日ぶんしかない。新商品の初期効果と区別できない。
- **売上と収益の関係。** 有償pt比率が日により 37.8%〜96.7% と振れる。購入者数が増えても
  有償ptは比例しない（08/13-15 の購入急増時に比率が 38〜43% へ低下）。**購入数を KPI にすると収益とずれる。**

### 次に確かめるなら

1. **7T1 の持続性** — 4週たってから同じ日内マッチ比較をやり直す。ここで平均差が
   +2.65 のままなら商品効果、縮むなら新商品効果。
2. **通常予選への出品を減らす**（無売上率 46%・相対 0.56）。ただし出品を減らしても総需要は
   変わらない可能性が高い（§6）ので、「別の枠へ振り替えたときに総購入数が増えるか」を見る必要がある。
3. **的中との前後関係は最低でも 2〜3ヶ月ぶんの日次データが要る。** 現状 n=17対では
   r=0.5 未満を検出できない。今のデータで採否を決めないこと。

`extract.sql`:

```sql
WITH submission AS (
    -- PK は (race_key, rank_key) なので 1レース複数行になりうる。
    -- 生きている入稿を優先し、同じなら新しい方へ畳む（keirin_router と同じ規則）。
    SELECT DISTINCT ON (netkeirin_race_id)
           netkeirin_race_id, rank_key, origin, deleted_at, submitted_at, status,
           is_confident, bet_detail
    FROM keirin.netkeirin_submissions
    WHERE netkeirin_race_id IS NOT NULL
    ORDER BY netkeirin_race_id, (deleted_at IS NULL) DESC, submitted_at DESC
),
nrank AS (
    SELECT netkeirin_race_id, count(*) AS n_sub_rows
    FROM keirin.netkeirin_submissions WHERE netkeirin_race_id IS NOT NULL
    GROUP BY 1
),
meeting_first AS (
    -- 開催（日×会場）の第1R発走時刻。種別への変換は keirin_meeting.py に任せる。
    SELECT replace(race_date,'-','') AS ymd, venue_id, MIN(start_at::bigint) AS first_start_at
    FROM keirin.wt_races
    WHERE start_at IS NOT NULL AND start_at <> ''
    GROUP BY 1,2
),
candidate AS (
    -- picks_history.race_key は '20260801_13_05#7C' とランク接尾辞つき。
    -- ランク名で等値結合してはいけない（看板の穴埋めは 7A/9A を名乗る）。
    SELECT split_part(race_key,'#',1) AS base_key,
           string_agg(DISTINCT replace(rank,'RANK_',''), ',' ORDER BY replace(rank,'RANK_','')) AS detected_ranks
    FROM keirin.picks_history
    GROUP BY 1
)
SELECT s.race_id, s.race_date, s.venue_code, v.name AS venue_name, s.race_no, s.race_key,
       s.race_label,
       s.n_sold, s.sold_points, s.sold_paid_points,
       s.n_predictions, s.n_hits_incl_garami, s.n_hits_excl_garami,
       s.stake_amount, s.payout_amount, s.avg_sold_hour, s.avg_sold_minutes,
       sub.rank_key, sub.origin, (sub.deleted_at IS NOT NULL) AS is_deleted,
       sub.status AS sub_status, sub.is_confident, sub.submitted_at,
       nr.n_sub_rows, c.detected_ranks,
       w.cup_grade, w.grade AS class_grade, w.race_type, w.n_entries, w.day_index,
       w.cup_name, w.start_at, m.first_start_at
FROM keirin.netkeirin_sales_race s
LEFT JOIN keirin.venue_info v      ON v.venue_code = s.venue_code
LEFT JOIN submission sub           ON sub.netkeirin_race_id = s.race_id
LEFT JOIN nrank nr                 ON nr.netkeirin_race_id = s.race_id
LEFT JOIN keirin.wt_races w        ON w.race_key = s.race_key
LEFT JOIN meeting_first m          ON m.ymd = s.race_date AND m.venue_id = s.venue_code
LEFT JOIN candidate c              ON c.base_key = s.race_key
ORDER BY s.race_date, s.race_id;
```

### C. 集計スクリプト

`races.csv` を入力に、以下の本番モジュールを import して集計した
（判定を写経せず正本を呼ぶ）:

- `backend/src/services/keirin_marquee.py` … `is_marquee_race` / `is_big_event_race`
- `backend/src/services/keirin_cup_grade.py` … `grade_label`
- `backend/src/api/keirin_meeting.py` … `meeting_type_of_first_hour` / `first_hour_jst`
- `backend/src/services/keirin_sales_analysis.py` … `pearson`（`MIN_SAMPLES_FOR_CORRELATION=5`）
- 売上金額換算 `backend/src/services/keirin_sales_report.py::REVENUE_RATE = 0.30`

主な定義:

```python
# 相対購入指数 = そのレースの購入数 ÷ 同じ日の1Rあたり購入数（日効果の除去）
byday = {d: sum(n_sold of day d) / len(races of day d) for d in days}
rel   = n_sold / byday[race_date]

# 商品系統
HIGHPAY = {"7T1", "7H1", "7H2", "9H1", "7SS"}
HIT     = {"7C", "7S", "7A", "7B", "9C", "9A", "9S"}

# ラグ相関（日別）
lag_corr(x, y, lag) = pearson([D[days[k]][x] for k in range(len(days)-lag)],
                              [D[days[k+lag]][y] for k in range(len(days)-lag)])
```

⚠️ 本レビューは **SELECT のみ**で実施した。`netkeirin_sales_*` /
`netkeirin_submissions` / `picks_history` への書き込みは一切行っていない。
