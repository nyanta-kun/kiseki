## ① 市場のペア同時確率（不採用）

二軸的中 =「2車がともに3着以内」は **ワイドの的中条件と完全に同じ**。
`1/オッズ` を正規化すれば市場のペア同時確率が直接取れる。
候補はモデル上位4車の6ペアに絞る（全21ペアを要求すると n が 1/4 になる）。

| 板 | 現行(p3上位2) | 市場最有力 | 混合 w=0.2 |
|---|---|---|---|
| morning (n=816) | 55.39% | −3.06pt | +0.86pt ±0.86 |
| h12 (n=1,031) | 54.61% | −1.45pt | +0.10pt ±0.72 |
| h14 (n=924) | 53.46% | −2.81pt | +0.22pt ±0.80 |
| h18 (n=786) | 52.54% | −0.13pt | +1.27pt ±0.76 |

🔴 **4つの板すべてで市場が負ける。** 混合しても差は 1SE 以内。
→ 天井 +2.62pt は**最終オッズ由来**で、入稿時刻の板にその情報は無い。層2の期待値を
   この数字で見積もるのはやめる。

⚠️ 朝の板は発走の近いレースしか埋まらないため、母集団が朝一番の開催へ偏る。

## ② レース選別のメタ化（採用候補）

現行 7C のゲートは `pred_top3_pct 上位2車の合計 >= 1.44` という**1次元**。
二軸的中を目的にしているなら、その事象を直接学習したほうがよい。

### 設計（リーク無し）

| 段 | 窓 |
|---|---|
| 層1 学習 | 2023-07〜2024-12 |
| **メタ学習** | 2025-01〜06（層1の out-of-sample 予測で作る） |
| 評価 | VAL 2025-07〜2026-02 / TEST 2026-03〜07-15 / **確認窓 2026-07-16〜08-18** |

### 結果（本番相当の採用件数で比較・二軸的中の差）

| 特徴 | VAL (8,291R) | TEST (4,956R) | 確認窓 (1,002R) |
|---|---|---|---|
| 2特徴 `sum2,gap23` | +0.11 [−0.23,+0.45] | +0.24 [−0.18,+0.73] | +0.40 [−0.60,+1.70] |
| 3特徴 `+same_line` | +1.35 [+0.86,+1.80] | +1.03 [+0.38,+1.65] | +1.00 [−0.50,+2.50] |
| **4特徴 `+p_ent`** | **+1.83 [+1.34,+2.40]** | **+1.21 [+0.56,+1.88]** | **+2.40 [+0.60,+3.99]** |
| 8特徴 | +2.01 [+1.46,+2.57] | +1.55 [+0.89,+2.26] | +2.30 [+0.50,+4.09] |

選別指標としての AUC は `sum2` 0.667/0.674 → 4特徴 0.688/0.686/0.699。
**4特徴で 8特徴の 9割が取れる。** 使うのは:

| 特徴 | 意味 | 係数の向き |
|---|---|---|
| `sum2` | p3上位2車の合計（＝現行のゲートそのもの） | + |
| `gap23` | **2位と3位の差**（軸2が本当に2番手か） | + |
| `same_line` | **軸2車が同ライン** | + |
| `p_ent` | レース全体の混戦度（p3のエントロピー） | − |

🔴 `gap23` と `same_line` が現行ゲートの穴。`sum2` は「上位2車がどれだけ強いか」しか
見ておらず、**2位と3位が僅差でも通ってしまう**。外れの主因が「軸2だけ来ず」
（7車 26.8%・`keirin_axis_miss_anatomy_2026_08_17`）だったのと整合する。
`same_line` が独立に効くのは、ペア相関（同ライン）を**選別側で**拾えるということ。

効くのは本番の運用点（採用 50〜60%）。深く絞る用途には使わないこと。

## 決めたこと

- **軸の選び方は変えない**（p3上位2車のまま）。ペア単位で選び直す案（層2-lite）は
  単体では二軸 +1.2〜2.5pt 出るが、**このゲートを通した母集団では上積みが +0.1〜0.4pt**
  しか残らない（ゲートと情報が重複する）。2つ同時に変えない。

  | | 現行軸 | ペア軸 |
  |---|---|---|
  | 現行ゲート | 63.05 / 64.40 / 66.40% | +0.86 / +0.32 / +0.90pt |
  | **メタゲート** | **+2.28 / +1.57 / +2.39pt** | +2.41 / +1.75 / +2.79pt |

  （VAL / TEST / 確認窓）

- **閾値は旧ゲートと同じ通過率**になる点（推定窓 50.9% → 0.1099）。
  評価窓での実通過率は 51% / 53% / 49% と再現した。**絞る意図はない。**
- **7M1 は7Cの裏返し**なので同じ判定を通す。片方だけ替えると境界に穴か重なりができる。
- `gate7c_score` が**無い / None** の候補は旧 p3合計ゲートへ落とす。
  判定不能を「買わない」にすると、旧JSONでの当日リカバリや上流故障で**商品が全滅**する。

## 🔴 二軸的中で見た +1.5〜2.0pt が、製品では +0.5pt まで縮む

理由は**下流のフィルタとの重複**で、閾値のせいではない。
レース単位で数えると **新ゲートのほうが通過は多い**（評価窓 25,249R で 51.6% vs 51.1%）。
にもかかわらず最終的な件数が毎窓 10% 減るのは、
`RANK_7C_LEGS_MIN`（相手4点以上）と `lowpay_pattern`（低配当パターン）が
**新ゲートの選んだレースをより多く弾く**ため。

新ゲートは `gap23`（2位と3位の差）が大きいレースを好む
→ 上位2車がはっきり抜けている → **残り5車が弱い** → 相手が p3>=0.15 で削られて4点に満たない
→ 低配当パターンにも該当しやすい。**「相手が絞れる＝配当が付かない」という既存の除外条件と、
新ゲートの好みが正面からぶつかっている。**

## 判定（保留）

- 表示的中の +0.50pt は 11/14 窓で正・t=2.58 と**一貫している**が小さい
- ROI は有意でない（+0.87pt・t=1.22）
- 対価は**件数 −10.0%**（全窓で減る）

同型の前例（`keirin_line_structure_2026_08_18` の細切れ: 件数 −17.1% に対し
表示的中 +0.1pt で見送り）と比べると効果は大きいが、**件数の対価は同じ形**。

**次にやるべきは件数を揃えた再試行**（閾値を下げて最終件数を 3,502 に合わせ、
「選別が良くなった」のか「少なく賭けただけ」なのかを分離する）。
それをやるまで本番へは入れない。

## 件数を揃えた再試行 → **不採用**（2026-08-18）

閾値を下げて件数を戻すと、差は比例して消える。

| | 件数 | 素の的中 | 表示的中 | ROI |
|---|---|---|---|---|
| 旧（p3合計 >= 1.44） | 3,502 | 41.01% | 31.90% | 77.02% |
| 新 閾値 0.1099 | 3,165 (−10.0%) | 42.12% | 32.39% (+0.49) | 77.90% |
| 新 閾値 0.0130 | 3,276 (−6.5%) | 41.64% | 32.20% (+0.30) | 77.37% |

月次の対応のある差:

| 閾値 | Δ表示的中 | t | ΔROI | t |
|---|---|---|---|---|
| 0.1099（−10.0%） | +0.50pt | +2.58 | +0.87pt | +1.22 |
| **0.0130（−6.5%）** | **+0.26pt** | **+1.33（ns）** | +0.16pt | +0.25 |

**件数を 3,502 へ外挿すると Δ表示的中 ≒ −0.09pt。**

🔴 **改善の正体は「良いレースを選んだ」ではなく「少なく賭けた」だった。**
二軸的中では +1.5〜2.0pt あった差が、本番の買い方（相手の足切り・低配当パターン・
買い方の正本）を通すとほぼ消える。既存の下流フィルタが**同じ情報をすでに拾っている**。

### 判定

**不採用。** `RANK_7C_P3_SUM_MIN = 1.44` を据え置く。

### この件から持ち帰ること

- **オフラインの目的関数（二軸的中）で測った改善が、製品の指標（表示的中・ROI）へ
  そのまま届くとは限らない。** 間に「相手の点数・ガミ・買い方」が挟まっている。
- **件数が動く比較は必ず件数を揃えてやり直す。** 揃えないと「少なく賭けただけ」を
  「選別が良くなった」と読み違える。今回は最初の A/B が t=2.58 で有意に見えていた。
- 次に効きそうなのは**選別と低配当フィルタの再設計**（相手の点数を選別スコアに
  取り込んで一体で決める）。別々に足すと今回のように打ち消し合う。
