## 3. RANK_7T3 の定義

### 3.1 母集団

```
n_entries == 7
∧ race_type ∈ {"決勝", "チャレンジ決勝"}      # 完全一致。部分一致にしないこと
∧ 予測オッズ30倍以上の目が1点以上ある
```

🔴 **`marquee.MARQUEE_KEYWORDS` を使ってはいけない**。あれは 決勝/特選/選抜/特秀 の
**部分一致**で、準決勝・特選・選抜まで拾う。7T3 は決勝だけを対象とする
（特選・選抜は単独 ROI 71.9% ＝ 壁の下・§6）。

🔴 **ライン条件は持たない**（§8）。7T1 の直後に置くことで同ラインだけが残る設計。

### 3.2 買い目

```
1. 位置別合成 Plackett-Luce で全210点の確率を出す
     a = normalize(ppw), b = normalize(pp3)
     s1 = a,  s2 = sqrt(a*b),  s3 = b      （各々レース内で正規化）
     P(x,y,z) = s1[x]/Σs1 × s2[y]/(Σs2−s2[x]) × s3[z]/(Σs3−s3[x]−s3[y])
2. 予測オッズ 30倍以上の目に限定
3. その中から P の降順に 5点
```

- 確認窓での top1 的中は **10.07%**（`ppw` 単独 PL は 5.99%）。
  参考: `src/odds_prediction_tf.pl_ordered` は `ppw` 単独なので**流用しないこと**。
- 🔴 **EV順（P×予測オッズ）にしてはいけない。** 100〜300倍帯では EV 順が優れるが、
  30倍帯では確率順のほうが素直（EV順は探索窓が in-sample で過大評価される）。

### 3.3 賭け金

1レース `RACE_BUDGET`（10,000円）を5点で等分 ＝ 2,000円/点。
`rank_7t1_stakes` と同じく最低単位で丸めること。

### 3.4 入稿形式

🔴 **1点=1行**（`formation_bet_7t1` 経路を共用）。
5点の1着が1車に揃うのは **7.0%** しかないので、1着1車固定のフォーメーションでは
表現できない。

## 8. 別ライン/同ラインの判定について（ユーザー質問への回答）

**判定できる。** `wt_entries.line_group` は朝の出走表（並び予想）に入っており、
7T1 が既に本番で `is_cross_line` として使っている。追加のデータ取得は不要。

```python
order = sorted(cars, key=lambda c: -p3[c])
g1, g2 = line_group[order[0]], line_group[order[1]]
is_cross_line = not (g1 is not None and g1 == g2)   # 単騎どうしは別ライン扱い
```

🔴 **ただし判定は「p3上位2車」の取り方に敏感**。軸2を p3 の3番手に替えると
**44.5%** のレースで別/同ラインの判定が反転する（2位-3位差が大きい帯でも 51.5%）。
モデルの微小な更新で商品が入れ替わりうる。

→ **だから 7T3 にライン条件を書かない。** 7T1 の直後に置き、
「7T1 が取らなかった決勝」を 7T3 が拾う形にすれば、判定が揺れても
**必ずどちらか一方の商品が出る**（穴が空かない・二重入稿もしない）。
判定ロジックの正本は 7T1 側の1箇所だけになる。

## 9. 優先順位の設計

### 9.1 現状

`RANK_CONFIGS` の**定義順がそのまま優先順位**（`RANK_ORDER = list(RANK_CONFIGS)`）。

```
定義順   : 7H2 > 9H1 > 7S > 9C > 7B > 7C > 7T1 > 7H1 > 7M1
実効     : 7S > 9C > 7B > 7C > 7T1 > 7H1 > 7M1   （7H2 / 9H1 は enabled=false）
```

`keirin.netkeirin_settings.enabled` の現状:
**有効** = 7B, 7C, 7H1, 7M1, 7S, 7SS, 7T1, 9C ／ **無効** = 7H2, 9A, 9H1, 9S, 9SS, S1

⚠️ `_is_enabled()` は **fail-open**（`netkeirin_settings` に行が無いと常時ON）。
**7T3 の行を `enabled=false` で明示的に INSERT してから**デプロイすること。

### 9.2 決勝を今どのランクが取っているか（2026-08 実入稿・7車決勝 85R）

```
7S 23件 / 7T1 14件 / 7A 13件 / 7C 4件 / 7M1 3件 / 7H1 1件
```

7T1 は 7S・7C の下にあるため、決勝の 16% しか取れていない。

### 9.3 決勝で各商品がいくら稼ぐか

| 商品 | 決勝すべて | 決勝×別ライン | 決勝×同ライン |
|---|---|---|---|
| 7S 相当（三連複・軸2車総流し5点） | ROI **75.0%**・的中 44.50% | 75.1%・40.61% | 74.8%・50.46% |
| 7T1（改） | — | **106.3%**・4.99% | 64.7%・3.19% |
| 7T3（新） | 91.7%・10.00% | 88.0%・10.05% | **97.2%**・9.93% |

**決勝では 7S より 7T1 / 7T3 が明確に上**（ROI で +22〜31pt）。

### 9.4 優先順位（確定）

```
7H2 > 9H1 > 7T1 > 7T3 > 7S > 9C > 7B > 7C > 7H1 > 7M1
             │     └── 新設
             └──────── 7C の後ろから移動
```
（`RANK_CONFIGS` の定義順をこの並びに書き替える。`RANK_ORDER = list(RANK_CONFIGS)`）

理由:
- 7T1 / 7T3 は**決勝のみ**が母集団で合計 3.6件/日と薄い。下に置くと 7S に取られて
  ほぼ出ない（実測 7T1 は決勝の16%しか取れていない）
- 決勝では ROI が 7S より 22〜31pt 高い
- **7T1 を 7T3 の上に置くのが必須**。この順序が「別ラインは 7T1・同ラインは 7T3」
  という棲み分けを実現している（§8）

### 9.5 決定事項（2026-08-24 ユーザー判断）

**7T1 / 7T3 を 7S の上に置く。** §9.4 の推奨順で確定。

受け入れたトレードの実測（7S 相当＝三連複・軸2車総流し5点・2,000円/点）:

| | 件/日 | 的中（生） | **表示的中（ガミ除く）** | ROI |
|---|---|---|---|---|
| 現状（決勝を含む） | 63.45 | 53.63% | **22.48%** | 74.2% |
| 決勝を外した後 | 59.82 | 54.18% | **22.26%** | 74.2% |
| （失う決勝ぶん） | 3.63 | 44.50% | 26.12% | 75.0% |

⚠️ **表示的中の低下は −0.22pt にとどまる。** 決勝は 7S の母集団の 5.7% しかなく、
実入稿ベースでも 236件中23件（2026-08）＝ 約1件/日。
ROI は 74.2% で変わらない。

🔴 **「決勝で 7S の的中が 44.5%」という数字をそのまま比較に使わないこと。**
これは**ガミ込みの生の的中率**で、netkeirin が顧客に見せるのはガミを除いた
**26.12%** のほう。7T3（9.93%）との差は 16pt で、当初見積もった 35pt ではない。

決勝で入れ替わる中身:

| | 表示的中 | 払戻中央 | ROI |
|---|---|---|---|
| 7S（従来） | 26.12% | 11,400円 | 75.0% |
| 7T1（別ライン） | 4.99% | 178,500円 | 106.3% |
| 7T3（同ライン） | 9.93% | 78,600円 | 97.2% |

看板レースでの体験が「そこそこ当たる少額」から「たまに当たる高配当」へ変わる。
これは**意図した商品判断**であり、ペーパー並走で売上（有償pt）への影響を見ること
（`keirin.netkeirin_sales_race` × `netkeirin_submissions.rank_key`）。

## 11. 受け入れ条件（ペーパー並走で見るもの）

🔴 **ROI で採否を判断してはいけない層**（的中率が低く払戻の分散が大きい）。
月次で見るのは次の3つ:

| 指標 | 期待値 | 許容 |
|---|---|---|
| 件数 | 7T3 1.4〜3.6件/日 / 7T1 2.2件/日 | ±30% |
| 的中率 | 7T3 約10% / 7T1 約5% | 月100R で ±6pt |
| 払戻中央 | 7T3 約7.8万円 / 7T1 約17.9万円 | ±30% |

ROI は **7窓の合議**（`src/keirin_protocol.MIN_TEST_WINDOWS = 4`）で判断する。
1窓（1四半期 ≒ 250R）では効果量とばらつきが同オーダー。

## 12. 落とし穴（実装前に必ず読む）

1. 🔴 **`rank_7t1_is_target_race_type` の中身を書き換えない**。`marquee.MARQUEE_KEYWORDS`
   を束縛しており、看板判定の正本に影響する
2. 🔴 **7T3 にライン条件を書かない**（§8）。優先順位で分ける
3. 🔴 **1点=1行**で送る。1着1車固定のフォーメーションでは 93% のレースが表現できない
4. 🔴 **`CURRENT_PAPER_RANKS` への追加を忘れない**（集計から消える事故が過去3回）
5. 🔴 **`netkeirin_settings` の行を先に入れる**（fail-open で意図せず入稿される）
6. 🔴 **日次上限を掛けるなら `race_date` ごとに掛ける**。バックフィルは月単位で
   呼ぶので、一括で掛けると月5本になる（7T1 で実際に踏んだ）
7. ⚠️ 予測オッズ30倍以上でも**確定では17%が下振れ**する。的中の内訳を語るときは
   予測ではなく確定オッズで数えること
8. ⚠️ 7T3 の 4〜8月 ROI 111.9% は的中60件・CI[81,146]。**黒字と言わないこと**
