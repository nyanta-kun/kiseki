冒頭フレーズはA案で確定し、`keirin.netkeirin_settings`（VPS PostgreSQL）へ
直接UPDATE済み（7SS/7S/9SS/9S→`自信の二軸`、7A/9A→`本日の二軸`、
comment_templateは全ランク共通で下記の確定版。S1は全廃済みのため対象外）。

## 方針（ユーザー指示の確認）

- **タイトル**：非購入者へのアピール枠。**軸2車が何番かは書かない**。代わりに「どのような推奨か」を伝える。
- **コメント**：購入者向け表示。**【詳細】**（軸の狙い・買い目・注意事項）と**【参考データ】**
  （既に実装済みの出走全選手の1着率・3着内率）の2段構成にする。

現行実装は `title_template` / `comment_template` を**ランクごとにDB管理**しているため、
以下の案は**コード変更なしで設定画面（`/keirin/settings`）から反映可能**です。
現在有効なランクは 7S / 7A / 9S / 9A（7SS/9SSはgate_label統合により実質廃止・S1は全廃済み）。

## 1. タイトル案（修正版）

レース番号・場名は netkeirin の一覧側に別途表示されるため重複させない。
アカウント名（二軸探偵）も一覧上で account 名として並ぶため、タイトル本文には入れない。
その結果タイトルは短いフック文言だけになるため、**S/A（厳選ゲート通過か全件か）で
文言そのものを変えて差別化する**（7車/9車の違いは選手数の差にすぎないため区別しない）。

| rank_key | タイトル案 |
|---|---|
| 7S / 9S（厳選ゲート通過） | `自信の二軸` |
| 7A / 9A（全件） | `本日の二軸` |

- venue/race_no/ブランド名を含めない分、5字程度の短いフックのみになる
- 「自信」と「本日」の対比で、厳選タイプかどうかが一目で伝わる
- 「自信の二軸」は2026-07-23に検討したSS+/SS向け文言の再利用（廃止済みSSから昇格させた形）

## 2. コメント案（全ランク共通・1本のテンプレート）

**修正版（2026-07-31）**：オッズ下限カットの開示文を削除。理由は以下の通り。
- 入稿は発走前の最終オッズを確認できないタイミングで行うため、購入者側も同じ制約で
  「最終オッズで買い目を絞る」アレンジは実質できない
- 検証の結果、現状の推奨は5点均等買いが妥当という結論になっている（不均等・足切りの
  優位性を謳う開示文と矛盾する）
- 三連単アレンジについては、1着率・3着内率という参考データを渡した上で
  「お任せする」姿勢に統一する（具体的な絞り込み手法は提示しない）
- 相手選手は総流しが基本方針のため、「相手選手を絞る」ニュアンスの文言は使わない。
  参考データは「三連単を購入する際の着順・買い目の参考」という位置づけに統一する
- 予想は1レース単位のため「本日」ではなく「本レース」を使う

```
{冒頭フレーズ（3案は下記参照）}

【詳細】
軸2車に自信が持てるレースだけを厳選してお届けしています。
買い目は三連複・軸2車流し（5点均等）でお届けします。

【参考データ】
出走選手全員の1着率・3着内率です。三連単で購入される際の着順・買い目の参考にご活用ください。
```

この直後に、既存コード（`_build_entry_table`）が自動追加する

```
【出走選手 1着率・3着内率】
<table>...</table>
```

がそのまま続く（`comment = f"{comment}\n\n{entry_table}"`、コード変更不要）。

### 設計上のポイント

- パターン分析で見つけた「言い切らない語尾」（〜お任せします／〜ご活用ください）を踏襲し、外れた時のブランド保護を維持
- 「軸間の連動理由」（分析5-3で提案した第二軸との関係性説明）は、システムが2車を独立モデルで選んでいる現状の実装と整合しないため**今回は入れていない**（実装するには軸間相関の特徴量が別途必要）
