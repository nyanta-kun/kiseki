# 大井「指数通りに決まらない」調査 — 2026-08-31

発端: 2026-08-31 の大井開催で指数下位の入着が続いた、という指摘。
結論: **指数の不具合は見つからず、変更すべき点も無かった。** 検討した4案は全て否定。

## 1. 当日の実態

| | |
|---|---|
| 確定5R の指数1位 | 1勝（勝率20% / 複勝40%）＝直近22開催日で最悪 |
| ただし n=5 | ベースライン44%なら「5戦1勝以下」は **約27%の確率**＝普通の下振れ |
| 1番人気（人気データのある2R） | **0勝0複勝**。同日の盛岡 3/6・金沢 4/5 |
| 信頼度 tier | **S:0 A:0 B:4 C:8＝S+A が 0%**。直近3か月22開催日で 0% はこの日だけ（他は17〜60%） |
| レース内 composite の sd | 5.93（期間最小。他日は 6.39〜8.14） |

**システム自身が事前に「今日は分離できない」と出力していた。** tier は honest でも
実際に効いている（walk-forward 24,093R: S 57.5% / A 44.8% / B 36.2% / C 30.0%）。

大井そのものは壊れていない（walk-forward の指数1位勝率 44.8%・14場中6位。
in-sample DB では 44.2% で2位だが、これは model-vintage look-ahead 込みの値）。

## 2. 否定した案（再検証不要）

### 案A: win_probability をレース内で正規化する — 否定

合計は 0.27〜2.29 まで振れる（±20%外が約44%のレース・平均は1.007）。しかし正規化は
**順位を一切変えない**（レース内単調変換。1位馬勝率 0.4290 で同値）。較正も一長一短:
log-loss 0.2447→0.2410 / Brier 0.0710→0.0703 は改善するが **ECE 0.0055→0.0142 と悪化**。
EV ゲートの単勝ROI も 0.760→0.779 でどちらも控除率の壁の下。**得が無い。**

検証: `scripts/exp_chihou_ooi/winprob_normalize.py`

### 案B: レース内 win_probability 合計を信頼度に足す — 否定

🔴 **測り方を誤って一度「+11.4pt の残差予測力あり」と判断した。誤り。**

「スコア66点以上の層内で wp_sum 下位1/3が44.4%・上位1/3が55.7%」は事実だが、
**66-100点という粗い帯で条件付けると帯内の連続スコアの序列を捨ててしまう**。
正しい検定を2つやると消える:

1. **選択率を揃えた比較**: 上位20%のレースを選んだときの指数1位勝率は
   現行59.6% ↔ 新59.7%（**+0.1pt, 95%CI [-0.8, +1.1]**）。大井も +0.2pt [-3.9, +3.9]。
   配点変更で S-C 幅が 26.8→32.6pt に伸びたのは **S が 27.4%→12.0% に減っただけ**の見かけ。
2. **tier 内で wp_sum と連続スコアを比べる**: 分離幅がほぼ同一
   （S帯 +8.2pt ↔ +8.0pt / A帯 +4.9pt ↔ +4.9pt / C帯は score の方が良い）。

**既存スコアが同じ情報を既に持っている。** prob_gap は未正規化確率の差なので
合計の情報を内包している。

検証: `scripts/exp_chihou_ooi/{tune_wpsum_term,tune_wpsum_big,score_curve}.py`

### 案C: 表示順を is_top3 ヘッドから is_win ヘッドへ替える — 否定

🔴 **in-sample の DB 値では大井 +2.8pt に見えたが、walk-forward では消える。**

| | in-sample DB | walk-forward (honest) |
|---|---|---|
| 全場 | +1.0〜+5.4pt | **+0.45pt** [CI +0.23, +0.68] |
| 大井 | +2.8pt | **+0.34pt** [CI −0.43, +1.16]＝有意でない |
| 1位馬の一致率 | 85% | **94.5%** |

バックフィル値は全期間1回学習モデルの遡及適用で、win ヘッドの方が look-ahead の
恩恵を大きく受ける。**そもそも両ヘッドはほぼ同じ馬を選んでいる。**

検証: `scripts/exp_chihou_ooi/head_compare_wf.py`（入力は
`chihou_rebuild_walkforward.py --dump-csv`）

### 案D: 新馬戦（能力指数が全馬中立50）を tier で下げる — 否定

🔴 **当初「R3 は全6頭が未出走で指数の裏付けが無いのに tier B」と指摘したが、
honest では逆だった。**

walk-forward 24,093R:

| | R数 | 指数1位勝率 | 平均スコア |
|---|---|---|---|
| 全馬未出走 | 366 | **47.3%** | 74.8 |
| カバレッジ100% | 20,169 | 44.6% | 70.0 |

tier 内でもほぼ同等（A帯 +1.8pt / S帯 −4.1pt(n=69) / B帯 +9.7pt(n=18)）。
**新馬戦はむしろ当てやすい**（少頭数で有力厩舎・騎手が素直に強い）。
in-sample DB で 34.0%/37.3% と低く見えたのは、模倣が実績馬を偏って助けるため。

検証: `scripts/exp_chihou_ooi/coverage_within_tier.py`

## 3. ついでに確認して健全だったもの

- **配信時に `races.condition` が NULL**（指数は当日00:01算出、馬場/頭数/天候は確定後にしか
  入らない）。「馬場込みで学習して馬場なしで配信」という v14 が市場特徴で直したのと同じ構造だが、
  **実測で指数1位勝率 −0.14pt・1位馬が変わるのは 2.1%** のみ。大井はほぼ常に良馬場で情報量が無い。
  検証: `scripts/exp_chihou_ooi/exp_ooi_serve_gap.py`
- **本番ORM実装（`_build_lgb_features`）と学習/検証pandas実装（`prep`）の特徴量整合**。
  完走日で突合し **39特徴中35本が完全一致**、残りも `speed_index` 最大 0.24/100 の再計算差。
  検証: `scripts/exp_chihou_ooi/exp_ooi_feature_parity.py`

## 4. 唯一の実装物: 値まで見るパリティテスト（対応済み）

`tests/test_chihou_model_parity.py` は **列名と順序しか検査していなかった**。
値が一致していることは調査で実測したが、それを固定する仕組みが無かった。

`tests/test_chihou_feature_value_parity.py` を新設した（**回帰予防・バグ修正ではない**）。
DB を引かず、両実装が受け取る注入テーブルを同一素材から作って 39 次元ベクトルを突き合わせる。
馬場5通り（良/稍/重/不/**空＝配信時の実態**）でパラメトライズ。

素材は分岐を踏むよう作ってある: 外部指数の両欠損 / last_margin 欠損 /
コーナー・調教師テーブルに行が無い / prev_pace_ratio 不明(-1) /
front_density の閾値 0.3 の境界(c_early_n=0.35) / `c_runs>0` ガード(c_early_n 低・c_runs=0)。

ミューテーション検査で実効性を確認済み（9種すべて捕捉）:
is_heavy/is_bad の入替 · 馬場不明の既定値 稍→良 · 調教師既定勝率 0.08→0.10 ·
front_density 閾値 0.3→0.4 · `c_runs>0` ガード削除 · 特徴の順序入替 ·
外部指数の欠損既定 0.5→0.0 · wet_active 閾値 >=2→>=1 · last_margin 欠損既定 ·
z の分母 ddof=1→0。

## 5. 手順の教訓

🔴 **バックフィル済み DB 値で案の優劣を決めてはいけない。** 案C は in-sample で
+2.8pt に見えて honest では +0.34pt（有意差なし）だった。CLAUDE.md の但し書き
（「DB の composite_index / win_probability で過去を評価しない」）は
ROI・的中率だけでなく **案の比較そのもの** に効く。

🔴 **粗い帯で条件付けて残差を見る手法は、帯内の連続量の序列を捨てる。**
案B はこれで一度「効く」と誤判定した。スコア関数の比較は
**選択率を揃えた曲線**で見ること。
