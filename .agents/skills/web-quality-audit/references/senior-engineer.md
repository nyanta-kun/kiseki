## チェック項目

### 1. コード品質
- **命名規則**: 変数、関数、クラス、ファイル名が一貫した命名規則に従っているか
- **コードの可読性**: 適切なコメント、ドキュメンテーション、自己文書化コード
- **DRY原則**: コードの重複がないか、共通処理が適切に抽出されているか
- **KISS原則**: 不必要に複雑な実装がないか
- **関数/メソッドの長さ**: 1関数が適切な長さか（目安: 50行以内）
- **ファイルの長さ**: 1ファイルが適切な長さか（目安: 300行以内）
- **マジックナンバー/文字列**: ハードコードされた値が定数として定義されているか

### 2. 設計パターンとアーキテクチャ
- **責務の分離**: 各モジュール/コンポーネントの責務が明確か
- **依存関係**: 適切な依存注入、循環依存の不在
- **レイヤー構造**: プレゼンテーション/ビジネスロジック/データアクセスの分離
- **コンポーネント設計**: 再利用可能で適切な粒度のコンポーネント分割
- **状態管理**: 適切な状態管理パターンの採用（技術スタックに応じて判断）
- **API設計**: RESTful設計原則、エンドポイント命名、レスポンス形式の一貫性

### 3. エラーハンドリング
- **例外処理**: try-catch の適切な使用、エラーの握りつぶしがないか
- **エラーメッセージ**: ユーザー向けと開発者向けの適切な分離
- **バリデーション**: 入力値の検証が適切に行われているか
- **エッジケース**: 境界値、null/undefined、空配列等の考慮

### 4. 保守性
- **技術的負債**: 明らかな技術的負債の特定（TODO/FIXME/HACK コメント等）
- **テスタビリティ**: コードがテスト可能な構造になっているか
- **設定の外部化**: 環境依存の値が設定ファイル/環境変数で管理されているか
- **ログ出力**: 適切なログレベルとログ内容
- **バージョン管理**: 適切な.gitignore、不要ファイルの混入がないか

### 5. フレームワーク固有のチェック
技術スタックに応じて以下の観点を追加する：

#### React/Next.js
- Hooks のルール遵守、カスタムHooksの適切な抽出
- コンポーネントのメモ化（React.memo, useMemo, useCallback）の適切な使用
- Server Components と Client Components の適切な分離（Next.js App Router）
- キーの適切な設定（リストレンダリング）

#### Vue/Nuxt
- Composition API の適切な使用
- リアクティビティの理解と適切な実装
- コンポーザブルの抽出と再利用

#### Angular
- モジュール構造、遅延ロード
- RxJS の適切な使用、メモリリークの防止
- Change Detection Strategy の最適化

#### バックエンド共通
- ミドルウェアの適切な使用
- ルーティングの整理
- データベースクエリの最適化（N+1問題等）
- 認証・認可の実装パターン
