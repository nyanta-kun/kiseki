# WEB品質監査スキル — 利用手順ガイド

## このスキルでできること

WEBシステムのプロジェクトに対し、9つの専門エージェントが並列で品質チェックを実施し、総合的な監査レポートを自動生成します。

### チェック観点（9カテゴリ）

| エージェント | 主な観点 |
|---|---|
| シニアエンジニア | コード品質、設計パターン、保守性 |
| QA | テスト網羅性、品質プロセス |
| 性能 | パフォーマンス、Core Web Vitals |
| セキュリティ | OWASP Top 10、認証、脆弱性 |
| 法務 | ライセンス、プライバシー、法的リスク |
| アクセシビリティ | WCAG準拠、スクリーンリーダー対応 |
| UX/UI | ユーザビリティ、レスポンシブ対応 |
| インフラ/DevOps | CI/CD、監視、可用性 |
| SEO/Web標準 | メタタグ、構造化データ、HTML品質 |

### 出力物

- マークダウン形式の監査レポート（`quality_reports/audit-report-YYYYMMDD.md`）
- 総合スコア + カテゴリ別スコア（100点満点）
- 重大度別の課題一覧（Critical / High / Medium / Low / Info）
- 各課題の具体的なファイルパス・推奨対応・参考URL

## セットアップ

### 前提条件

- Claude Code CLI がインストール済みであること
- Claude Team プラン（またはそれ以上）に加入済みであること

### インストール方法

#### 方法1: Gitリポジトリ経由（推奨）

スキルはプロジェクトの `.claude/skills/web-quality-audit/` に含まれているため、リポジトリをクローンまたはプルするだけで利用可能になります。

```bash
git clone <リポジトリURL>
cd <プロジェクトフォルダ>
# → .claude/skills/web-quality-audit/ が含まれていれば準備完了
```

#### 方法2: 手動コピー（個人環境に常駐させたい場合）

プロジェクト横断で使いたい場合は、ホームディレクトリのスキルフォルダにコピーします。

```bash
cp -r .claude/skills/web-quality-audit ~/.claude/skills/web-quality-audit
```

この場合、どのプロジェクトディレクトリからでもスキルが利用可能になります。

#### 方法3: Claude.ai 組織設定からチーム全体に配布（Team/Enterprise プラン）

管理者（Owner）が `.skill` ファイルを組織設定からアップロードすることで、チームメンバ全員に自動配布できます。

**管理者の操作手順:**

1. `web-quality-audit.skill` ファイルを用意する（プロジェクトルートに同梱済み）
2. Claude.ai にログイン
3. 左下の **組織名** → **管理コンソール** を開く
4. **Capabilities（機能）** で以下が有効になっていることを確認:
   - **Code execution and file creation**（スキル動作に必須）
5. **Skills** セクションを開く
6. **Add skill** → `web-quality-audit.skill` をアップロード
7. アップロード完了後、組織内の全メンバに自動的に配布される

**メンバ側の確認手順:**

1. Claude.ai にログイン
2. **設定** → **カスタマイズ** → **Skills** を開く
3. 「web-quality-audit」が一覧に表示されていれば利用可能
4. スキルはデフォルトで有効。不要な場合は個別にトグルオフ可能

**注意事項:**
- 組織からプロビジョニングされたスキルはメンバが削除することはできない（管理者のみ）
- スキルのバージョン更新時は、管理者が再度 `.skill` ファイルをアップロードする

### ディレクトリ構成の確認

以下のようにファイルが配置されていれば正しくインストールされています。

## 使い方

### 基本的な使い方

プロジェクトフォルダで Claude Code CLI を起動し、以下のように入力します。

```
品質チェックをして
```

これだけで、スキルが自動的にトリガーされ、以下のフローが実行されます：

1. 技術スタックの自動検出（package.json, pyproject.toml 等から特定）
2. 9つの専門エージェントが並列でチェック実施
3. 各エージェントがWebSearchで最新のベストプラクティスを取得
4. PMエージェントが結果を統合し、監査レポートを生成
5. `quality_reports/audit-report-YYYYMMDD.md` に保存

### トリガーフレーズ例

以下のような自然な言い方で起動できます。

- 「品質チェックして」
- 「コードレビューして」
- 「セキュリティ監査して」
- 「パフォーマンス分析して」
- 「リリース前チェック」
- 「アクセシビリティ確認して」
- 「SEO診断して」

### 特定の観点を重視する場合

```
セキュリティと性能を重点的にチェックして
```

全9カテゴリのチェックは行いつつ、指定した観点はより詳細に分析されます。

### 対象範囲を絞る場合

```
フロントエンドのコード品質を見て
```

特定のディレクトリに絞ったチェックも可能です。

### デプロイ済みサイトも含める場合

```
品質チェックして。デプロイ済みサイトは https://example.com です
```

ソースコードに加えて、実際のサイトに対するチェック（HTTPヘッダー、パフォーマンス、アクセシビリティ等）も実施します。

## 監査レポートの読み方

### スコアの基準

| スコア | 評価 | 意味 |
|--------|------|------|
| 90-100 | 優秀 | 重大な問題なし、ベストプラクティスに準拠 |
| 70-89 | 良好 | 軽微な改善点あり |
| 50-69 | 要改善 | 対応すべき課題が複数存在 |
| 30-49 | 問題あり | 重要な課題への対応が必要 |
| 0-29 | 深刻 | 早急な対応が必要 |

### 重大度レベル

| レベル | 対応目安 |
|--------|----------|
| Critical | 即時対応必須（システム停止、データ漏洩、法令違反） |
| High | 1週間以内に対応 |
| Medium | 次回リリースまでに対応 |
| Low | 余裕がある時に対応 |
| Info | 対応任意（参考情報） |

### 課題IDの見方

課題IDのプレフィックスでどのエージェントが検出したかがわかります。

| プレフィックス | エージェント |
|---|---|
| ENG- | シニアエンジニア |
| QA- | QA |
| PERF- | 性能 |
| SEC- | セキュリティ |
| LEG- | 法務 |
| A11Y- | アクセシビリティ |
| UX- | UX/UI |
| INF- | インフラ/DevOps |
| SEO- | SEO/Web標準 |

## 修正と再チェック

監査レポート提示後、修正対象を選択できます。

### 選択方法

- **課題IDで個別選択**: 「SEC-001 と QA-002 を修正して」
- **重大度で一括選択**: 「CriticalとHighを全て修正して」
- **全課題**: 「全て修正して」
- **レポート確認のみ**: 修正不要の場合はその旨を伝える

### 再チェック

修正後、再チェックを実行すると以下が確認できます：

- スコアの変動（前回比 ↑↓）
- 解決済み課題の一覧
- 新たに検出された課題（修正に伴い発生した問題）
- 残存する課題

再チェック結果は `quality_reports/audit-report-YYYYMMDD-recheck.md` に保存されます。

## よくある質問

**Q: チェックにどのくらい時間がかかりますか？**
A: プロジェクト規模によりますが、目安として3〜5分程度です。9エージェントが並列で動作するため、順次実行より高速です。

**Q: 特定のファイルやフォルダをチェック対象外にできますか？**
A: はい。「node_modules と .venv を除外して品質チェックして」のように指示してください。

**Q: チーム全員が同じスキルを使うにはどうすればいいですか？**
A: `.claude/skills/web-quality-audit/` をGitにコミット・プッシュしてください。チームメンバがプルすれば自動的に利用可能になります。

**Q: スキルのチェック基準をカスタマイズできますか？**
A: `references/` 配下の各エージェントのマークダウンファイルを編集することで、チェック項目を追加・変更・削除できます。
