# JRA ラップ由来の過去走特徴 — 事前登録（2026-09-16・**結果を見る前に書いた**）

## 0. 発端

netkeiba が「走行データ マスター」（個別ラップ・走行距離・距離補正タイム・位置）を
公開した（2026-09 実測）。ただし **SuperPremium 契約ではサーバが1着馬1頭分しか返さず**
（`is-master` が偽）、全頭分は別契約「マスターコース」が要る。

そこで先に、**追加費用ゼロで手元にあるラップ情報**（JRA-VAN の `races.lap_times` と
各馬の走破タイム・上がり3F）がモデルに情報を足すかを測る。
ここで何も出なければ、マスターコースの個別ラップの価値も低いと判断できる
（距離ロス補正は別物なので、その判断は別に残る）。

## 1. 測る前に確かめた事実（2026-09-16 実測）

| 項目 | 実測 |
|---|---|
| `races.lap_times` 充足（JRA 10場・平地） | 2019〜2025 年 99.0〜100%、2026 年 97.6% |
| ラップの並び | **スタートから**。距離が 200 で割り切れないとき先頭区間が短い（1700m → 100m + 200m×8） |
| `Σラップ = 1着馬 finish_time` | 2025 年 3,340R で**全件一致**（差 >0.15 秒は 0 件） |
| 末尾3区間の和 = `last_3f_race` | 全件一致 |
| 先頭3区間の和 = `first_3f`（200 で割り切れる距離） | 全件一致 |
| 各馬 `finish_time` / `last_3f` / `time_diff`（2023〜・完走） | 100% |
| 🔴 各馬 `last_4f` | **全行 NULL** → 使えない |
| 既存モデルでの `lap_times` 利用 | **なし**（`first_3f` の距離別中央値比較だけ） |

⚠️ ラップは「先頭馬の区間タイム」なので、各馬の区間は **前半 = finish_time − last_3f** と
**上がり3F = last_3f** の2区間にしか分解できない。

## 2. 特徴の定義（`backend/src/indices/lap_form.py` が正本）

### 2.1 1走ぶんの指標（過去走 r ごと）

対象は **JRA 10場・平地・ラップ有効・`abnormality_code = 0`・着順 > 0** の走のみ。

    race_total  = Σラップ
    race_last3  = 末尾3区間の和
    race_front  = race_total − race_last3
    race_shape  = mean(末尾3区間) − mean(その前の2区間)   … 負 = 加速（瞬発戦）/ 正 = 失速（消耗戦）

    horse_front = finish_time − last_3f
    horse_last3 = last_3f
    n_front     = (distance − 600) / 200                    … 前半を 200m あたりへ揃える

**標準タイム（par）**: `(course, surface, distance, condition)` ごとの
`race_front` / `race_last3` の**走 r の日付より厳密に前のレースだけ**の平均。
件数が 10 未満なら `(course, surface, distance)` へ落とし、それも 10 未満なら欠損。

    front_par       = (horse_front − par_front) / n_front   … 秒/200m・正 = 前半が遅い
    l3_par          = horse_last3 − par_last3               … 秒・正 = 上がりが遅い
    race_front_par  = (race_front − par_front) / n_front    … そのレースの前半ペース

### 2.2 馬の特徴（対象レース日より**厳密に前**の有効走・新しい順に最大3走）

| 列 | 定義 |
|---|---|
| `lap_front_par_l1` | 直近1走の `front_par` |
| `lap_l3_par_l1` | 直近1走の `l3_par` |
| `lap_race_front_par_l1` | 直近1走の `race_front_par`（そのときのペース） |
| `lap_race_shape_l1` | 直近1走の `race_shape` |
| `lap_front_par_m3` | 直近3走の `front_par` 平均（1走以上） |
| `lap_l3_par_m3` | 直近3走の `l3_par` 平均（1走以上） |
| `lap_l3_par_best3` | 直近3走の `l3_par` 最小 |

- 欠損は NaN のまま LightGBM に渡す（v28 の新特徴と同じ意味論）
- 「直近」は **有効な JRA 平地の走に限った直近**。地方・障害・ラップ欠損の走は飛ばす
- 🔴 point-in-time: 同日の先行レースも使わない。par も走 r の日付より前だけで作る
- JRA-VAN の結果は当日中に入るので、配信時に使えない情報は無い
  （netkeiba 個別ラップの「翌週金曜公開」の問題はこの特徴には無い）

### 6.4 診断（結果を見た後に回した・**採否には使わない**）

効果が v28 採用時より大きかったため、漏れを疑って中身を割った。

| 腕（v28 + …） | 四半期等重み Δ | 95%CI | 改善 |
|---|---|---|---|
| 7列すべて | −0.00872 | [−0.01173, −0.00553] | 10/10 |
| 馬の走り5列（F1/L1/Fm3/Lm3/Lb3） | −0.00867 | [−0.01151, −0.00587] | 10/10 |
| 過去レースの文脈2列（RF1/SH1） | −0.00272 | [−0.00520, −0.00016] | 6/10 |

- **効いているのは馬自身の前半・上がりの par 比**。過去レースのペースや形状だけでは弱い
- DM がそろったレース（7,684R）で Δ −0.0098。DM 欠損が過半のレース（303R）では +0.0055
  ＝**ラップは DM の代わりにはならず、DM に上乗せされている**
- 勝ち馬にラップ特徴が無いレース（761R・新馬や地方からの転入）でも Δ −0.0040。
  勝ち馬自身の値が無くても改善する＝他馬の確率の配り直しから来ている。
  勝ち馬の行だけに情報が漏れているなら、ここは 0 になるはず
