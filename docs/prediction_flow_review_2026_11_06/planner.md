## 1. 目的の再定義

### 1.1 結論（一文）
**「指数を置き換える」改修ではなく、「既存の指数・確率の上に、展開を介した“馬同士の相関を持つ着順分布”を載せ、組合せ確率（ワイド・馬連・三連複）と“なぜそうなるか”を出せるようにする」改修**と位置づける。

### 1.2 なぜそう置くか（過去の否定結果との整合）
| 既存の知見 | この企画への含意 |
|---|---|
| ROI は控除率の壁で作れない（中央・地方・競輪で繰り返し確認） | 成功指標に ROI・回収率を置かない。画面でも収支を謳わない |
| 指数の価値は順位・的中精度 | 成功指標は「確率の較正と識別力」に置く |
| tier（購入指針）は廃止（オッズの言い直しと判明） | 組合せ確率を「買い推奨」や tier に使わない。復活提案はしない |
| **中央**で「三連複 EV による買い目選別は構造的に不成立」（PROJECT_STATUS §3.2・旧08-24メモ）。中央の walk-forward では三連複へ替えると上乗せ +0.066、2着・3着ヘッド＋Henery 混合で三連複3点 0.868→0.895 まで来たが ROI 1.0 には届かない（三連複6点で必要 w 0.031 ↔ 現在地 0.009）。地方は市場が予測しやすく横展開は打ち切り（§3.3） | 組合せ確率は「較正された目安」として出す。EV 選別は目的にしない。**組合せ側の伸びしろが周辺確率より大きい**ことは追い風 |
| 既存の未完案件（§4.2）: 事前登録 `jra_exotic_ev_preregistration_2026_08_23.md` の改訂・本実行、エキゾチック特徴の3ヘッド A/B やり直し、三連複3点 vs 6点、listwise。**exotic オッズは21日しか保持されない** | Wave 1 は白紙の新規ではなく**この未完案件の再開・統合**として扱う。保持窓の決定が先 |
| 画面の「波乱度」はメカウチダ（外部サイト）の札を保存したもので、自前モデルではない。地方は有意（高−低で三連複×1.41）、中央は判定不能 | 自前の「展開発生確率」とは別物。**併存**とし、将来、波乱度を自前展開確率に置換するか比較する（論点F） |
| 現行 LightGBM は単勝・複勝の周辺確率を直接出す | **周辺確率（勝率・複勝率）で現行を超えられる保証は無い。むしろ劣化させないことが条件** |

### 1.3 誰が何を得るか
- **利用者**: 馬連・ワイド・三連複の「組合せ確率」の目安、展開（前に行く馬の数・隊列）に基づく説明。ただし**価値（オッズに対する妙味）の保証ではない**と明記。
- **運営者**: (a) 組合せ確率が Harville/Henery より較正されているかの検証基盤、(b) 予測保存→結果照合→Forward 検証の一貫した台帳、(c) 展開・馬場傾向という説明可能な中間量。
- **得られない（約束しない）**: 回収率の向上、的中率の大幅向上。

### 1.4 技術的な正直な見立て（企画の前提として重要）
- 「馬ごとの能力＋ノイズを独立に10万回引いて着順を決める」だけなら、結果は Plackett-Luce/Thurstone 型の周辺分布になり、**既に較正済みの LightGBM の勝率・複勝率と二重計上になるだけ**で新情報はほとんど無い。
- シミュレーションが意味を持つのは **「展開（ペース・隊列）という共通ショックを介して馬同士が相関する」**ときだけ。つまり価値の源泉は *展開発生確率モデルと脚質×展開の交互作用* であり、10万回という回数自体ではない。
- 従って最初に検証すべきは「展開の共通ショックを入れると、**組合せ確率の対数損失**が Harville/Henery/既存 LGB 組合せ（finish_order.py の lgb 法）より下がるか」。**下がらないなら本線（Wave 3 以降）には進まない**（撤退条件を計画に埋め込む）。
- 「事前試行10万回」の役割（目標フロー上）は未確認。キャリブレーション用か収束確認用か、ユーザーの意図を確認する（論点 D）。

## 3. スコープ

### 3.1 やる
1. 組合せ確率の本番配線（まずは **Harville/Henery/既存 lgb 法**で既存確率から出す。finish_order.py を本番化）。シミュレーション無しでも先に価値が出る＝**最小到達点**。
2. 展開発生確率モデル（ペース: ハイ/ミドル/スロー、前残り/差し決着など）。学習は既存の past_form・pace 系の PIT 安全部分を使う。
3. 多段階位置取りシミュレーション（START→中間→直線）と、展開を共通ショックとする着順サンプリング。
4. 予測の保存（確率集計、シード、入力ハッシュ、モデル版）と結果照合、Forward 検証台帳。
5. 中央の当日馬場傾向の入力化（既にバイアス系があるかは未確認。要棚卸し）。

### 3.2 やらない
- ROI・回収率を目標にすること、EV による買い目選別、tier/購入指針/「推奨」の復活。
- 現行の勝率・複勝率・composite_index を置き換えること（シミュレーション出力は**並走の追加列**とし、採用は M2 の非劣性を満たした後）。
- 自動購入（IPAT 連携＝MS7/8）や有料サービスの追加契約・外部公開を伴う実装（必要になる場合は別途承認事項）。
- 「AS / AAR / APS」という名称の既存指数への置換（用語対応は論点 E）。既存サブ指数を 01 層に**写像**するだけで、再学習はしない。

### 3.3 後回し
- 事前試行（10万回）の厳密な意味づけ（論点 D 確定後）。
- 三連単など点数の多い券種。
- 競輪への展開（対象外。別柱）。
- 画面での組合せ確率表示の詳細デザイン（Wave 2 で最小限、本格 UI は検証合格後）。

### 3.4 中央と地方の差
| 項目 | 中央 | 地方 | 差を付ける理由 |

| 着手順 | 先 | 後（中央の枠組みを流用） | 中央は DM（JV-Next）特徴が強く、前向き記録・TEST プロトコルが四半期ローリングで整っている。地方は月次で標準誤差が小さく検証しやすい面もあるが、**地方の市場乖離特徴を v14 で外した経緯**があり、組合せ確率で市場を混ぜる設計は慎重を要する |

## 6. ユーザーに決めてもらう論点

### 論点A: 目的と成功指標の置き方
- 案1（推奨）: 目的を「組合せ確率の較正＋説明可能性」とし、成功指標は M1〜M3（対数損失・較正）。ROI は指標にしない。
- 案2: 馬券収益を目標にする。→ 過去の否定結果（控除率の壁）と矛盾するため**非推奨**。
- 案3: 的中率の向上を主目標にする。→ 周辺確率で現行を超える根拠が現時点で無い。

### 論点B: 撤退条件の事前合意
- 推奨: 「G2 または G3 を通らなければ、シミュレーションは採用せず Wave 1 の成果（組合せ確率の本番化）だけ残す」を**着手前に合意**する。
- 代替: 通らなくても目標フローの形（説明用の可視化）として運用する。→ 精度保証の無い表示が増えるため、表示に「参考値」と明示する必要がある。

### 論点C: 実行場所と計算負荷
- 推奨: 重い計算は **Mac mini（launchd）で実行し結果を VPS に POST**。VPS は保存・配信のみ。理由: VPS の資源は未確認で、他ジョブが落ちた前例がある。
- 代替: VPS で回す。→ Wave 0 の実測で余裕が確認できた場合のみ。コンテナの CPU/メモリ増強は有料になりうるので承認が要る。
- 注意: Mac mini ジョブ用 clone は自動 pull されない（運用メモあり）。デプロイ手順を企画に含める。

### 論点D: 「事前試行10万回」の意味
- 推奨解釈: 事前試行＝収束確認とパラメータ較正（本番は別シード）。
- 他の解釈: 展開の発生確率を推定する予備ラン。
- ユーザーの意図に合わせて確定したい。**推測で進めない**。

### 論点E: 用語（AS / AAR / APS / PEI）と既存指数の対応
- 推奨: 既存のサブ指数を 01 層に**写像**し（再学習しない）、PEI は「周辺確率に展開補正を加えた指数」と定義、`composite_index` は並走させる。
- 代替: 新指数を `composite_index` の後継にする。→ M2 の非劣性が出るまでは**非推奨**。

---

### 論点F: 既存の波乱度（メカウチダ由来）との関係
- 推奨: 併存。自前の展開発生確率は Wave 2 で作り、前向きで波乱度と比較（中央は244Rで判定不能のため前向き蓄積が前提）。置換は比較後に判断。

### （補足）地方を後回しにする理由
ご要望は中央・地方の両方だが、地方は市場が予測しやすく上乗せが小さい（ΔAUC +0.0006）うえ当日馬場バイアスの入力が無いため、中央で G2/G3 を通過してから展開する。Wave 1（組合せ確率の本番化）は地方も並走可。
