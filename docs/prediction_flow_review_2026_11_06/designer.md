### 1.2 一覧（`RaceCard.tsx`）で出ている物と判断できること

### 1.3 中央レース詳細（`RaceDetailClient.tsx` 691行）

画面は「出馬表 指数一覧」1枚のテーブルのみ（レース単位のサマリ領域は無い。`RaceSubHeader` は名称・日時・コース・波乱度チップのみ）。

- 判断できない（事実としてこの画面に無い物）:

  - 予測がいつ時点のものか（保存時刻・モデル版）。
- 期待値列: `win_probability × 単勝オッズ` を緑の濃淡で強調（L74-80, L456-459、`EV_HIGHLIGHT_THRESHOLD` 使用）。凡例に「ROI … 1.0以上で期待値プラス」（L681）。

## 3. 目標フローに合わせた表示設計案

方針:
1. 既存の「判定はバックエンド純関数、フロントは表示のみ」を維持。分解・確率・組合せは**全てバックエンドが計算済みの値を返し**、フロントは並べるだけ。
2. 「収支」ではなく「確率とその検証」を主役にする。馬券の期待値や回収の謳い文句は出さない。組合せ確率にオッズを並べる場合も、*市場の暗黙確率との比較*に留め、「買い」「推奨」という語を使わない。
3. 全ての確率・分解に「保存時刻・モデル版・シミュレーション回数」を添える。予測保存→結果照合→Forward 検証の流れが利用者に見えること自体を信頼の根拠にする（現状の推奨タブの「探索期間と前向きを分けて書く」作法を全画面へ）。

### 3.1 レース詳細の新構成（上から）

1. **レースサマリ帯**: 想定ペース（ハイ/ミドル/スロー確率）、本命度（1位馬の勝率）、波乱度（外部、従来）、予測保存時刻。
2. **馬カード一覧**（表→カード化。後述ワイヤー）: 各馬に PEI、勝率/連対率/3着内率、脚質、1行の理由。
3. **展開（シナリオ）**: ペース確率と、各シナリオで有利な馬の帯。
4. **馬場傾向（Track Bias）**: 内外/前後の有利度メーター。
5. **組合せ確率**: 馬連・ワイド・三連複の上位 N（折りたたみ、既定は閉じる）。
6. **この予測の検証**（折りたたみ）: 同種レースの過去の的中状況、キャリブレーション。
7. 確定後: 予測順位と着順の照合行（既存の確定着順ブロックを置換）。

### 3.2 案ごとの内容と必要な API フィールド

#### A. 「なぜこの馬が上か」寄与分解

- 表示: 馬カード展開内に横積みバー。AS(基礎能力) / AAR(条件適性) / 展開 / 馬場 / 騎手・その他 の寄与を +/- で表示。合計 = PEI（またはレース内の相対スコア）。1 行テキスト「○○が強み／△△が減点」。
- 注意: 現行 10 指数バーとは別物にする。名称も「入力指数」と「寄与」で区別。入力指数は引き続き折りたたみで残す。
- 必要 API（`HorseIndex` 追加、中央・地方共通）:
  - `contrib: { as: number, aar: number, pace: number, bias: number, other: number }`（単位はレース内偏差か log-odds。合計が `pei` と一致する）
  - `contrib_basis: "shap_group" | "ablation"`（算出方法の明示）
  - `reason_top: { label: string, direction: "+"|"-" }[]`（上位 2 件。文言はバックエンドで生成）
  - 現行モデル（LightGBM）の段階で先行実装可能: `pred_contrib` の特徴量グループ集計で `as/aar/…` に相当する分解が作れるなら、シミュレーション前でも出せる。

#### B. 勝率・連対率・3着内率

- 表示: 馬カードに 3 本の確率を並べる（整数%は 5% 以下で小数 1 桁）。バーは同一スケール（レース内最大で正規化しない。常に 0〜100%）。
- 事実: 現状は勝率と複勝率のみ。2 着以内がない。
- 必要 API: `win_prob`, `top2_prob`, `top3_prob`（既存の `win_probability` / `place_probability` とは意味を揃える。`place_probability` は払戻対象着順（5〜7頭立ては 2 着）になっているので、**`top3_prob` は常に 3 着以内**、払戻対象は別フィールド `place_pay_prob` とする。CLAUDE.md の `place_slots` 事情と衝突させない）。
  - `prob_ci95: [lo, hi]`（シミュレーション標準誤差。表示は ±表記か薄い帯）
  - `n_sim`, `model_version`, `saved_at`（レース単位で 1 回返せばよい）

#### C. 展開シナリオ（ペース確率）の可視化

- 表示: 横 1 本の積み上げバー「ハイ 25 / ミドル 50 / スロー 25」。その下に、各シナリオで勝率が上がる馬を 2〜3 頭（"スローなら ○○"）。脚質は各馬カードに小バッジ（逃/先/差/追）と、位置取りの予想（START→中間→直線の順位帯）を 3 点の細いドットで示す。
- 必要 API:
  - レース: `scenario: [{ key: "high"|"mid"|"slow", prob: number }]`, `bias: { inner_outer: number, front_back: number, basis: string }`（-1〜+1。`basis` に「当日 n 走の結果から」等）
  - 馬: `style: "逃"|"先"|"差"|"追"`, `position_prob: { start: number[], mid: number[], final: number[] }`（順位帯 1-3/4-6/7+ の確率でよい）, `win_prob_by_scenario: { high: number, mid: number, slow: number }`
  - 外部依存: バイアスは当日のレース結果から推定するため、午前のレースが少ないとき `bias.n_obs` が小さい。`n_obs` が閾値未満なら「データ少」表示にして強く見せない。

#### D. 組合せ確率の表

- 表示: 3 タブ（馬連 / ワイド / 三連複）、各上位 10。列は「組合せ（馬番）」「モデル確率」のみ。
- **市場の暗黙確率と差の列は提案に含めない。** 「モデル確率 − 市場の暗黙確率」は `確率×オッズ` を並べ替えた期待値と同じ性質で、色を中立にしても数値の意味は変わらない（地方では EV が回収率と逆相関だった）。中央 EV の検証結果が出るまで出さない前提でよいかを設計部への確認事項に置く。
- 取り扱い注意: CLAUDE.md の複数の記録（EV と回収率が逆相関、tier 廃止）を踏まえ、**確率の精度（キャリブレーション）が検証されるまで既定では閉じ、「検証前」バッジを付ける**。
- 必要 API:
  - `combos: { quinella: Combo[], wide: Combo[], trio: Combo[] }`、`Combo = { horses: number[], prob: number, prob_ci95?: [number, number] }`

#### E. 前向き検証の成績表示

- 表示: 成績ページの主役を「ROI」から「確率が当たっているか」へ。
  1. キャリブレーション図（予測確率の 10 分位 vs 実際の頻度）。勝率/連対率/3着内率の 3 枚、前向きのみ。
  2. 1 位馬の的中（勝/連対/3着内）の前向きと、レース数・期間・バックフィルの区別（in-sample は別ラベル）。
  3. 組合せ確率の対数損失/ブライアスコア（モデル単独の推移。市場との並置は上記の判断が出るまで保留）。
- レース詳細の末尾にも「このレースと同条件（芝/ダ・距離帯・頭数）の前向き成績」を 1 行（n 付き）。
- 必要 API（新エンドポイント想定）: `GET /api/forward/summary?from&to&surface&distance_bucket` → `{ n_races, since, model_version, calib: { target: "win"|"top2"|"top3", bins: { p_mean, hit_rate, n }[] }[], top1: { win, top2, top3, n }, combo_logloss: { model, market, n } }`。各レースに `prediction_saved_at` を持たせ、**発走前に保存した記録のみ**を前向きと呼ぶ（既存の `keiba.hit_tier_*` / `chihou.place_picks` と同じ作法）。

#### F. 現状の項目の整理（案 A〜E と併せて）

| 現状 | 扱い |
|---|---|
| 期待値列（中央） | 既定非表示にして判断を仰ぐ。表示するなら地方と同じ注記を付ける |
| 10 指数バー | 「入力指数」として折りたたみに降格。DM（`jvan_*_dm`）を足す |
| 複勝ピック/激走/平八/穴/特穴/外部◎ | 馬名の隣のバッジを 2 個までに制限し、残りはカード展開内の「印」欄へ |
| ☆穴ぐさ | 過去日のみ表示 |
| 足切り | グレーアウトはやめ、「着外率 85%」と小さく添えて行は通常色（読めなくなる問題の回避） |

## 5. 段階導入順

### Phase 0 — バックエンド変更不要（すぐ可能）

1. 凡例の整理: 地方の足切り閾値の直書き文言を、定性文（「着外率が高い／指数差が大きい馬」）に置換。穴ぐさ節を履歴注記へ縮小、☆A/B/C と穴ぐさコメントは過去日のみ表示（課題 2, 3, 12）。
2. 詳細の主表に騎手・斤量・馬体重/増減・枠を追加（`fetchEntries` の取得済みデータを渡す。課題 5）。
3. 中央の「期待値」列の扱いを決める（要ユーザー判断。課題 1）。方針どおりなら既定で非表示にして地方と揃え、残すなら地方と同じ「当たりやすさの印でなく…」注記を付ける。
4. バッジを馬名セルから分離（2 個まで／残りは展開内）。足切りの `opacity-40` をやめて着外率の数値表示へ（`out_probability` は既存フィールド）。課題 6, 13。
5. 確率表示を小数 1 桁対応（5% 以下）。
6. `RaceDetailClient` / `ChihouRaceDetailClient` の共通部分（SortButton・結果マップ・確定着順・`finishBadgeClass`・`formatTime`・`useIsMounted`）を共通モジュールへ（課題 7、動作変更無しのリファクタ）。
7. 成績ページに前向き/バックフィルの区別ラベルを追加（既存の推奨タブの文言を流用。課題 10）。

### Phase 1 — 既存フィールドで可能な小改修

8. 馬カード（モバイル）化。ソート条件の拡張。
9. 中央にもオッズ鮮度バッジ（バックエンド側 `freshness` を中央のオッズ API にも付ける小改修が要る。設計部へ依頼）。
10. 一覧カードに 1 位馬名と勝率（`top_horse_name`・`win_prob_top` の流用で、不足なら 1 フィールド追加）。
11. 展開行に DM 指数（`jvan_time_dm` / `jvan_battle_dm`、型にあり）を追加し、「入力指数」へ名称変更。

### Phase 2 — LightGBM のままバックエンド小規模追加

12. 案 A（寄与分解）: `pred_contrib` のグループ集計。`contrib` / `reason_top` / `contrib_basis`。
13. 案 B の一部: `top2_prob`（現行 LightGBM に連対ヘッドがあるかは設計部に確認。無ければ Phase 3）。
14. 予測保存時刻・モデル版を返す（`saved_at`, `model_version`）。前向き記録（`keiba.hit_tier_*` 等）の仕組みを全馬・全確率へ拡張。

### Phase 3 — シミュレーション導入後

15. 案 B（勝/連/3着内 + `prob_ci95` + `n_sim`）、案 C（`scenario` / `bias` / `style` / `position_prob` / `win_prob_by_scenario`）、案 D（`combos`）。
16. 案 E（`/api/forward/summary` とキャリブレーション図）。**組合せ確率の公開前に、3 確率のキャリブレーションが前向きで一定期間確認できていること**を掲示条件にする（確認前は「検証前」バッジ、既定で閉じる）。

### 設計部への確認事項

- 寄与分解の算出方式（SHAP のグループ集計か、シミュレーション内での入れ替え実験か）と、合計が PEI と一致する保証。
- `top3_prob`（3 着以内）と払戻対象確率（`place_slots`）を別フィールドにすること。
- 市場差分（モデル確率と市場の暗黙確率の差）の表示は EV 列と同じ性質。中央 EV の検証結果が出るまで出さない前提でよいか。
- 前向き記録を全馬の 3 確率・組合せ確率にまで広げるときのテーブル設計（`hit_tier` 系は 1 位馬中心で、全馬の確率の保存は地方 `place_picks` のみ全出走馬を持つ）。
- 中央で EV と回収率の関係を地方と同じ手順で検証する予定の有無（課題 1 の判断材料）。
