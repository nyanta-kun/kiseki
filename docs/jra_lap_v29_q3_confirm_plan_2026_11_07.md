## 4. 主指標と判定（事前に固定・動かさない）

**主指標は1つ**: 単勝の**レース単位の多項対数損失**の対応差 `lap − v28`（負 = 改善）。
95%CI はレース単位の bootstrap 2000 回（`jra_prob_scoring.paired_logloss_ci`・seed 20261107）。

前段の「改善 6/10 四半期以上」は1四半期では使えないので外し、CI だけで判定する。

| 判定 | 条件 | 次の手順 |
|---|---|---|
| **確認成功** | 95%CI の上端 < 0 | v29 の実装へ進む（§6） |
| **判断保留** | 点推定 < 0 だが CI が 0 を跨ぐ | 何も出荷しない。2026Q4 が閉じた後に §4.1 を1回だけ行う |
| **確認失敗** | 点推定 ≥ 0 | 不採用で終える。定義をいじって回し直さない |

### 4.1 判断保留のときの追加の1回（2026Q4 = TEST を消費する）

- 2026Q4（20261001〜20261231）が閉じたら、学習を 2026-09-30 までに伸ばして Q4 を評価し、
  **Q3 と Q4 のレースを合わせた**対応差の 95%CI（同じ bootstrap）で判定する
- 上端 < 0 なら確認成功、それ以外は不採用。これで最後にする
- Q4 は TEST なので `jra_protocol.record_test_usage()` で台帳に記録する

### 4.2 検出力（判定基準を決める前に見積もった）

前段の全期間 CI（8,618R で半幅 約 0.0031）から、レース単位の差の標準偏差は約 0.15。
871R なら SE 約 0.005・CI 半幅 約 0.0099 になる。VAL と同じ効果（−0.0087）が本当にあっても、
**Q3 だけで確認成功になる確率は約4割**。判断保留が一番ありうる結果であり、
そのときに Q4 を足す手順（合計約1,700R・同じ効果なら約7割）を先に決めておく。

v28 の確認（§15.3）は「点推定が改善側なら成功」という緩い基準だった。今回それを採らないのは、
v28 と違って**本番の確率を作り直す版上げ（v29）**であり、外部（kiseki-lab）にも影響が出るため。
