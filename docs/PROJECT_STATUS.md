## 3. 検証結果（決着したもの）

「同じ穴を二度掘らない」ための記録。数値は測った窓に紐づくので、別の窓と直接比べないこと。

### 3.1 横断の一般則

- **DB に保存した過去の指数・予測値で ROI や的中率を測ってはいけない。** 全期間で refit したモデルを
  遡って当てているため in-sample になる。判定は walk-forward で行い、**市場だけのモデルを並べて走らせ**、
  市場の上にどれだけ上乗せできたかだけを見る。
  - 中央の実例: 指数の複勝上乗せが in-sample では +0.053、walk-forward では **−0.022 [−0.040, −0.003]**。
    リークで符号が逆になっていた（08-23）
  - 地方の実例: sweet_spot は model-vintage look-ahead に丸ごと依存していた（`CLAUDE.md`）
- **市場と同じ向きの分類器は、どれだけ精度が高くても ROI にならない。** 3競技とも控除率の壁に収束している。
- **「市場が非効率」と「自分に情報優位がある」は別物。** ばんえいは市場 AUC 0.778 と明らかに非効率なのに、
  上乗せはゼロだった。

### 3.4 競輪

正本は `AUDIT_2026_09_20.md` と `RECOMMENDATION.md` §7。要点:

- **モデルは健全だが、確定オッズに対して実用的な追加情報を持たない。** 買い方の工夫で届く ROI の上限は
  **78〜82%**。実売 ROI の通算 72.3% は、偶然の下振れ（約1σ）で説明できる。
- **採点・リーク・train/serve skew に欠陥は無い**（独立に再計算して不一致 0。netkeirin の帳簿との差 0.09pt）。
- **売上を動かすもの**: 高額系のラベル、自信あり、決勝、10万円以上を当てた翌日。
  的中率・出す本数・公開の早さは効かない。
- 型ラボの実地とペーパーは揃っている（売った 1,240 件が live 候補と完全一致。ROI 77〜78% ↔ 78.2%）。
- **型A は買い方をどう変えても割に合わない**（7軸すべて否定・A-split も窓で最良の腕が入れ替わる）。
  → A_ana / A_trio / A_hit の3分割で決着（#384）。
- **軸崩壊は全プランで取れない**（7車の 7.1%・9車の 12.6%）。単一で最大の損失要因。
- 否定したもの: 型C の合成オッズ下限 / gap による見送り・点数の増減（窓で符号が反転）/
  形の制約（1着固定・BOX・二軸流し）/ レースの厳選（無作為の対照に負ける）/ 均等配分（ダッチ一択）/
  「軸が不利」な指数 / 予測オッズの精度向上 12 案 / 上帯の重ね買い（#466）/ 段の販売（#583）/
  高額枠を1日10本にする（#588）/ 較正崩れを型判定へ反映する案。
- **旧リポジトリ期（〜07-07）の教訓**: バックテストに3つのバイアスがあった
  （①欠車の生存バイアス × 古いオッズ ②6車以下を完走者で数えていた ③週次再学習のリーク）。
  除くと全レバーが ~70〜90% に落ちた。fav_mismatch（1168% → HOLD 23.1%）や
  1-2着BOX三連単（★頑健 → 32.5%）はバイアスが作った幻だった。
  ほかに風・師匠・身体測定・条件別成績・LambdaRank・他券種オッズの特徴量化も否定済み。
  O10・T7・money-flow などの live 追跡は、旧ランクの破棄とともに停止した。

## 付録 A. 作業上の教訓（旧メモから移設）

`CLAUDE.md` に書かれていないものだけを残す。

**測り方**
- 平均は個体の動きを隠す。閾値の跨ぎは馬・レース単位で見ること（「D は30分窓で安定」はこれで誤った）
- 逸話で判断しない。3レースで読んだ傾向が183頭では逆だった
- 復元・照合の判定は「行が合うか」ではなく「ソースが正しいか」で行う。食い違い率を実測してから閾値を置く
- オッズの出所はメタを読んで決めず、実測で突き合わせる
- 商品の定義を変えたら、`type_lab_picks` の paper は旧版のまま残る。版で絞らずに測ると別の商品の話になる
- 「帯を下げる」と「点数を減らす」を同時にやらない（型C の合成下限はこれで代償が倍になった）

**運用・データ**
- スケジュールタスクの rc は意味を持たない（VBS は非同期起動）。データ側から見る（`scripts/jra_agent_health.py`）
- ログの「0件」を「起きなかった」と読まない。break でサマリ行ごと消えることがある（#292）
- コンテナを再起動するとログが消える
- VPS へ重いクエリを投げるときは、他の長時間ジョブと重ねない（型ラボの 2025-Q2 生成が丸ごと落ちた）
- 長時間ジョブは一括保存にしない（月ごとに保存する）。走っているジョブの作業ツリーでは
  `git switch` しない・worktree を消さない
- `data/models_vintage/odds_tf_te20241231/` は git の外にあり、Mac と VPS に1部ずつある。
  2025年を作り直すときは `KEIRIN_ODDS_TF_MODEL_DIR` で指す。指し忘れると静かに in-sample になる
- バックエンドの `--backend` デプロイはソースの変更を反映しない（レジストリのイメージを使う）。
  確認はコンテナ内を直接 grep する
- 固定長レコードのオフセットは、引き算で求めず仕様書の絶対位置を写す

**Windows VM**
- SSH 越しの PowerShell は文字化けする。先頭に
  `$OutputEncoding=[Console]::OutputEncoding=[Text.Encoding]::UTF8;` を付け、パイプ `|` は避ける
- ファイル転送は `scp`（UNC パスは SSH 越しだと壊れる）
- `kiseki-JVLink-BldnFull-Stop`（毎日 08:00）は問答無用で止める。日中に手動で流すなら 08:00 を過ぎてから

**変更・リリース**
- 新しい画面には導線を付ける。外に出すものはデプロイ先で 200 を確かめてから報告する
- `.sh` だけを変更した PR では `preflight.sh` が keirin の pytest を起動しない。`gh pr checks` で Keirin (Python) の結果を見る
- 新しいテーブルを `create_table` だけで足すと、ORM 同期ガードをすり抜ける
- worktree には `node_modules` も `backend/.venv` も無い。本体からシンボリックリンクを張る
- 静的検査は目視の代わりにならない（#422 は面を縛ったが、その上の文字が壊れていた）
