## 2. 人気薄の定義

- **主定義（採否に使う）**: 発走前オッズ昇順の順位 `pop_rank >= 8`
- **従定義（報告のみ）**: 発走前単勝オッズ `>= 10.0` 倍

🔴 **人気順位は必ず発走前オッズから作る。** 確定人気（`race_results.win_popularity`）は
使わない。理由は §3.1。

---

## 3. ラベル

- 上位人気馬 = `pop_rank < 8`、人気薄 = `pop_rank >= 8`
- `S` = 複勝圏（`finish_position <= place_slots`）に入った**上位人気馬**の数
- `E = place_slots − S` = 空席数
- `hit_unpop` = 複勝圏に入った**人気薄**の数

⚠️ 出走取消等で複勝圏の頭数が `place_slots` に満たない場合、`E` は `hit_unpop` を
上回りうる。**観測量である `hit_unpop` を正本とする。**

| | 定義 |
|---|---|
| **主目的変数** | `y1 = 1 if hit_unpop >= 1 else 0`（二値） |
| 従目的変数（報告のみ） | `y2 = 1 if hit_unpop >= 2 else 0` |

`E` の順序回帰は**今回はやらない**（腕を増やすと多重比較になるため）。

### 3.1 確定人気を学習ラベルに代用しない — 測ったうえでの決定

学習ラベルにも発走前オッズを要求すると、窓は発走前オッズの蓄積期間（5か月）に
縛られる。確定人気で作ってよければ窓は年単位に広がるので、**代用が成立するかを
先に測った**（2026-09-02・PR #430 / #431）。

| 柱 | 対象 | 一致率 | 発走前だけ陽性 | 確定だけ陽性 |
|---|---|---|---|---|
| 地方 | 5,111R | **89.53%** | 7.59% | 2.88% |
| JRA | 1,435R | **90.80%** | 5.71% | 3.48% |

→ **代用は却下。** 一致率が9割弱にとどまるうえ**非対称**で、確定人気ラベルは
陽性を系統的に取りこぼす。この差のまま学習させると本番と別の目的関数を
最適化することになる。**学習も評価も発走前ラベルで行い、窓は5か月で我慢する。**

## 8. 合成式（Phase 2・実行前に固定）

```
score(horse) = P(y1 = 1 | race)                      ← レース側モデル（または base_a）
             × p_place_market(horse) / Σ_{pop_rank>=8} p_place_market(j)
             × [指数フィルタを通過したか（0 or 1）]
```

**積とする。** 対数和・重み付き和は試さない（腕を増やすと多重比較になる）。

## 11. 主判定基準（Phase 1）

> **`m_noodds` または `m_odds2` が、選択率 10% / 20% / 30% の全3点で
> `base_a` `base_b0` `base_b` の R2 をすべて上回り、かつ差の95%CIが
> レース単位ブートストラップで 0 を跨がないこと。**

- `R2` = 人気薄が複勝圏に来たレースのうち、選ばれたレースが占める割合
- CI は `boot_mean()`（`backend/scripts/anagusa_top3_walkforward.py:267`）を import して算出
- **1点でも落ちたら不採用。** 「2点で勝った」は採用理由にしない

## 12. 従判定基準（Phase 1）

> **頭数ビンを固定した lift（加重平均）が `base_a` を上回ること。**

Phase 0 実測の `base_a` の値: **地方 1.421 / JRA 1.289**。
頭数をまたいだ lift は「頭数の言い換え」でも出てしまうため、こちらを必ず併記する。

## 12b. Phase 2 の判定基準

> **同一選択率で R2 が §9 の既存商品を上回り、CI が 0 を跨がず、かつ
> 人気を揃えた層化リフトが 5-8番人気 +1.95pt / 9-12番人気 +0.81pt を満たすこと。**

層化リフトは `strat_diff()`（同ファイル `:281`）を import。`strata = pop_rank`。

## 15. Stop rule（触れたら即中止。閾値を動かして探し直さない）

**Phase 1**

1. 🔴 学習モデルが §11 を満たさない → **中止。** `base_a` 単体を軽い商品として
   残す案に縮退する（学習不要・オッズだけで動く）
2. 🔴 `m_noodds` と `m_odds2` の差の大半がオッズ2列から来ている → 二重使用の退化。**中止**
3. 🔴 特定の月を抜くと結論が反転する → n 過小。**判断せず窓を貯める**

**Phase 2**

4. 🔴 R2 が既存商品と同等以下 → **中止**（既存の方が単純なので同等なら既存を残す）
5. 🔴 層化リフトが合格水準に届かない → 市場のエコーの再パッケージ。**中止**
6. 🔴 セグメント別に切って初めて勝つ → **事後分割は判断に使わない。中止**

**プロジェクト全体**: 上記のいずれかに触れたら畳み、結論を `docs/` と台帳に残す。

### 17.2 判定

主判定（§11）は 2モデル × 3選択率 × 3ベースライン = **18通りすべてで CI が
0 を跨がずに勝つこと**を要求していた。実際に勝ったのは:

- 地方 **1通り**（`m_odds2` vs `odds_top1` @30%・Δ+0.088 [+0.035, +0.142]）
- JRA **0通り**

逆に **`base_a` に対しては地方で全6点負け、うち6点すべてで CI が 0 を跨がない
＝有意に劣る**。JRA は CI が広く（±0.07 前後）有意ではないが、点推定はすべて
`base_a` 以下。

従判定（§12・頭数固定 lift が `base_a` を超えること）も満たさない
（地方 1.272 < 1.511 / JRA 1.184 < 1.302）。

→ **stop rule #1 に該当。Phase 2 へ進まず中止する。**

### 17.3 縮退先

事前登録 §15-1 のとおり、**`base_a`（期待空席数）単体**を残す。

```
E_hat = place_slots − Σ_{pop_rank < 8} p_place_market(i)
p_place_market = Henery(λ=0.82) 変換した市場複勝確率（発走前オッズ由来）
```

- **学習しない。モデルファイルも学習窓も要らない。** 発走前オッズだけで計算できる
- 地方では現行の運用ゲート `base_c`（`top3_share<0.63` ∧ 8頭以上）を
  同等の選択率で上回る（選択率 19.8〜20% で R2 40.9% vs 35.3%）
- 頭数を固定しても lift 1.511（地方）/ 1.302（JRA）が残るので、頭数の
  言い換えではない

⚠️ **商品化するかは別の判断で、本事前登録の範囲外。** 判断するなら Phase 2 の
基準（§12b・既存商品との同一母集団比較 + 層化リフト）を別途事前登録すること。
TEST 窓は Phase 1 で消費していない（窓内分割のみ）ので、そこは温存されている。

### 17.4 実行時に踏んだこと

🔴 **最初の Phase 1 は特徴量が欠けたまま回っていた。** §5.2 が挙げた10列のうち
`surface` / `race_type_code` / `weight_type_code` の3列が Phase 0 の `RACE_SQL` に
無く、`r.get(...)` が `None → 0.0` に潰れて**定数のまま**学習していた。
取得漏れは例外にならず「ただ列が定数になる」形で壊れるので気づけない。
3列を SELECT へ足してキャッシュを作り直し、`check_constant_features()` で
**事前登録した特徴が定数なら落ちる**ようにしたうえで測り直した。
**結論は測り直しても変わらなかった**（不採用）。
