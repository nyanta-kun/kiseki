## 1. 中央（JRA v27）からの取り込み候補

### A1. min-max 15〜85 の廃止 → z合成 + `sd_race` 比例スケール ★最優先
- **根拠**: JRA v27 実装時に「min-max は禁止」と結論済み。全レースを同じ幅に正規化すると
  混戦度情報が消え、`calculate_race_confidence` の分散スコア・指数差スコアが機能しない。
  JRA では tier S が 19.0%→30.2% に膨張した。
- **地方の現状**: 上表のとおり **sd(range)=0.000** ＝ まさにその状態。
  `chihou_races_router.py` の3箇所が `calculate_race_confidence` をこの値に対して呼んでいる。
- **判定**: **適用すべき**。JRA と同じ `composite = 50 + z_blend * C * sd_race(base)` 方式へ。
  地方は `DEFAULT_GAP_FULL_SCORE=10.0` を使っているので、スケール変更後に tier 分布を実測して
  係数 C と gap_full_score を再調整する（JRA では C=55.3 / gap=6.0）。
- **工数**: 小（1日）。ただし **全期間バックフィル必須**（memory `feedback_full_period_migration`）。
- **リスク**: 低。ROI は動かない。動くのは tier / 表示順 / 足切り。

### A2. `reg_rank`（レース内正規化着順の回帰）ヘッドの新設 ★
- **根拠**: JRA で 9候補を HEAD/TAIL/ALL 分離比較した結果、レース内正規化着順の回帰が
  Spearman・top1複勝率とも 2窓一貫で首位。binary(is_top3) や LambdaRank より上。
- **地方の現状**: is_top3 binary 単独。順位全体の並びは最適化されていない。
- **判定**: **A/B の価値が高い**。地方は1レース7〜12頭で JRA(16頭) より順位情報が薄いぶん
  効果は小さくなりうるので、必ず実測すること。
- **工数**: 中（学習スクリプト新設 + parity 確認）。
- **リスク**: 中。地方で再現しない可能性あり（chihou は「診断→確認で崩壊しやすい」経験則）。

### A3. 着外率ヘッド（`out_probability`）+ 足切りの置換
- **根拠**: JRA で「除外30%・除外馬の実着外率88.6%・1着取りこぼし4.8%」（旧・指数差ルールは
  除外55%で1着を16.8%取りこぼし）。**ROI は作らないが足切り精度は明確に改善**。
- **地方の現状**: `ChihouRaceDetailClient.tsx` は旧・指数差ルール。DB 列も無い。
- **判定**: **適用推奨**（ただし A1/A2 の後）。alembic で `chihou.calculated_indices.out_probability`
  追加が必要。地方は7〜12頭立てなので「着外」の定義を JRA の6着以下から
  **4着以下 or 頭数比**に変え直す必要がある（そのまま移植は不可）。
- **工数**: 中。
- **リスク**: 低。

### A4. HEAD/TAIL/ALL 分離の評価スクリプト（`chihou_rank_quality_review.py` 新設）
- **根拠**: JRA では「単一の ROI や的中率だけ見ていたため、線形和0.7が足枷という事実を
  発見できなかった」。分離測定して初めて本番が最下位クラスと判明した。
- **地方の現状**: 評価は勝率/複勝率/ROI のみ。ランキング品質の指標がない。
- **判定**: **A1〜A3 の前提として先に作るべき**。これ無しに A2 の採否は判断できない。
- **工数**: 小〜中。`chihou_rebuild_walkforward.py` の honest 予測を再利用できる。
- **リスク**: なし（測定のみ）。

### A5. 特徴量の死活監視（`check_feature_health.py` の地方版）
- **根拠**: JRA では `paddock_index` が **学習期間を通してずっと sd=0**（モデル寄与ゼロ）
  だったことが v27 調査の副産物で発覚。「特徴量が生きているか」の監視が構造的に無かった。
- **地方の現状**: `chihou_data_health_check.py` はあるが供給率・分布比較まで。特徴量単位の
  DEAD/SHIFT/SPARSE 検出はない。44特徴のうち何本が死んでいるか**未確認**。
- **判定**: **即やるべき**（工数最小・発見価値が高い）。`running_style` が全件0だった前例あり。
- **工数**: 小（半日）。
- **リスク**: なし。

## 2. 競輪からの方法論取り込み候補

### B1. 市場残差学習（`init_score = logit(市場含意確率)`）への設計変更
- **根拠**: 競輪 M2 モデル。市場をベースラインに置き**残差だけ**を LightGBM で学習すると、
  ミスプライシング十分位が D1 1.066 → D10 0.853 と**完全単調**になり、検出器として本物と確認。
  S7型ペア ROI は 78.6%→82.0%（honest 史上最良）。
- **地方の現状**: v11 で `odds_rank_n` / `speed_mkt_gap` / `kc_mkt_gap` 等を**素の特徴として
  投入**しているだけ。市場をベースラインに置く構成ではない。
- **判定**: **A/B の価値が高い**。同じ情報でも入れ方で挙動が変わる。ただし
  **黒字化はしない**前提（競輪でも 82% 止まり、地方の控除率は 20〜25%）。
- **工数**: 中。
- **リスク**: 中。地方は既に市場特徴を入れているため差分が小さい可能性。

### B2. 「最下位十分位を外す」— 上位を選ぶより下位を外す
- **根拠**: 競輪で「D10（比0.853・ROI 64%）を避けるだけで含める場合と約20pt差。
  **上位を選ぶより下位を外す方が効果が大きい**」。
- **地方の現状**: 推奨は全て「拾う」方向のカテゴリ設計。除外側の設計がない。
- **判定**: **A3（着外率）と統合して1つの施策にするのが合理的**。
- **工数**: A3 に含まれる。

### B3. レース選択（堅いレースに絞る）★
- **根拠**: 競輪で本調査全体の最良発見。`top3確率上位2車の合計` 上位20%のレースに絞ると
  TEST 比 1.123 / ROI 84.2%（n=2,388＝期間の21%）。**下位80%は比0.99でほぼ完全に効率的**。
  エッジが「堅いレース」に集中していた。
- **地方の現状**: レース単位の発火制御がない（馬単位の条件のみ）。
- **重要な但し書き**: 地方では類似の `entropy_norm`（市場混戦度）を検証済みで、
  診断→確認で符号反転し**不採用**になっている。ただし当時の測定は
  「オッズ帯内の再分割（共線性）」の疑いが指摘されており、
  **モデル確率ベースの `top2_prob_sum` は測っていない**。別物として再測定の価値はある。
- **判定**: **測る価値あり。ただし過去の否定結果を踏まえ期待値は下げる**。
- **工数**: 中（walk-forward honest 予測は既存資産で再利用可）。
- **リスク**: 高（過去に近い仮説が落ちている）。

### B4. 評価指標を ROI から「比（実測/市場含意）」へ
- **根拠**: 競輪で確立。ROI は控除率でオフセットされるため差が見えにくいが、
  比なら paired 比較で t 検定でき、小さいエッジも検出できる。
- **地方の現状**: ROI と的中率のみ。
- **判定**: **A4 とセットで導入。測定基盤の改善**。
- **工数**: 小。

### B5. 券種の拡張（ワイド・馬連）
- **根拠**: 競輪では券種選択自体のエッジは限定的だった（Task3）が、地方は現在
  **単勝・複勝しか評価していない**。`chihou.race_payouts` には
  quinella/wide/exacta/trio/trifecta が入っている。
- **判定**: **優先度低**。競輪の結論では券種選択のエッジは Task1（レース選択）より小さい。
  ただし JRA 側では「高オッズ穴×ワイド軸×モデル1位で ROI 1.05」の前例あり
  （memory `highodds_place_wide_recommendation`）ので、B3 が成立した場合の受け皿として保留。
- **工数**: 中。

## 3. 新データ源（Web 調査 + DB 棚卸しから）

### C1. ★★ JRA 戦歴のクロス活用（最有力）
- **根拠**: 上記のとおり地方出走馬の **53.8%** に JRA 出走歴が自DB内にある。
  JRA 側は走破タイム・上がり3F・馬場・クラス・賞金が地方より高品質かつ**基準が全国統一**。
  地方は場ごとに時計水準もクラス体系も違うため、**JRA 戦歴は場をまたぐ共通のものさし**になる。
- **想定特徴**: JRA最高着順 / JRA平均着順_正規化 / JRAクラス最高 / JRA最終出走からの経過日数 /
  JRA走数 / JRAダート実績 / JRA上がり3F最速（対レース平均）。すべて
  「今回レース日より前の JRA 走のみ」で point-in-time 構成。
- **判定**: **最優先で検証すべき新データ源**。過去の chihou 改善調査
  （調教SLOP・パドック・kichiuma未使用列）が全滅した中で、**唯一「未使用かつ高充足かつ
  情報の質が高い」**候補。
- **工数**: 中〜大（馬名突合の正規化・point-in-time 集計・train/serve parity）。
- **リスク**: 中。馬名突合の誤マッチ（同名馬）を要検証。ただし市場も「元中央馬」は
  当然知っているため、**市場に織り込み済みで比は動かない**可能性は高い
  （＝ランキング品質は上がるが ROI は上がらない、という JRA v27 と同じ結論になりうる）。

### C2. 血統（`keiba.pedigrees` 経由・76.7% カバー）
- **根拠**: `chihou.pedigrees` は空だが、`keiba.pedigrees.sire` は地方出走馬の76.7%で引ける。
  JRA 側には `going_pedigree_index` / `pedigree_index` の実装資産がある。
- **判定**: **C1 と同時にやると効率が良い**（同じ馬名突合基盤を共有）。
  ただし JRA 側の `going_pedigree_index` は**本番で常に死んでいる**（馬場状態が算出時点で
  未確定）という既知バグがあるので、その設計をそのまま移植しないこと。
- **工数**: 中（C1 と共通基盤）。
- **リスク**: 中。ダート短距離主体の地方で血統の識別力は JRA 芝ほど高くない可能性。

### C3. 転入初戦・場替わりフラグ
- **根拠（Web）**: 中央→地方の転入初戦は競馬場で大きく差がある。
  金沢 勝率25.1%/複勝率55.2%・笠松 24.8%/55.7%・高知 24.6%/53.8%・盛岡 22.4%/51.8% に対し、
  大井 11.6%/28.0%・園田 13.2%/33.7%・川崎 14.1%/34.2%。
  **ただし単勝回収率は全場100%未満（最良 水沢85.2 / 金沢82.8）＝市場は既に織り込んでいる。**
- **判定**: **特徴量としては採用価値あり（C1 の一部として実装）。買い目ルールにはしない。**
  地方間の場移動（例: 高知→園田）も同じ枠組みで作れる。
- **工数**: 小（C1 の派生）。
- **リスク**: 低（ただし ROI 寄与は期待しない）。
- 出典: [勝ち馬理論](https://baken.pro/baken/6448/) / [日刊SPA!](https://nikkan-spa.jp/1707671)

### C4. 賞金によるクラス水準の連続量化・場間格差
- **根拠**: `prize_1st` が 100% 充足。地方はクラス体系が場ごとに独立（A1/B2/C3、南関と高知で
  意味が違う）ため、**賞金額が唯一の場横断で比較可能なレース格の連続量**。
- **判定**: **適用推奨・工数最小**。現行 `class_drop_ratio` を賞金ベースへ置換 or 併用。
  「前走賞金水準 − 今走賞金水準」＝実質的なクラス昇降級の連続量。
- **工数**: 小。
- **リスク**: 低。

### C5. ナイター（`post_time` 100%充足）
- **根拠**: 大井・川崎・高知・門別・園田などナイター開催がある。照明・気温・砂の締まり方が
  昼と異なる。競輪では「ミッドナイトは車番が完全単調」という夜開催特有の構造が実測された前例。
- **判定**: **適用推奨・工数最小**。`is_night`（発走19時以降）+ `post_hour` を特徴に追加。
- **工数**: 極小。
- **リスク**: 低。

### C6. 減量騎手（`jockey_apprentice_code` 100%充足）
- **根拠**: 100%充足で未使用。1〜5kg 減は地方の短距離では影響が相対的に大きい。
  現行 `jockey_index` は勝率ベースなので、減量特典は別情報。
- **判定**: **適用推奨・工数最小**（C4/C5 と同じバッチで）。
- **工数**: 極小。
- **リスク**: 低。

### C7. 直前オッズ変動（`chihou.odds_history`）
- **根拠（Web）**: 前日オッズと直前オッズの精度差は小さいという検証がある一方、
  締切直前5分に売上の約半分が投じられるため直前変動は情報を含む。
  競輪・JRA でも `odds_movement` 系は検証済み（JRA Phase4-A）。
- **地方の現状**: `odds_history` は **2026-04-07 以降のみ**。学習に使うには
  TRAIN_END=20250630 との整合が取れず、**現時点では学習特徴にできない**。
- **判定**: **保留**。データ蓄積を待ち、2027年以降に再検討。今できるのは
  「蓄積が正しく続いているかの監視」を A5 のヘルスチェックに含めること。
- **工数**: —
- **リスク**: —

### C8. 馬場の定量情報（砂厚・含水率・クッション値）
- **根拠（Web）**: 含水率・クッション値は **JRA が公式発表しているもの**で、
  NAR（地方）は場ごとにバラバラで統一的な公式データがない。
- **判定**: **取り込み不可**。代替として「当日・当該場の勝ちタイム水準からのトラックバイアス推定」
  （その日その場の平均勝ちタイムを基準タイムと比較した z 値）は自前で作れる。
  ただし**当日レースでは前レースまでしか使えない**ため point-in-time 設計が必須。
- **工数**: 中。
- **リスク**: 中（JRA の `going_pedigree_index` と同型の「算出時点でデータが無い」罠がある）。

### C9. `weight_type_code`（重量種別）/ `first_3f`（レースペース）
- **判定**: `weight_type_code` は100%充足で工数極小なので C4/C5/C6 と同梱。
  `first_3f` は 22.8% 充足と薄く、欠損処理のコストに見合わないので**見送り**。

## 8. Phase 2 実施結果（2026-08-02・**いずれも不採用**）

### C1〜C3: JRA戦歴のクロス活用 → **不採用（市場に織り込み済み）**

スクリプト: `scripts/chihou_jra_history_ab.py`。
名寄せは `name + birthday`（keiba 側は同一 (name,birthday) が 1,769 組重複＝同じ馬の
マスタ重複なので、一致した keiba 馬IDを全部まとめて 1 頭として扱いレースIDで重複排除）。
馬名のみの突合は keiba に同名馬が 1,769 組あるため使わない。
point-in-time は `merge_asof(direction="backward", allow_exact_matches=False)` で担保。

追加した8特徴: `has_jra` / `jra_runs_n` / `jra_best_pos_n` / `jra_avg_pos_n` /
`jra_days_since` / `jra_first_after`（転入初戦）/ `jra_prize_log` / `jra_last_pos_n`。
JRA走 117,114件・14,202頭、test 期間のカバレッジ **57.7%**、転入初戦フラグ 4.32%。

| 土台 | top1_win 差 | spearman 差 |
|---|---|---|
| base44（**市場特徴あり＝本番構成**） | +0.0003 [−0.0019,+0.0026] | +0.0004 [−0.0002,+0.0010] |
| base39（市場特徴なし） | +0.0034 [−0.0016,+0.0084] | **+0.0028 [+0.0012,+0.0043]*** |

**解釈**: 市場特徴を外すと Spearman が有意に改善するので、JRA戦歴には**本物の情報がある**。
しかし本番構成（市場特徴あり）では上乗せがゼロ ＝ **オッズに完全に織り込まれている**。
JRA戦歴のある馬だけに絞っても指数1位の複勝率は 0.6879 → 0.6881 で変わらない。

これは Web 調査の事前の示唆（転入初戦の単勝回収率は全場 100% 未満・最良 85.2）とも、
keirin/JRA で繰り返し確認されている「自前モデルは市場情報の真部分集合」とも整合する。

### 着外率ヘッド（out_probability）の新設 → **不採用（指数差ルールと同等）**

同じ除外率で並べると、専用モデルは較正済みの指数差ルールに勝てない:

| 除外率帯 | 指数差ルール | 着外率モデル |
|---|---|---|
| 約25% | 32/26/順位5 → 93.9% / 2.1% / 5.2% | p_out≥0.84 → 95.0% / 2.0% / 4.4% |
| 約31% | **30/24/順位7 → 93.6% / 2.9% / 6.9%** | p_out≥0.80 → 93.9% / 3.0% / 6.7% |
| 約38% | 28/22/順位7 → 92.8% / 4.1% / 9.3% | p_out≥0.75 → 92.7% / 4.9% / 9.9% |

（各セル = 除外馬の着外率 / 1着取りこぼし / 3着内取りこぼし）

低い除外率帯でわずかに専用モデルが上回るが、採用予定の 31% 帯ではほぼ同一。
**alembic 移行（`chihou.calculated_indices.out_probability` 追加）とバックフィルの
コストに見合わない**ため見送る。

**示唆**: JRA で「指数差ルール → 着外率モデル」が大きく改善したのは、
モデル自体の力というより**旧ルールの較正が壊れていたから**である可能性が高い。
地方でも旧ルールは 82% 除外・1着取りこぼし 35% と壊れており、
**較正し直すだけで着外率モデルと同等の性能に到達した**。

### Phase 2 の総括

地方の現行データセットでは、**残っていた最有力の新データ源（JRA戦歴）も市場に織り込まれて
おり、指数のランキング精度をこれ以上押し上げる材料は見当たらない**。
[[chihou_improvement_investigation_2026_06_07]] 以来 5 回目の同型の結論。

今回のセッションで実際に効いたのは、新しい情報を足すことではなく
**壊れていた3つ（履歴が v10 のまま・min-max による tier 崩壊・足切りの誤較正）を直すこと**
だった。
